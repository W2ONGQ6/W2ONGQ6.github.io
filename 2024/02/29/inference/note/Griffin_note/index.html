Griffin: 门控线性递归与局部Attention混合的高效语言模型

date: 2024-02-29

Griffin: 门控线性递归与局部Attention混合的高效语言模型

核心信息

Griffin 是 Google DeepMind 对 Mamba 的系统性回应，引入了 Hawk（纯递归架构）和 Griffin（递归 + 局部 Attention 混合架构）。核心创新为 RG-LRU (Real-Gated Linear Recurrent Unit)——一种比 Mamba 的 selective SSM 更简单但同样高效的门控线性递归层。Griffin 混合架构将 RG-LRU 层与滑动窗口局部 Attention 交错排列，以少 6 倍的训练 token 匹敌 Llama-2 的质量，在长序列上展现出优越的吞吐量和外推能力。论文的有效扩展到 14B 参数。

原文摘要翻译

我们提出了 Hawk 和 Griffin，两种基于门控线性递归的新型语言模型架构。Hawk 是纯递归架构，不使用任何 attention；Griffin 则混合使用门控线性递归和局部 attention。核心构建模块 RG-LRU（Real-Gated Linear Recurrent Unit）是一种新颖的门控层，比 Mamba 的 selective SSM 更简单。Griffin 以少 6 倍的训练 token 匹敌 Llama-2 的质量，在长序列上展现出比 multi-query attention Transformer 更高的吞吐量和更低的延迟。模型有效扩展到 14B 参数，在超出训练长度的上下文上展现出强大的外推能力。

创新点

  1. RG-LRU (Real-Gated Linear Recurrent Unit)：一种新型的门控线性递归单元，核心公式：a_t = sigmoid(LN(x_t)^T W_a) （输入依赖的门控标量）+ 简化的状态更新。比 Mamba 的 selective SSM（S6）更简单——参数更少、计算更直接。门控是实数值标量（非矩阵），计算极其高效。

  2. Hawk 架构：纯递归架构，完全不含 attention。RG-LRU 层 + MLP 层的交替堆叠。用更少的训练 token 在下游任务上超越 Mamba。

  3. Griffin 混合架构：在 RG-LRU 层之间插入滑动窗口局部 Attention 层。递归层处理长程上下文压缩，Attention 层处理局部精确 token 匹配。两种机制互补。

  4. 系统性的长序列评估：在超出训练长度的上下文（训练 2K/4K → 评估 128K+）上验证外推能力。有效扩展到 14B 参数。

一句话总结

Griffin 以 RG-LRU 门控递归提供比 Mamba 更简单的选择性机制，以局部 Attention 弥补递归在精确匹配上的短板，是 DeepMind 对”最优混合架构”的权威定义。

研究问题

总体框架

  • 架构简化问题：Mamba 的选择性 SSM 的数学框架相对复杂。能否设计一个更简单但同样有效的门控递归层？
  • 混合问题：递归和 Attention 各自擅长什么？Attention 在混合架构中的最佳角色是什么？
  • 扩展问题：门控递归架构能否有效扩展到 14B 参数（工业级规模）？
  • 外推问题：递归架构在超出训练长度的序列上是否天然更有优势？

子问题分解

子问题1：标量门控 vs 向量门控的表达力。 Mamba的S6使用逐通道的选择性门控——2048个隐藏维度就有2048个独立的”遗忘率”。RG-LRU使用标量门控——整个隐藏维度共享一个0到1之间的遗忘率。关键问题：在语言建模中，逐通道的选择性有多大的边际收益？对于”记住这个专有名词”（需要精确逐字记忆）和”理解这个段落的主题”（需要宽松的全局压缩），标量门控是否都能有效处理？量化目标：在Copying任务（需要精确逐位复制远距离信息）上，标量门控的准确率下降与向量门控相比有多少？

子问题2：局部Attention的最优窗口大小。 Griffin使用滑动窗口局部attention（窗口大小256 tokens）。这个选择是基于什么？如果窗口太小（如64），关键局部依赖（如主谓一致、代词回指）可能跨越多于64 token的距离——对于平均句子长度约20个单词（约25 tokens），64的窗口覆盖约2.5个句子。如果窗口太大（如1024），局部attention的计算开销接近全局attention——对于长度为N的序列，每个token attend到W个邻居，总复杂度O(NW)。W=64时复杂度约为全局attention的64/N（当N=4096时，仅1.6%）。W=1024时升至25%——优势减弱。

子问题3：训练-推理的外推差距。 Griffin声称”在2K/4K训练长度上，可以外推到128K+”——这个声称需要一个解释：递归机制的什么性质使其天然支持外推？答案在于：递归状态更新 h_t = a_t * h_{t-1} + (1-a_t) * new_info 不依赖于序列总长度。无论序列是2K还是200K tokens，状态更新公式完全相同。这与Transformer形成对比：RoPE位置编码的旋转角度随位置线性增长，在训练范围外（如位置>4096）产生模型从未见过的编码值。因此，递归的”外推友好性”不是训练技巧的结果，而是架构本身的性质——递归天然不依赖位置编码来建立长程依赖。

数据与任务定义

  • 预训练数据：DeepMind内部大规模高质量语料库（规模未公开，推测>500B tokens）
  • 训练上下文长度：2K和4K tokens（两个变体）
  • 模型规模：1B, 3B, 7B, 14B参数（Hawk和Griffin各4个规模）
  • 评估任务：语言建模PPL, HellaSwag, PIQA, ARC-E/ARC-C, WinoGrande, LAMBADA, MMLU
  • 长序列评估：外推到128K+ tokens, Needle-in-a-Haystack, Copying任务
  • 效率测量：训练tokens/s/GPU, 推理延迟(ms/token) vs 序列长度, 最大吞吐量(tokens/s)
  • 对比基线：Llama-2 (Transformer), Mamba-2.8B, Hawk (纯递归), 同规模MQA Transformer

RG-LRU 架构详情（14B Griffin）：

  • 层数：约40层（其中约27层RG-LRU, 约13层局部Attention, 比例约2:1）
  • 隐藏维度：5376
  • RG-LRU状态维度：5376（与隐藏维度相同，全维度的递归状态）
  • 局部Attention窗口：256 tokens, sliding window
  • 局部Attention头数：28个Q头, 4个KV头（GQA 7:1 ratio）
  • 门控投影：单标量输出投影（5376→1, 通过sigmoid）

标量门控的物理直觉： “gate_t接近1”→ 保留状态→”当前token信息不重要，继续记住之前的内容”。”gate_t接近0”→ 更新状态→”当前token信息很重要，用新信息替换旧状态”。标量意味着：整个隐藏维度同步遗忘或同步更新——没有”部分维度记住、部分维度遗忘”的灵活性。这在数学上等价于一个单时间尺度的指数移动平均。

与LSTM Forget Gate的对比： LSTM的forget gate是向量（每维度独立决定是否遗忘）——比RG-LRU更灵活但更复杂。RG-LRU是”最低复杂度”的门控递归——在”标量门控”vs”无门控”的维度上做到了极简。

2. Hawk 架构（纯递归）

完全不含 attention。每层的”状态”仅为递归状态向量h_t（D维）。推理时O(1)内存。

3. Griffin 混合架构

局部 Attention 的设计：

  • 滑动窗口机制：每个 token 只能 attend到周围256个token
  • 实现：因果attention mask限制为窗口范围（标准实现，与全局attention相同的kernel但mask限制）
  • KV cache 大小：窗口大小×维度——恒定，不随序列长度增长（类似Mamba state的O(1)性质但在attention空间中）

4. 训练和推理的优化（详细流程）

Step 1: 并行训练 → RG-LRU的关联扫描实现。

  • 输入：完整序列所有token的嵌入 [B, S, D]
  • 操作：RG-LRU的递归 h_t = gate_t * h_{t-1} + (1-gate_t) * u_t 是线性递归——可以用关联扫描（associative scan, 与Mamba相同技术）并行计算所有时间步的h_t
  • 关联扫描的操作符：(a, b) ∘ (c, d) = (a*c, a*d + b) —— 对应状态转移的组合规则
  • 通过并行前缀扫描prefix sum的变体，计算所有h_t从h_0到h_{t-1}的累积结果
  • 复杂度：O(log S) 的并行深度（而非O(S)的顺序深度）
  • 输出：所有时间步的h_t（并行计算完成）

Step 2: 局部Attention的KV cache管理。

  • 滑动窗口attention的KV cache：仅保留最近W=256个token的K,V
  • 当新token到来时：删除最旧的K,V（窗口外），添加最新token的K,V
  • 内存：W × 2 × num_kv_heads × head_dim × 2bytes（恒定）

Step 3: 推理时的逐token循环。

  • RG-LRU层：O(1) 状态更新（gate计算 + 状态乘法 + 输出投影）
  • Local Attention层：O(W) window attention（attend到最近256个token）
  • 总推理延迟：不随序列长度增长的恒定延迟（与全局attention Transformer的O(N)形成对比）

深度分析

1. RG-LRU：极简主义的胜利

RG-LRU 的设计哲学是”如果简单的设计足够好，就不要用复杂的”：

  • Mamba 的选择性 SSM 有 A, B, C, Delta 四个参数化的变换
  • RG-LRU 只有一个标量门控

但实验表明，这个极简设计的性能不逊于 Mamba。为什么？

可能的解释：

  • 语言建模中，大部分”选择性”可能并不需要细粒度的逐通道控制。一个全局的”现在是时候遗忘旧信息了”的信号（标量门控）在很多情况下已经足够。
  • Mamba 的细粒度选择性可能主要用于合成任务（如 Selective Copying），而对实际的语言建模的边际收益有限。
  • RG-LRU 的”简单”使得它更容易优化和扩展——复杂的参数化在更大规模下可能更难训练。

这验证了一个重要的设计原则：在着手设计复杂机制之前，先测试最简单的可能方案。

深入分析：标量门控何时足够？ 语言序列中有明确的”事件边界”——句子结束、段落结束、主题切换。在这些边界处，模型确实需要”重置”或”大规模更新”状态——标量门控（全体遗忘+更新）在这些场景下是合理的甚至是最优的。标量门控可能失灵的场合是：需要”选择性记忆”——如记住一个重要的数字（需要极低衰减），同时遗忘周围的噪音（需要高衰减）。标量门控无法同时做到（因为整个状态的衰减率相同）。向量门控可以——某些通道保持低衰减（记住数字），其他通道快速衰减（遗忘噪音）。这解释了为何在Copying任务上Griffin不如Mamba：Copying需要这种”选择性记忆”。

2. Google DeepMind 的混合架构路线

Griffin 代表了 Google DeepMind 对”Transformer 之后”架构选择的明确立场：混合架构优于纯架构。这与 Mamba-2 的建议（混合架构最优）一致，但来自不同的团队和不同的实验设置，增加了这一结论的可信度。

关键洞察：Attention的真正价值是什么？ Griffin暗示：Attention的核心价值不在于”全局上下文整合”（递归可以高效地做到），而在于”局部精确交互”——在近距离内需要精确的token级关联（如解析代词、匹配括号、短距离的语义关联）。递归的压缩/传播机制在局部精确交互上不如attention——因为递归状态是”平滑的压缩”，丢失了逐个token的精确位置信息。局部attention（滑动窗口）恰好弥补了这个短板。

3. Albert Gu 的参与

论文的共同作者包括 Albert Gu（Mamba 的创造者）。他的参与表明：

  • Mamba 的作者本人也认同混合架构可能是更好的方向
  • RG-LRU 的极简设计可能反映了 Gu 对 Mamba 复杂性的反思
  • 从纯 SSM（Mamba-1）到 SSD 统一（Mamba-2）再到混合架构（Griffin），Gu 的思想轨迹是从”替代 Transformer”到”与 Transformer 共存”

Griffin 处于”极简设计”和”实用混合”的交汇点：用最简单的门控递归提供效率，用最少量的局部 attention 补齐精确性。

局限

  1. RG-LRU 标量门控的表达力上限：在更大规模（70B+）和更复杂任务上，逐通道的门控（如 Mamba）可能产生差距。标量门控在需要”选择性记忆”的任务（如多实体追踪、复杂代码理解）上的表现未知。

  2. 局部 attention 窗口大小的经验选择：256 是经验最优，但缺乏理论依据。最优窗口大小可能随任务（精确匹配需要多大范围？）和模型深度（深层是否因压缩而需要更大窗口？）变化。

  3. 训练数据的闭源性：使用 DeepMind 内部数据集，与开源社区使用公开数据集（如The Pile）的方法难以公平对比——部分性能优势可能来自更高质量的训练数据。

  4. 缺少指令微调和对话能力评估：论文主要关注基础语言建模能力，RLHF/对话对齐后的性能未验证。对齐可能改变递归和attention的动态（如安全拒绝需要全局理解用户的敌对意图）。

  5. 局部 attention 在”长程归纳”上的局限：滑动窗口attention无法直接处理距离>256 tokens的归纳关系（如”第一章提到X，第十章的Y回指X”）。这依赖RG-LRU递归层在256+距离上”携带”信息——递归的压缩保真度在这些距离上的质量未知。

  6. RG-LRU vs Mamba 的直接消融缺乏：论文对比了Griffin vs Mamba的整体架构，但缺乏”同一架构中仅替换递归单元”的直接消融——无法明确RG-LRU相对Mamba S6的具体增益/损失。

  7. 扩展到视觉/多模态的验证缺乏：递归+局部attention的混合在2D/3D视觉数据上的行为未知——图像patch的序列长度（如256×256=65536 patches for ViT）可能需要不同的窗口大小或交错模式。

可复用洞见

  1. 更简单通常就足够好了：RG-LRU 的经验表明，复杂的参数化（如 Mamba 的选择性 SSM）可能对实际语言建模是”过设计”的。在引入新的复杂机制前，先测试简化的基线。

    如何应用： 在设计中新序列处理机制时，采用”复杂度阶梯”——从标量门控开始（1个参数/层），如果不满足需求再上向量门控（D个参数/层），再不满足再上全矩阵门控（D²参数/层）。每一级只有在实验证明”前一级确实不够”时才升级。

  2. 递归 + 局部 Attention = 黄金组合：全局内容理解用递归（高效），局部精确匹配用 attention（精确）。

    如何应用： 在构建混合架构时，将递归层和attention层的角色明确分工——递归负责长程信息传播（每隔2-3层插入attention作为”校准点”），attention负责局部精确交互（窗口大小以”覆盖平均句子长度+语法依赖距离”为下限，通常64-512 tokens）。

  3. 训练效率不止于 FLOPs：Griffin 用更少的训练 token 达到同等质量——数据效率也是评估架构的重要维度。

  4. 外推能力是架构设计的显性目标：如果架构不支持长序列外推，在短序列上训练、长序列上推理的能力将成为架构选择的关键考量——递归架构在这方面有天然的结构性优势。

我的笔记

Griffin 是”最不炫技但最实用”的替代架构论文。它没有 Mamba 那样深厚的 SSM 数学理论，没有 Mamba-2 那样漂亮的统一框架。它做的只是一件简单的事：设计一个极简的门控递归，然后在需要精确性的地方加一点局部 attention——但效果出奇地好。

RG-LRU 的标量门控让我重新思考了”模型复杂度”和”实际效果”之间的关系。”一个标量就够了”可能是被严重低估的智慧。

Griffin 最让我信服的一点是它来自 Google DeepMind——全球最大的 ML 研究机构之一。当这样一支团队说”我们选择了最简单的递归 + 局部 attention，因为它最好”，这个结论的分量远超一个学术实验室的类似声明。

后续问题

  1. RG-LRU 的标量门控在更大规模（70B+）下是否仍优于 Mamba 的逐通道门控？
  2. 局部 attention 窗口的最优大小是否有 scaling law？
  3. Griffin 的混合比例是否可以学习而不需要人工设定？
  4. RG-LRU 的门控值是否可以可视化——哪些 token 触发了”遗忘”信号？
  5. Griffin 架构在 vision 和多模态任务中的表现如何？
