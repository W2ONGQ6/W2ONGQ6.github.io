KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache

KIVI: 免调参非对称2比特KV缓存量化

核心信息

  • 标题: KIVI: A Tuning-Free Asymmetric 2bit Quantization for KV Cache
  • 标题翻译: KIVI：免调参的非对称2比特KV缓存量化
  • 作者: Zirui Liu, Jiayi Yuan, Hongye Jin, Shaochen Zhong, Zhaozhuo Xu, Vladimir Braverman, Beidi Chen, Xia Hu
  • 机构: Rice University, Carnegie Mellon University
  • 发表时间: 2024年2月5日
  • 发表渠道: ICML 2024
  • arXiv: 2402.02750
  • 论文链接: https://arxiv.org/abs/2402.02750

原文摘要翻译

大型语言模型（LLM）中长序列生成的瓶颈是KV缓存的内存消耗。现有KV缓存量化方法通常需要校准数据来减轻异常值的影响，并且大多限于4比特量化。本文提出了KIVI——一种插件式的免调参2比特KV缓存量化算法，无需任何校准即可实现。KIVI的设计基于我们对KV缓存中异常值的系统分析：Key缓存中的异常值主要存在于少量固定通道中，而Value缓存中没有这种持续的通道异常值。据此，我们对Key缓存使用逐通道非对称量化，对Value缓存使用逐token非对称量化。KIVI在LLaMA、Mistral和Falcon等模型上表现出色——使用2比特量化时产生可忽略的困惑度退化，在4比特时甚至优于大多数4比特基线。此外，KIVI将模型权重也采用2比特量化后，峰值内存减少2.6倍，支持高达4倍的更大batch size，在真实工作负载上的吞吐量提升达2.35至3.47倍。源代码可在https://github.com/jy-yuan/KIVI获取。

创新点

1. Key和Value的非对称量化策略

核心思想: 通过系统分析发现Key缓存和Value缓存的异常值分布模式根本不同——Key有逐通道异常值（少量固定通道具有持续的大数值），而Value没有这种持续的结构。因此，对Key应该使用逐通道量化（per-channel），以保护这些关键通道不被压缩失真；对Value应该使用逐token量化（per-token），因为其异常值在token维度上分布更均匀。

为什么重要: 这一洞察揭示了Key和Value在注意力机制中的不对称性不仅是计算角色上的（Key用于匹配、Value用于聚合），还体现在数值分布结构上。传统的K和V使用相同量化策略的做法（如统一逐token量化）会严重损害Key中通道异常值通道的质量，而这些通道对注意力分数的精确计算至关重要。KIVI的非对称量化策略使2比特KV缓存量化首次在无校准数据的情况下成为可能。

2. 免调参设计（Zero-Shot适用）

核心贡献: KIVI不需要任何校准数据、模型微调或逐模型的超参数调优。它能以”即插即用”的方式应用于任何预训练LLM，开箱即在LLaMA、LLaMA-2、Mistral、Falcon等不同架构模型上表现良好。

为什么重要: 这是KV缓存量化实用性的巨大进步。传统的KV缓存量化方法（如Int4、GPTQ-4bit）需要准备特定于模型和领域的校准数据集，这在动态多变的实际部署中极为不便。KIVI的免调参设计意味着它可以被部署在HuggingFace Transformers等通用框架中作为默认选项，无需最终用户进行任何额外准备。这种”零配置”特性对于开源生态系统的广泛采用至关重要。

3. 小型FP16残差缓冲区分块量化

核心扩展: 对于流式生成（token逐个到达），KIVI不会在每步都对整个KV缓存进行重新量化。它维护一个小的FP16残差缓冲区，存储最近到达的未量化token。只有当残差缓冲区填满（如32个token）后，才对这组token执行分块量化并合并到量化缓存中（进行group-wise量化）。这避免了频繁的逐token量化计算开销，同时摊销后的内存使用无限接近2比特目标。

为什么重要: 流式推理中的量化需要同时解决两个矛盾的要求：（1）最近token的KV需要高精度以维持生成质量（2）整个缓存的存储需要低精度以控制内存。残差缓冲区设计优雅地解决了这个矛盾：最近token保持FP16精度直至缓冲区满，之前的token被量化为2比特存储。这实现了计算效率和内存效率的帕累托最优。

4. 处理RoPE的Key量化方案

核心发现: KIVI识别出RoPE（旋转位置嵌入）对Key量化的关键影响。由于RoPE是在Key向量计算后应用的，它混合了不同通道的值。如果在前RoPE阶段量化，通道异常值模式会丢失；如果在后RoPE阶段量化，异常值模式也存在但更分散。

为什么重要: KIVI选择了在RoPE之后量化Key缓存（与KVQuant选择前RoPE量化不同），因为KIVI的逐通道量化需要在看到RoPE混合后的通道值的基础上进行异常值识别。这个工程决策的微妙之处在于：正确的量化范式选择取决于具体的量化策略，而非存在唯一的最优选择。

一句话总结

KIVI通过发现Key缓存存在逐通道异常值而Value缓存没有的分布不对称性，提出了逐通道量化Key、逐token量化Value的2比特KV缓存量化方法，无需任何校准数据即可在多种LLM上实现2.6倍内存减少、4倍更大batch size和最高3.47倍吞吐量提升。

研究问题

核心挑战

KV缓存在LLM推理中的内存消耗公式为：

$$M_{\text{KV}} = 2 \times L \times H \times d \times N \times \text{bytes_per_element}$$

对于LLaMA-2-7B ($L=32, H=32, d=128$)，在16比特精度下每token需要0.5MB KV缓存，处理100K token需要约50GB——超过单个A100 (40GB) 的容量。

量化可以将$\text{bytes_per_element}$从2 (FP16) 减少到0.25 (2-bit)，理论上实现8倍内存减少。但问题是：如何在2比特极限压缩下保持生成质量？

现有方法的局限

  1. 统一量化策略（Uniform Quantization:

    • 对K和V使用相同的量化方案（如Int4）
    • 容易忽略K和V的分布差异
    • 在2比特时质量退化显著

  2. 基于校准的量化（Calibration-based Quantization:

    • 需要代表性的校准数据集
    • 校准数据的选择影响量化效果
    • 不适用于动态变化的输入领域

  3. 加权/敏感度引导量化:

    • 需要计算参数的Fisher信息矩阵
    • 计算昂贵，特别是对大模型
    • 通常需要微调恢复精度

  4. 混合精度量化:

    • 对关键层使用高精度、非关键层使用低精度
    • 在极端比特率下（2比特），所有层都变为关键层

关键洞察

KV分布的非对称性: Key矩阵具有持续的通道方向异常值模式（特定通道索引始终具有大幅值），而Value矩阵没有这种结构。因此，Key适合逐通道量化以保护异常值通道，Value适合逐token量化以保护异常token的表示。

实证基础

论文对LLaMA-2-7B的KV缓存进行了详细分析：

Key缓存的异常值特征:

  • 某些通道索引（如通道0, 32, 64等）在所有token中都具有比其他通道显著更大的幅度
  • 异常值通道是持续存在的——同一通道索引在不同token、不同输入序列中都表现出大振幅
  • 这是由Key投影权重的特定行造成的结构性产物

Value缓存的异常值特征:

  • 没有持续的通道维度异常值模式
  • 相反，异常值表现为”异常token”——某些特定的token具有比其他token更大的整体Value幅度
  • Token级别的异常值模式随输入内容变化

核心机制

非对称量化的数学背景

传统的对称量化仅使用scale（缩放因子）：

$$x_{\text{quant}} = \text{round}\left(\frac{x}{s}\right)$$

非对称量化同时使用scale和zero-point：

$$x_{\text{quant}} = \text{round}\left(\frac{x - z}{s}\right)$$

$$\hat{x} = s \cdot x_{\text{quant}} + z$$

其中$s$是缩放因子，$z$是零点偏移。非对称量化能够更好地适应非对称分布（如Key缓存的通道异常值），因为零点可以在不压缩范围的情况下将量化网格中心对准数据分布的中心。

机制流程


Figure 2: 来源—原论文。

步骤1: KV缓存异常值分析

在进行量化策略选择前，KIVI分析Key和Value缓存的分布特性：

步骤Key缓存分析:

  • 计算每个通道（维度）在多个token上的平均幅值：$\mu_c = \mathbb{E}t[|K{t,c}|]$
  • 识别异常值通道：${c : \mu_c > \tau \cdot \text{median}(\mu)}$，通常$\tau = 5$
  • 确认异常值通道的索引在不同输入中保持一致

步骤Value缓存分析:

  • 计算每个token在多个通道上的平均幅值：$\nu_t = \mathbb{E}c[|V{t,c}|]$
  • 确认异常值token的模式随输入内容变化
  • 验证没有持续的通道异常值模式

步骤2: 逐通道非对称Key量化

对于Key矩阵 $K \in \mathbb{R}^{N \times d}$：

  • 沿通道维度 $c = 0, \ldots, d-1$ 独立量化：

    • 对每个通道 $c$，计算：$s_c = \frac{\max({K_{t,c}}t) - \min({K{t,c}}_t)}{2^b - 1}$
    • 计算zero-point：$z_c = \min({K_{t,c}}_t)$
    • 量化：$\hat{K}{t,c} = \text{round}\left(\frac{K{t,c} - z_c}{s_c}\right)$
    • 反量化：$\tilde{K}{t,c} = s_c \cdot \hat{K}{t,c} + z_c$

  • 每个通道有自己的一套 $(s_c, z_c)$，总共 $2d$ 个FP16元数据

设计理由: 逐通道量化使得异常值通道和非异常值通道各自获得独立的量化范围，避免了全局范围内异常值”污染”非异常值通道的量化精度。

步骤3: 逐Token非对称Value量化

对于Value矩阵 $V \in \mathbb{R}^{N \times d}$：

  • 沿token维度 $t = 1, \ldots, N$ 独立量化：

    • 对每个token $t$，计算：$s_t = \frac{\max({V_{t,c}}c) - \min({V{t,c}}_c)}{2^b - 1}$
    • 计算zero-point：$z_t = \min({V_{t,c}}_c)$
    • 量化：$\hat{V}{t,c} = \text{round}\left(\frac{V{t,c} - z_t}{s_t}\right)$
    • 反量化：$\tilde{V}{t,c} = s_t \cdot \hat{V}{t,c} + z_t$

  • 每个token有自己的一套 $(s_t, z_t)$，总共 $2N$ 个FP16元数据

设计理由: 逐token量化使得异常值token拥有自己的量化范围，其内部通道值可以精细地量化，而不会因为单个异常通道导致整个token的量化范围扩大。

步骤4: 分组量化以控制元数据开销

对于长序列，$2N$ 个FP16元数据（逐token Value量化）可能成为显著开销。KIVI使用分组量化：

  • 将每 $G$ 个连续的token分为一组（$G = 128$ 是典型值）
  • 每组共享一套scale和zero-point
  • 元数据开销：$2d + 2N/G$ 个FP16值（而非 $2N$ 个）

总内存 = 量化数据 + 元数据：

$$M_{\text{total}} = \frac{N \times d \times b}{8} + 2d \times 16/8 + \frac{2N \times 16}{G \times 8} \text{ bytes}$$

其中 $b = 2$（2比特量化）。

步骤5: 流式生成的残差缓冲区

对于自回归生成（token逐个到达）：

  • 维护一个小的FP16残差缓冲区 $B_K, B_V$，大小为 $B_{\text{size}}$（如32）
  • 前 $B_{\text{size}}$ 个新token的KV以FP16精度存储在残差缓冲区中
  • 当缓冲区满时，将整块token一起量化为2比特并添加到量化缓存中
  • 清空残差缓冲区，准备下一批token

这种分块量化策略的好处：

  • 减小频繁量化操作的开销（摊销为每$B_{\text{size}}$步量化一次）
  • 保持最近token的高精度（局部上下文对生成质量最重要）
  • 残差缓冲区的额外内存开销（$B_{\text{size}} \times d \times 2$ FP16）相对于总缓存可忽略

步骤6: 模型权重量化

可选的追加优化：将模型权重也量化为2比特：

  • 对权重矩阵执行逐组分组量化（每组128个元素）
  • 结合KV缓存量化（2-bit Key + 2-bit Value + 2-bit Weights）
  • 总体内存减少：原始FP16模型的2.6倍

RoPE集成的工程决策

LLaMA/Mistral/Falcon使用RoPE，其对Key向量的影响如下：

$$K_{\text{rope}} = \text{RoPE}(xW_K)$$

RoPE混合了通道对（$2i$ 和 $2i+1$ 通道通过旋转矩阵耦合）。

KIVI的量化顺序：先计算RoPE，后将结果量化为2比特。原因：

  • RoPE后通道间不再完全独立，但逐通道异常值模式仍然可辨识（混合了但未消失）
  • 在RoPE后量化确保量化引入的误差不会通过旋转操作扩散

这与KVQuant（Pre-RoPE量化）形成对比，体现了不同量化策略下的不同最优选择。

深度分析


Figure 5: 来源—原论文。

为什么Key和Value有根本不同的分布

Key和Value在注意力机制中扮演不同的计算角色，这自然地反映在它们的数值分布上：

  1. Key的角色: 匹配与路由:

    • Key投影的目标是产生能够精确区分的相似性分数
    • 某些通道专门用于存储”显著特征”（如语义类别标记），导致这些通道持续具有大值
    • 通道间的分工是结构性的，体现在投影矩阵 $W_K$ 的特定行/列

  2. Value的角色: 信息聚合:

    • Value投影的目标是产生可用于线性组合的语义表示
    • Value中的信息更均匀地分布在各个通道中
    • Token级别的异常值反映了该token的”语义权重”而非结构性的通道模式

  3. RoPE的差异化影响:

    • RoPE应用于Key后混合了相邻通道对，但通道异常值模式仍然可见
    • RoPE不应用于Value，因此Value的分布保持原始特征

2比特量化的数值挑战

将浮点数压缩到仅2比特（对应4个量化级别: 0, 1, 2, 3）带来了极大的约束：

  • 每个量化值只能表示4种不同的数值
  • 量化误差（$|\tilde{x} - x|$）在2比特时可能是4比特时的4倍
  • 对于256个通道，需要800个FP16元数据（scale + zero-point per channel）来支持2比特数据

然而，KIVI的实验表明，KV缓存对量化噪声的容忍度出乎意料地高：

  • 注意力计算中的Softmax归一化可以部分抵消Key量化噪声
  • Value的加权求和操作可以通过”平均效应”掩盖Value量化噪声
  • 多层Transformer的残差连接提供了误差恢复机制

免调参设计的工程价值

KIVI不需要校准数据的设计在工程实践中意义重大：

  1. 跨域泛化: 校准数据无法覆盖所有可能的输入领域。一个在WikiText上校准的量化器在处理数学论文时可能表现不佳。KIVI通过设计通用的量化范式（而非学习特定的量化参数）来实现跨域泛化。

  2. 部署简化: 无需收集、维护和加载校准数据集。这消除了一个关键的运维复杂性。

  3. 失败模式简化: 无校准意味着预测量化效果更简单——如果KIVI适用（即模型架构兼容），它在所有输入上都会以相同方式运行，不会有数据依赖的性能波动。

与KVQuant的对比分析

KIVI和KVQuant代表了两种不同的量化哲学：

维度 KIVI KVQuant
量化位置 Post-RoPE Pre-RoPE
Key策略 逐通道 逐向量稠密-稀疏
Value策略 逐token 逐向量
量化类型 非均匀（非对称） 非均匀（k-means + Fisher）
需要校准 否 否（但需要使用Fisher信息）
目标比特率 2-bit 3-4 bit
额外技术 残差缓冲区分块 Q-Norm感知量化

两者是不矛盾的——KVQuant的Pre-RoPE量化结合KIVI的逐通道策略可能是更强的组合。

对比定位

vs 均匀量化方法

维度 Uniform Int4 KIVI
K和V策略 相同 非对称（K per-channel, V per-token）
异常值处理 异常值扩展所有值的量化范围 异常值仅在自身通道/token内影响
2-bit可行性 退化严重 可接受退化
需要校准 通常需要 不需要

关键区别: 均匀量化将异常值的影响全局化了。一个幅值为100的异常值会导致整个量化网格的分辨率降低100倍。KIVI的非对称策略将异常值隔离在自己所属的通道/token内。

vs GPTQ风格量化

维度 GPTQ KIVI
量化对象 模型权重 KV缓存
策略 Hessian-based排序量化 基于分布分析的非对称量化
需要校准 是（需要梯度信息） 否
量化为 2/3/4/8-bit 2/4-bit
推理时 静态（预量化） 动态（在线量化KV）

关键区别: GPTQ量化的对象是静态的模型权重，而KV缓存是在推理时在线生成的，需要动态量化。KIVI的设计充分考虑了动态量化的需求（低开销、在线执行）。

vs 基于稀疏度的KV剪枝

维度 KV稀疏化 KIVI量化
压缩维 token数量 per-token存储
信息损失 token级别（全部丢失） token内精度降低
互补性 与KIVI正交 与稀疏化正交

关键区别: 稀疏化保留部分token的全部信息、其他token的零信息。量化保留所有token但精度降低。两者互补可叠加。

局限

1. 无法完全消除元数据开销

问题: 逐通道和逐token的非对称量化需要存储scale和zero-point。对于2比特量化，元数据开销（4字节per element）可能超过有效负载（2比特 = 0.25字节per element）。

以LLaMA-2-7B ($d=128$)为例：

  • 量化数据: $128 \times N \times 2 / 8 = 32N$ bytes
  • 逐通道Key元数据: $2 \times 128 \times 2 = 512$ bytes (固定)
  • 逐token Value元数据: $2 \times 4 \times N / G$ bytes (随$N$增长)

对于短序列（$N<100$），元数据占比可能超过50%。

影响: 在极短序列场景下，KIVI的净内存节省不如声称的显著。

2. 分块策略的时间延迟

问题: 残差缓冲区的分块量化机制意味着最后$B_{\text{size}}$个token始终以FP16存储。对于$B_{\text{size}}=32$，这意味至少32个token的内存”浪费”在FP16上。此外，缓冲区中的token在正式进入量化缓存前无法享受到2-bit内存节省。

影响: 在严格内存约束场景下，需要将$B_{\text{size}}$设置得更小（如8或16），但这会降低分块量化的效率。

3. 对特定架构的依赖

问题: KIVI的逐通道/逐token区分依赖于Key和Value的特定数值分布特性。对于使用不同注意力机制（如多查询注意力MQA、分组查询注意力GQA）或不同位置编码（如ALiBi、无位置编码）的模型，这些分布特性可能不同。

影响: KIVI在一个新架构上的应用需要先进行分布分析以验证假设。不能保证在所有架构上都同样有效。

4. 软硬件的兼容性

问题: 2比特算术操作不是GPU的标准操作。实际实现中需要将2比特数据解压缩为FP16/INT8进行计算，引入额外的解压开销。

影响: 名义上的”2比特存储”不一定转化为”2比特速度”。实际加速比取决于解压开销与内存带宽节省的权衡。

5. 与KV稀疏化的组合效率

问题: 如果与H2O或StreamingLLM等稀疏化方法组合，稀疏化后的token数量减少会使KIVI的元数据开销占比显著增加（因为逐token/逐通道元数据相对于实际token数变成更大的负担）。

影响: 在极端稀疏化场景下，可能需要降低量化粒度（从逐通道改为逐组）来控制元数据开销。

可复用洞见

1. 分布分析引导量化策略

洞见: KIVI的成功来源于对KV缓存数值分布的仔细分析，而非盲目应用现有量化技术。在将任何优化技术应用于新场景前，先分析数据的统计特性是关键的步骤。

如何应用:

  • 在量化其他模型组件时（如注意力输出、FFN中间状态），首先进行分布分析
  • 关注不同维度的异常值模式（通道、token、层、头）
  • 根据分布特性选择量化粒度而非使用统一策略

2. 结构不对称性蕴含优化机会

洞见: KIVI揭示了Key和Value在数值结构上的不对称性，并利用这种不对称性设计了差异化的量化策略。在ML系统的其他组件中，类似的结构不对称性很可能存在，等待被发现和利用。

如何应用:

  • 在分析系统组件时，积极寻找”不对称性”——在某个维度上的行为差异
  • 为具有不同特性的组件设计不同的而非统一的处理方案
  • 不要因为”看起来相似”就默认使用相同的优化策略

3. 免调参设计的价值

洞见: 在维护和部署成本高昂的生产环境中，”无需调参”是一个被低估的设计目标。KIVI通过通用设计（而非学习特定参数）实现了这一点，证明”差一点的通用方案”往往优于”最优的特定方案”。

如何应用:

  • 在设计优化方法时，将”零配置”作为核心设计约束
  • 优先选择基于统计特性的通用方案，其次考虑基于学习的特定方案
  • 为新方法提供默认的超参数集，使其能够开箱即用

4. 分块处理在流式场景中的通用价值

洞见: KIVI的残差缓冲区分块量化策略是一个通用的设计模式——在流式处理的场景中，使用小缓冲区积累数据然后进行批量处理，同时保持最近元素的高精度。这种模式可以推广到其他流式系统优化中。

如何应用:

  • 在流式ML推理中使用分块策略平衡延迟和吞吐量
  • 将”最近元素保持高精度”作为流式量化的默认启发式
  • 选择分块大小时考虑精度-效率权衡

5. RoPE是KV缓存量化的关键考虑因素

洞见: RoPE的位置嵌入操作对Key向量的通道结构产生显著的混合影响。任何KV缓存量化的方法都必须明确考虑RoPE的交互——无论是选择前RoPE量化（如KVQuant）还是后RoPE量化（如KIVI）。

如何应用:

  • 在涉及RoPE模型的任何KV缓存操作中，明确考虑RoPE的影响
  • 对于位置编码的操作，分析其对后续优化（量化、稀疏化）的影响
  • 将RoPE处理作为KV优化pipeline的显式步骤

我的笔记

对后续研究的启发

  1. 2比特是可部署的极限: KIVI证明了2比特KV缓存量化在实际系统中是可用的，且质量退化可控。这为整个领域设立了”2比特够了”的基线，后续研究需要在此基线上证明改进的必要性。

  2. 免调参的趋势: 随着LLM在多种场景中广泛部署，免调参的方法越来越受重视。KIVI是这一趋势的代表，后续工作（如KVQuant的部分特性）也在走向免调参方向。

  3. 从KV缓存扩展到其他中间状态: KIVI的成功表明，Transformer中的中间状态可能都有优化空间。注意力输出的”残差状态”、FFN的中间激活等都可以从类似的分布分析开始，探索量化或压缩的可能性。

实际应用场景

  1. 消费级硬件上的长上下文推理: KIVI将KV缓存从2GB压缩到0.25GB（7B模型, 4K序列），使得在16GB VRAM的GPU上运行长上下文推理成为可能。

  2. 大batch实时服务: KV缓存内存是限制batch size的主要因素。KIVI的4倍batch size提升直接转化为4倍吞吐量，对高并发推理服务至关重要。

  3. 边缘和移动部署: 在内存极度受限的边缘设备上，KIVI的2比特量化可能是唯一能让LLM运行长上下文的方案。

后续问题

1. 1比特KV缓存量化

问题: 是否可以将KV缓存进一步压缩到1比特（二元量化）？二值化的Key和Value会保留多少信息？

研究方向:

  • 探索1比特binary量化 + 残差校正的策略
  • 使用随机化技术（如stochastic rounding）改善1比特量化质量
  • 分析1比特量化的理论性能下界

潜在影响: 如果可以实用化，将再实现2倍额外内存节省。

2. 异常值感知的模型架构设计

问题: 如果KV缓存的异常值模式是可预测的（特定通道始终为异常值），能否在模型架构设计阶段就考虑这一点？例如，将异常值通道分离为更高精度的独立流。

研究方向:

  • 设计显式分离异常值通道和正常通道的Key投影
  • 探索”内置量化”的Transformer变体
  • 在架构搜索中考虑推理内存效率

潜在影响: 从根本上解决量化-精度权衡。

3. 量化与稀疏化的联合优化

问题: KIVI与H2O/StreamingLLM等稀疏化方法是相互独立的。能否设计一个联合优化框架，同时进行token驱逐和精度降低决策？

研究方向:

  • 开发统一的率失真优化框架
  • 设计动态的精度分配策略（重要token高精度、非重要token低精度）
  • 研究联合优化是否能突破单独优化的帕累托前沿

潜在影响: 实现比单独优化更好的质量-效率权衡。

4. 硬件原生支持2比特操作

问题: 当前GPU没有原生的2比特算术支持。如果未来硬件提供2比特矩阵乘法、2比特加法和Softmax近似，KIVI等方法的实际加速将达到什么水平？

研究方向:

  • 为2比特KV缓存操作设计专用硬件加速器
  • 分析2比特精度下的端到端推理延迟
  • 研究混合精度（2比特存储、FP16计算） vs 原生2比特计算的权衡

潜在影响: 推动硬件发展以匹配软件量化能力。

5. 训练阶段的量化感知

问题: 能否在预训练阶段就考虑KV缓存将被量化这一事实？量化感知训练（QAT）是否可以进一步提升2比特KV缓存的生成质量？

研究方向:

  • 设计KV缓存量化的QAT算法
  • 探索在预训练中模拟低精度KV缓存的效果
  • 研究QAT后是否可以进一步降低比特率（如1.5比特）

潜在影响: 在不增加推理开销的情况下提升量化质量。
