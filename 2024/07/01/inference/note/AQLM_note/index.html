AQLM: Extreme Compression of Large Language Models via Additive Quantization

AQLM: 基于加性量化的LLM极致压缩方法

原文摘要翻译

我们提出加性量化语言模型（AQLM），一种面向LLM的极致压缩方法。AQLM将信息检索领域的经典加性量化（AQ）框架泛化到LLM权重压缩中。具体而言，每个权重向量被表示为学习得到的码本中多个向量的和，这比传统的标量量化提供了更丰富的表示能力。我们通过三个关键创新使AQ适应LLM压缩：我们将AQ扩展到输入自适应的权重编码、跨整个Transformer块联合优化码本参数，以及使用专门的微调步骤进一步恢复质量。在Llama 2 70B上，AQLM以2位精度达到的压缩效果仅比FP16退化0.22 perplexity，一致优于所有已知的后训练量化方法。此外，我们提供高效的GPU和CPU推理内核，使得在显著减少内存的同时能够匹配甚至超越FP16的推理速度。

创新点

1. 将加性量化从信息检索推广到LLM权重量化

核心思想: 加性量化（Additive Quantization, AQ）是信息检索中压缩高维向量的经典技术。其核心思想是：一个高维向量 不是被量化到单个最近的码本向量，而是被表示为个来自不同码本的向量的和：

其中是第个码本，是从该码本中选择的索引。个码本，每个码本个码字，可表示种不同的组合——指数级增长的表示空间。

为什么重要: 标量量化每权重独立决策，个权重需个索引。向量量化（如E8格）一次处理个权重，但表示能力有限。加性量化位于两者之间：用多个码本的组合来表示一个权重向量组，提供了指数级的表示空间，同时保持了较低的索引存储开销。

2. 输入自适应权重量化

核心思想: 传统的权重量化假设特定权重的”重要性”是固定的。AQLM发现这是次优的——权重的重要性取决于其输入上下文（即激活模式）。因此AQLM使码本查找依赖于输入：对于输入，权重在不同上下文中的重要程度不同，码本索引的选择应以最小化输出误差（而非重构误差）为目标。

为什么重要: 这是从”重构优化”到”功能优化”的范式转变——不是在重建原权重，而是在优化网络的实际输出行为。输入自适应的量化更好地保护了对最终输出更关键的网络路径。

3. 跨Transformer块的联合码本优化

核心思想: 逐层量化（每层独立优化重构误差）在LLM中可能次优——一层的小误差可能在经过多层后被放大。AQLM将优化范围从单层扩展到整个Transformer块（一个自注意力子块 + 一个FFN子块），通过反向传播联合优化该块内所有层的码本参数。

为什么重要: 这解决了”误差累积”问题——如果注意力层的输出有0.01的小偏差，经FFN层后可能被放大为0.1的偏差。通过跨层联合优化，误差可以在一层内被另一层”补偿”，就像GPTQ在权重列间补偿误差的跨层版本。

4. PV-Tuning专门的微调方案

核心思想: 在量化完成后，AQLM执行PV-Tuning（基于投影和值的微调）：冻结量化权重（仅更新码本向量，不改变索引分配），使用重构损失和教师-学生蒸馏损失的组合在标定数据上微调码本内容。

为什么重要: 这是量化后的”软着陆”——索引分配（哪个权重用哪个码字）保持不变，但码字本身的向量值可以微调以减少剩余误差。PV-Tuning的成本远低于全模型微调，但在2位精度下贡献了有意义的perplexity改善（通常0.1-0.2 ppl）。

一句话总结

AQLM通过将信息检索的加性量化泛化到LLM权重、引入输入自适应编码和跨Transformer块联合优化，在2位极致压缩下为Llama 2 70B达到仅退化0.22 perplexity的最优结果，并提供了可匹敌FP16推理速度的高效运行内核。

研究问题

核心挑战

在2-3位的极致压缩范围内，传统的标量量化（GPTQ、AWQ）面临信息论瓶颈：

  • 每权重2位 = 仅4个不同值
  • 即使有分组缩放和误差补偿，4值的表达能力本质上限制了精度

加性量化的核心问题是：能否在保持较低索引存储开销的同时，指数级地增加有效表示容量？

AQ的LLM适配挑战

经典AQ是为高维空间最近邻搜索设计的，直接应用于LLM权重面临三个问题：

  1. 维度不匹配: LLM权重矩阵的行或列通常为维（4096-8192），但AQ在1024-2048维的空间中效果最好
  2. 计算效率: AQ解码（索引->码字->求和）需要多路内存访问和加法，在GPU上的延迟可能抵消内存节省
  3. 优化目标: AQ优化重构误差，但LLM需要的是功能等价（输出误差最小化）

关键洞察

加性量化的指数表示空间天然适合LLM权重的结构化冗余：极少数比特可以表示大量不同的模式，而网络功能仅依赖于部分模式的有效组合。

步骤2: 输入自适应的码字分配

步骤输入: 各组权重向量，标定激活，当前码本
步骤操作:

  • 对每个权重组，不是通过重构误差选择码字索引，而是通过功能误差：
    $$i_m^* = \text{argmin}{i} |X(W_g - \sum{m} C_m[i_m])|_2^2$$
  • 展开来说：将候选加性表示 应用到网络的对应位置，选择使输出激活误差最小的对
  • 由于穷举搜索( 种组合太大)，采用beam search或迭代优化：固定一个码本的索引，优化另一个
  • 最终每个权重组被编码为——两个16位索引
    步骤输出: 每组的索引对，以及优化后的码本

步骤3: 跨Transformer块联合优化

步骤输入: 当前Transformer块所有层的量化索引和码本，标定数据
步骤操作:

  • 构建该块的完整前向计算图（例如：Attention QKV投影 + Attention Output投影 + FFN Up + Gate + Down投影）
  • 冻结索引分配（不变），将码本向量视为可训练参数
  • 优化目标：最小化该块输出与原始FP16块输出的均方误差
    $$\text{min}{{C}} \mathbb{E}{X} \left[ |f_{\text{block}}^{\text{FP16}}(X) - f_{\text{block}}^{\text{AQLM}}(X) |^2 \right]$$
  • 反向传播更新所有层的码本向量
  • 关键优势：如果自注意力输出的量化误差可以被FFN输入层的码本”吸收”，联合优化会自然地调整码本来实现这一点
    步骤输出: 联合优化后的码本向量

步骤4: PV-Tuning质量恢复

步骤输入: 量化模型、优化后的码本、标定数据
步骤操作:

  • 保持索引分配不变（不重新搜索最佳码字），仅微调码本向量的数值
  • 使用两个损失：
    • 重构损失： （使码字更好地重建原始权重行为）
    • 蒸馏损失： （使量化模型的输出分布匹配原始模型的输出分布）
  • 在少量标定数据上微调若干epoch，学习率极低（通常1e-5到1e-6）
  • PV-Tuning比块联合优化更昂贵（需多次前向+反向），但质量恢复效果更好
    步骤输出: 最终微调后的码本和量化模型

GPU推理内核设计

AQLM的推理面临一个特殊挑战：加性量化解码需要从码本加载码字向量（随机访问模式），并将它们相加。论文设计了融合内核：

  1. 从group index查找两级码本索引
  2. 从GPU shared memory（存储码本向量）加载对应码字
  3. 将个码字相加形成反量化权重向量
  4. 与激活矩阵相乘

关键优化：码本存储在shared memory中（大小约 ），避免从HBM读取码字，使解码延迟远低于HBM访问延迟。

深度分析


Figure 5: 来源—原论文。

加性量化 vs 格量化 (QuIP#)

AQLM和QuIP#代表了2位量化的两种路线：

  • QuIP#: 数学构造路线——使用预定义的E8格，依赖去相关预处理使分布匹配格结构
  • AQLM: 数据驱动路线——从数据中学习码本，使其适配权重的实际分布

两者的2位表现极为接近（均约+0.22 ppl on 70B），但路线完全不同。AQLM的优势在于灵活性——学到的码本可以适应任意分布的权重；QuIP#的优势在于优雅性——无需学习，数学结构保证了无偏性。

输入自适应编码的精妙性

AQLM的输入自适应编码是最容易被忽略的创新。直观理解：

  • 非自适应：选择使 最小的索引
  • 输入自适应：选择使 最小的索引

差别在于——不同输入的激活模式不同。如果在给定的输入下，某个权重维度的激活几乎为0，那么在该维度上的量化误差对输出的影响也几乎为0——量化器可以将更多”精度预算”分配给激活幅值大的维度。这本质上是AWQ的缩放保护逻辑编码到了码本选择过程中。

块联合优化的作用范围

单独优化每个层的码本忽略了跨层误差传播。考虑一个简单场景：

  • 自注意力的输出投影有一个小的量化偏差
  • FFN的输入投影将乘以一个大权重矩阵
  • 这个大矩阵可能将放大（通过对应的奇异值）
  • 最终输出误差 可能远大于

块联合优化通过同时调整自注意力输出投影和FFN输入投影的码本，使前者的偏差被后者”补偿”——即FFN输入层学习轻微改变其行为来消除前一层引入的特定误差模式。

PV-Tuning = 精调而非重训

PV-Tuning的命名（Projection-Value Tuning）暗示了其操作：冻结投影（索引分配），微调值（码本向量）。这相当于在量化空间内做局部搜索，找到给定分配下最优的码本向量。因为不改变索引分配（输出行为的大结构不变），PV-Tuning不会引入过拟合，仅做精细校准。

局限

1. 训练流程复杂

AQLM的完整流程包括码本初始化（K-means）、输入自适应分配（beam search）、块联合优化（反向传播）和PV-Tuning（蒸馏微调）——总共四个阶段。相比GPTQ的”一次性Hessian+逐列量化”或AWQ的”激活统计+网格搜索”，AQLM的实施更复杂。

2. 推理内核的内存层次压力

AQLM的解码需要将码本向量存储在快速的shared memory中。当 且 时，码本约需 的shared memory。A100每个SM有164KB shared memory，远不足以存储完整码本。论文使用码本分片存储和部分缓存策略，这会增加额外的HBM读取。

3. 码本初始化质量依赖

码本初始化的质量（K-means收敛程度）对最终量化效果有不可忽略的影响。不好的初始化可能导致beam search陷入差的局部最优。论文未系统研究初始化策略的敏感性。

4. 非标准架构的适配成本

加性量化的优化（输入自适应编码、块联合优化）是针对标准Transformer设计的。对于MoE、Mamba、RWKV等新架构，这些优化策略需要重新设计和验证。

可复用洞见

1. 信息检索技术向ML压缩的迁移

AQ最初是为高维向量相似搜索设计的（Product Quantization及其变体）。AQLM展示了这类技术迁移到ML权重量化的巨大潜力。类似地，其他信息检索技术（如Locality-Sensitive Hashing、HNSW图的量化版本）也可能被适配。

如何应用: 在解决ML压缩问题时，跨领域搜索信息检索、数据库和信号处理领域的已有技术——这些领域有数十年的量化研究积累。

2. 功能优化 > 重构优化

AQLM的所有优化（输入自适应、块联合、蒸馏）围绕同一个原则：优化网络行为而非重构权重。这是超越GPTQ类方法的根本原因——GPTQ最小化权重重构误差（ ），AQLM最小化网络输出误差（ ）。

如何应用: 在压缩或近似任何计算组件时，以最终系统的行为误差为优化目标，而非组件的参数重构误差。

3. 指数表示空间的经济性

个码本、个码字提供的个组合，仅需位索引——这是信息论上的高效编码。核心在于：码本的存储成本在各组间摊销（所有组共享相同码本），而每个组仅需少量索引位。

如何应用: 在设计参数化系统时，寻找”共享结构+局部索引”的高效编码模式，使局部表示的空间呈指数级远超局部索引的比特数。

我的笔记

对后续研究的启发

  1. 与GPTQ的互补性: AQLM的输入自适应分配和GPTQ的Hessian补偿可以结合——先用Hessian信息引导码字分配，再通过二阶补偿减少剩余的量化误差。

  2. 码本学习的规模化: AQLM当前的码本学习是逐层/逐块的。更大范围的联合学习（跨多个块甚至全模型）可能进一步提升质量，但计算成本也会指数增长。

  3. 加密/隐私部署: AQLM的码本-索引结构天然适合某些加密计算场景——零知识证明中验证”我知道码本索引”比验证”我知道浮点权重”简单得多。

实际应用考量

  • AQLM是2位量化的最佳选择之一（与QuIP#并列）
  • 需要接受其训练流程的复杂性（4阶段流水线）
  • 推理内核的成熟度在快速提升中
  • 在3位精度下，AQLM提供最佳的质量-压缩率平衡

工程实践

  • 码本初始化用K-means++而非随机初始化，质量差距显著
  • 输入自适应beam search的beam width=4在大部分情况下足够
  • PV-Tuning的学习率调度：前50%步数线性warmup，后50%余弦衰减
  • 块联合优化对大型模型（70B）收益最大——小模型（7B）收益有限

后续问题

1. 码本学习的训练数据依赖性

当前码本在标定数据上学习。如果部署数据分布不同，码本是否需要重新适配？重新进行部分阶段的优化（如仅PV-Tuning）的成本和效果如何？

2. 码本结构的理论最优性

AQLM的 配置是经验选择。是否存在理论上的最优组合，在给定比特预算下最大化表示容量？M和K之间的trade-off如何量化？

3. 与知识蒸馏的深层结合

PV-Tuning使用蒸馏损失，但仅限于码本微调阶段。如果在量化之前的初始阶段就使用知识蒸馏来训练更”量化友好”的权重分布，是否能解锁更高的压缩率？

4. 多语言和多模态扩展

学到的码本针对单一语言（主要是英语）的训练数据。在多语言LLM中，不同语言的权重使用模式可能不同——码本是否需要覆盖跨语言的使用差异？多模态中的视觉编码器权重是否适合加性量化？

5. 超越2位的极限

AQLM将2位做到了接近实用。是否存在通往1位或1.58位（类似BitNet）的加性量化路径？如果码本被完全替换为简单的{-1, 0, 1}操作，加性量化的框架还剩下什么优势？
