Scaling Rectified Flow Transformers for High-Resolution Image Synthesis

Stable Diffusion 3: 基于 Rectified Flow Transformer 的文生图规模化

原文摘要翻译

扩散模型在图像和视频数据上创建数据时已经达到了新的高度。尽管它们已经取得了成功，但这些模型仍然通用的 U-Net 骨干网络长期以来一直是文生图的默认选择。本文探索了 Transformer 架构在文本到图像生成中的规模化应用，提出了一种新的多模态 Diffusion Transformer（MMDiT），它使用独立的权重集合来处理图像标记和文本标记，但允许两者通过联合注意力机制进行信息交换。我们使用 Rectified Flow 生成模型，该模型将数据和噪声连接为直线，因此可以使用直线轨迹进行更高效的推理。通过创新的噪声采样策略将训练集中在感知上相关的尺度上，结果形成了一个系统，其验证损失在不同参数规模和训练步数上遵循可预测的缩放规律。最终我们展示了从 800M 到 8B 参数的各种模型基准结果，验证了该架构的有效性。

创新点

1. 从 U-Net 到 DiT：Transformer 架构的范式迁移

核心思想: 用基于 Transformer 的多模态 DiT（MMDiT）取代传统的 U-Net 扩散骨干。MMDiT 对图像 token 和文本 token 使用各自独立的权重路径，但通过联合注意力机制实现双向信息交互——这是扩散模型从”CNN 时代”正式进入”Transformer 时代”的标志性工作。

为什么重要: 这是文生图模型架构史上的一个重要拐点。U-Net 此前统治扩散模型长达 4 年（从 DDPM 2020 到 SDXL 2023），SD3 首次在大规模文生图中验证了 Transformer 架构的可行性。更重要的是，Transformer 的可扩展性与 LLM 的经验一致——这使得文生图模型也可以像 GPT 一样通过规模化持续提升。

2. Rectified Flow 替代传统扩散

核心思想: 将生成过程建模为从噪声到数据的直线路径（而非随机扩散过程的随机路径）。训练目标从”预测噪声”（epsilon-prediction）改为”预测速度场”（velocity field）：v = x_1 - x_0。这意味着在推理时，模型沿着几乎直线的轨迹从噪声走向数据，可以用更少的步骤完成采样。

为什么重要: Rectified Flow 提供了比传统 DDPM/DDIM 更简洁的理论框架和更高效的训练。直线路径意味着：（1）采样步骤可以更少（因为路径更短、更直）；（2）训练目标更简单（直接预测速度而非预测噪声）；（3）天然支持从数据到噪声和从噪声到数据的双向变换。这个选择也被 Flux 继承。

3. 创新的噪声采样策略

核心思想: 训练时对噪声水平 t 进行非均匀采样——倾向于感知相关的中间尺度——使模型更多地在”人类视觉最敏感”的噪声范围内进行训练。具体来说，使用对数正态分布采样来偏置中间噪声水平。

为什么重要: 在传统扩散模型中，去噪前期（高噪声、几乎纯随机）和后期（极低噪声、几乎无变化）的训练对最终生成质量的贡献相对较小。将训练集中在中噪声区域等同于将计算资源分配到最关键的生成阶段，在固定训练预算下显著提升生成质量。

4. 可预测的 Scaling Law

核心思想: SD3 验证了文生图领域中清晰的 scaling law——从 800M 到 8B 参数，验证损失（validation loss）随模型规模呈现规律的幂律下降，且验证损失与文生图质量（FID、CLIP Score）之间存在稳定的对应关系。

为什么重要: 这是 SD3 获得 ICML 2024 Best Paper Award 的核心原因之一。它证明文生图模型的规模化是可预测的（而非撞大运），给模型投资提供了科学依据。在 LLM 领域，scaling law 已经是标准操作（从 Kaplan et al. 2020 开始）；SD3 将这一范式完整地迁移到了视觉生成领域。

一句话总结

SD3 通过将文生图模型从 U-Net 切换到基于 Rectified Flow 的 MMDiT Transformer 架构，验证了清晰的 scaling law——随着参数从 800M 扩展到 8B，模型性能持续、可预测地提升，标志着文生图从”U-Net 工程改进”时代正式进入”Transformer 规模化”时代。

研究问题

核心挑战

截至 2024 年初，文生图模型面临两个根本性的架构问题：

  1. U-Net 扩展性差: U-Net 架构的参数量扩展无法像 Transformer 那样呈现稳定的幂律收益，在某个规模后性能提升趋于平坦
  2. 模态融合不够自然: U-Net 中文本条件通过交叉注意力注入，文本和图像信息之间的流动是单向的（文本 -> 图像），缺少双向交互

关键假设

Transformer 架构 + Rectified Flow + 创新的噪声采样 = 文生图的 LLM 式 scaling law。

整体架构

SD3 的 MMDiT 架构将文生图建模为：

  1. 图像 Patch 编码: 图像潜变量切成 patch，线性投影为图像 token
  2. 文本编码: 双编码器（CLIP + T5）提取文本 token
  3. MMDiT 处理: 图像 token 和文本 token 通过各自独立的注意力权重路径 + 联合注意力层进行双向交互
  4. Rectified Flow 采样: 沿直线路径从噪声恢复到数据

机制流程


Figure 2: 来源—原论文。

步骤 1: 图像 Patch 化与 Token 化

步骤输入: VAE 编码后的潜变量 z（32x32x4 或更多通道）
步骤操作:

  • 将潜变量按 2x2 的 patch 切分（与 ViT 的 patch embedding 类似）
  • 每个 patch 通过线性投影转换为 d_model 维的 token
  • 加上位置编码（使用 2D RoPE 或可学习的位置嵌入）
    步骤输出: N_img 个图像 token（如 16x16 = 256 个 token，每个维度 d_model）

步骤 2: 文本 Token 化

步骤输入: 文本 prompt
步骤操作:

  • CLIP 编码器：提取全局文本嵌入（pooled）和 token 级嵌入
  • T5 编码器：提取 token 级嵌入（提供深度语义理解）
  • 通过小型投影网络将文本嵌入映射到 Transformer 的 d_model 维度
    步骤输出: N_txt 个文本 token（每个维度 d_model）

步骤 3: MMDiT 联合注意力处理

步骤输入: 图像 token 序列和文本 token 序列
步骤操作:
步骤图像自注意力: 图像 token 之间进行自注意力（使用图像专属的 W_Q, W_K, W_V）
步骤文本自注意力: 文本 token 之间进行自注意力（使用文本专属的 W_Q, W_K, W_V）
步骤联合注意力: 图像 token 作为 Query，文本 token 作为 Key 和 Value——实现文本到图像的信息注入；同时文本 token 也关注图像 token——实现双向信息流
步骤FFN: 独立的图像 FFN 和文本 FFN

  • 重复多个 Transformer 块（约 24-32 层）
  • 注入时间步 t 和噪声水平信息
    步骤输出: 处理后的图像 token 和文本 token

步骤 4: Rectified Flow 采样

步骤输入: 纯噪声 z_T ~ N(0, I) 和文本条件 c
步骤操作:

  • Rectified Flow 定义：z_t = (1-t) * z_0 + t * z_1（线性插值）
  • 速度场：v_t = z_1 - z_0（从噪声到数据的直线速度）
  • 训练目标：MMDiT 预测 v_θ(z_t, t, c)，最小化 E[||v_θ(z_t, t, c) - (z_1 - z_0)||^2]
  • 推理时使用 ODE solver（如 Euler 或 Heun 方法），沿直线方向积分
  • 因为路径是直的，只需少量步数（如 20-50 步）即可达到高质量
  • Classifier-free guidance 在速度场空间中计算
    步骤输出: 解码后的 RGB 图像

Rectified Flow 与传统扩散的对比

维度 传统扩散 (DDPM) Rectified Flow (SD3)
正向路径 随机（SDE） 直线（ODE）

噪声采样策略的细节

SD3 采用对数正态（log-normal）采样来偏置训练噪声水平：

这样噪声水平 t 的分布集中在中间区域（0.1~0.9），而非均匀分布在整个 [0, 1] 区间。动机：

  • t 接近 0: 几乎无噪声，去噪任务是平凡的
  • t 接近 1: 几乎纯噪声，去噪任务几乎无信息

深度分析


Figure 5: 来源—原论文。

为什么 MMDiT 是”双流”而非”单流”

MMDiT 的关键设计选择是为文本和图像维护各自独立的权重路径（双流），而非完全统一的单流 Transformer：

  1. 模态差异: 文本 token 和图像 token 承载的信息类型不同——文本是抽象语义，图像是空间-视觉信息
  2. 序列长度不对称: 文本序列（~77-512 tokens）远短于图像序列（256-1024 tokens），统一处理会导致文本被稀释
  3. 训练稳定性: 独立权重路径避免了模态间不均衡的梯度干扰

这一设计与 Flux 的混合架构（19 个双流 + 38 个单流块）形成对比——Flux 认为一定量的单流融合是必要的，而 SD3 保留了完整的双流设计。

Scaling Law 的深层含义

SD3 验证的 scaling law 有几个实用洞见：

  1. 可预测性: 在投资训练 8B 模型之前，可以从 800M 模型的验证损失可靠地预测 8B 模型的损失——大幅降低了大规模训练的风险

  2. 数据效率: 更大的模型需要更少的训练数据即可达到相同质量——这对训练预算分配有直接指导

  3. 计算最优分配: 在给定的计算预算下，可以优化模型规模和训练数据量的分配——类似 Chinchilla 定律在文生图领域的对应

Rectified Flow 的理论优势

Rectified Flow 提供的不只是工程加速——它改变了扩散模型的底层数学框架：

  • DDPM: 学习 score function（对数概率密度的梯度），需要通过复杂的 SDE 和 ODE 等价来建立
  • Rectified Flow: 直接学习速度场——从噪声到数据的直线位移。目标函数更直接，理论更清晰

局限

1. 架构复杂度增加

问题: MMDiT 的训练和推理比 U-Net 更复杂——需要处理两种模态的独立权重路径、联合注意力计算、位置编码管理等。

影响: 对推理速度、内存开销和部署优化提出了新挑战。

2. 对长文本的理解仍然有限

问题: 虽然使用了 T5 编码器，但长文本场景（如详细场景描述、复杂指令）的文本跟随度仍然有提升空间。

影响: 在专业设计工作流中仍需要人工后处理。

3. Rectified Flow 的样本多样性

问题: 直线路径虽然高效，但可能会限制生成样本的多样性——在更窄的路径空间中探索。

影响: 在需要高度多样化输出的创意场景中可能不如传统 SDE-based 扩散。

4. 训练成本

问题: 8B 参数的 Transformer 训练需要巨大的计算资源——远超学术研究团队的预算。

影响: 限制了学术界的独立验证和改进。

5. 评估指标的限制

问题: FID、CLIP Score、人类偏好 ELO 等指标虽然常用，但无法全面反映”语义理解深度”和”创意质量”等维度。

影响: 可能存在指标与真实用户体验之间的 gap。

可复用洞见

1. Transformer 的通用性

洞见: Transformer 不仅是 NLP 的最佳架构，也是视觉生成的最佳架构成分之一。其可扩展性（scaling law）使得性能提升变得可预测和可投资。

后续应用: Sora 使用 DiT 架构进行视频生成，进一步验证了 Transformer 在视频域的适用性。

2. Rectified Flow 的通用价值

洞见: 将生成过程建模为直线路径而非随机扩散具有理论和工程双重优势——训练目标更简洁、采样更高效。

后续应用: Flux 完整继承了 Rectified Flow，许多后续工作（如视频生成中的 Flow Matching）也采用了类似思路。

3. 噪声水平感知训练

洞见: 对训练样本（噪声水平）进行有意识的重加权是一个简单但有效的技巧——与课程学习（curriculum learning）的思想一致。

后续应用: 可以推广到任何使用扩散/Flow 模式的生成任务。

我的笔记

SD3 的里程碑意义

SD3 获得 ICML 2024 Best Paper Award 不仅是对其技术贡献的认可，更有象征意义——它标志着学术界对文生图研究达到了最高级别的重视。从 DALL-E 2021 的”这能行吗”到 SD3 2024 的 ICML 最佳论文，文生图领域用了不到 4 年完成了从工程demo到顶级学术认可的跨越。

U-Net 时代的终结

SD3 的发表正式宣告了 U-Net 在文生图模型中的”退位”。但这不意味着 U-Net 失去了价值——在嵌入、低预算、快速推理等场景中，U-Net 仍有不可替代的优势。SD3 的意义在于它为文生图的未来提供了一个与 LLM 共享基础设施的技术路线：同样的 Transformer 蓝色图、同样的 scaling law 思维、同样的规模化训练经验。

下一步是什么

SD3 将文生图带入了 Transformer 时代，但这只是开始。接下来的问题包括：

  • 能否实现端到端的文本-视觉联合预训练（类似 GPT-4V 的思路）？
  • 能否将 LLM 的知识直接注入文生图（而不仅仅是 T5 文本编码）？
  • 视觉生成和视觉理解能否在同一个架构中统一？

2. Scaling Law 的上限

问题: SD3 验证了从 800M 到 8B 的 scaling law。继续扩展到 80B 或 800B，scaling law 还能保持吗？是否存在视觉生成特有的规模瓶颈？

3. 文本理解的下一步

问题: T5 已经提供了很强的文本理解。进一步提升文本跟随度的方向是什么？使用更大的 LLM？微调 LLM？还是改进交叉注意力机制？
