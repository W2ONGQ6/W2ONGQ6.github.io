二、为什么需要微调

2.1 预训练模型的三个局限

预训练模型在海量数据上学习通用语言规律,但存在明显局限:

  1. 通用但不专精: 对特定领域(医疗、法律、金融)的术语和逻辑理解不足
  2. 不会听指令: 可能继续补写问题,而不是回答问题
  3. 缺乏安全对齐: 可能生成有害、虚假或偏见内容

例如,GPT-3 在预训练后:

用户: 请将这句话翻译成英文
模型: 可能继续写"以下是一些翻译技巧..."

经过微调后:

用户: 请将这句话翻译成英文
模型: [直接输出英文翻译]

2.2 微调的本质

微调是在预训练基础上的进一步训练,目标是:

  • 任务适配: 学会完成特定任务(翻译、问答、代码生成)
  • 领域定制: 适应特定领域的数据分布和知识
  • 行为对齐: 遵循人类期望的交互方式

可以类比为:

预训练 = 通识教育(学会语言规律和世界知识)
微调 = 专业培训(学会如何完成具体工作)

3.2 全参数微调的资源挑战

以 LLaMA-7B 为例,全参数微调需要:

资源 需求 说明
参数量 70亿 每个参数以FP16存储需2字节
模型存储 ~14GB 仅模型权重
训练显存 ~80GB+ 包括梯度、优化器状态、激活值
GPU要求 A100 80GB 单卡难以训练,需多卡并行

核心瓶颈:

  • 优化器状态: Adam优化器为每个参数维护动量和方差,内存开销达参数量的2倍
  • 梯度存储: 反向传播需存储所有参数的梯度
  • 激活值: 前向传播的中间结果,与序列长度平方成正比

这使得全参数微调在消费级硬件上几乎不可行。

4.3 多LoRA适配器

单个基础模型 + 多个LoRA权重 = 多任务系统:

基础模型(7B)
   ├─ LoRA-翻译(4MB)
   ├─ LoRA-代码(4MB)
   ├─ LoRA-客服(4MB)
   └─ LoRA-医疗(4MB)

切换任务只需替换小文件,无需重新加载整个模型。

六、指令微调:让模型学会听话

6.1 从续写到对话

预训练模型学习的是"文本接龙",不是"任务完成":

预训练目标: P(下一个token | 上文)
指令微调目标: P(任务答案 | 指令+上下文)

6.2 指令数据格式

典型的指令-输入-输出三元组:

{
  "instruction": "将下列文本翻译成英文",
  "input": "人工智能正在改变世界",
  "output": "Artificial intelligence is changing the world"
}

或简化的指令-回答对:

{
  "prompt": "解释什么是强化学习",
  "completion": "强化学习是一种机器学习方法..."
}

6.3 任务多样性的重要性

FLAN研究表明:

在1800+不同任务上微调,比在单一任务上大量训练更能提升泛化能力。

任务覆盖:

  • 问答、翻译、摘要、情感分析
  • 推理、常识、数学、代码
  • 开放对话、角色扮演、创意写作

维度 含义 例子

八、混合精度与分布式训练

8.1 混合精度训练

核心策略:

  • 前向/反向传播: FP16(速度快,显存小)
  • 权重主副本: FP32(精度高,防止累积误差)
  • 损失缩放: 防止梯度下溢

收益:

  • 训练速度提升2x
  • 显存占用减半
  • 精度损失可忽略

8.2 ZeRO优化器

DeepSpeed ZeRO将优化器状态、梯度和参数在多GPU间分片:

阶段 分片内容 内存减少 通信增加
ZeRO-1 优化器状态 4x 无
ZeRO-2 +梯度 8x 很少
ZeRO-3 +模型参数 Nd倍 1.5x

九、实践指南:如何选择微调方案

9.1 决策树

有充足GPU资源(多张A100)?
   ├─ 是 → 全参数微调
   └─ 否 → 是否需要最佳性能?
          ├─ 是 → QLoRA (4-bit + LoRA)
          └─ 否 → LoRA (16-bit)

任务是对话对齐?
   ├─ 是 → DPO / RLHF
   └─ 否 → 监督微调

需要多任务切换?
   ├─ 是 → 多LoRA适配器
   └─ 否 → 单一微调模型

9.2 参数设置建议

LoRA超参数:

参数 推荐值 说明
rank(r) 8-64 小任务8,复杂任务64
alpha 16-128 通常为rank的2倍
dropout 0.05-0.1 防止过拟合
目标模块 q_proj, v_proj 至少包含attention

学习率:

  • 全参数微调: 1e-5 ~ 5e-5
  • LoRA: 1e-4 ~ 3e-4
  • 批次大小: 4-32(根据显存调整)
  • 训练步数: 1000-5000(根据数据量)

9.3 常见问题

过拟合:

  • 症状: 训练损失持续下降,验证损失上升
  • 解决: 增加数据、降低rank、加dropout、早停

灾难性遗忘:

  • 症状: 微调后通用能力下降
  • 解决: 混合通用数据、降低学习率、使用LoRA而非全参数

对齐税:

  • 症状: 对齐后任务性能下降
  • 解决: 先任务微调,再对齐;或用多目标优化

十、最新进展(2024-2025)

10.1 FP8训练

NVIDIA H100的FP8支持:

  • 训练吞吐提升2x
  • 显存降低40%
  • DeepSeek-V3用FP8以560万美元训练671B模型

10.2 GaLore

在梯度空间做低秩投影,而非权重空间:

  • 全参数训练的显存降至1/3
  • 性能接近全参数微调
  • 优于LoRA的表达能力

10.3 自我奖励(Self-Rewarding)

模型自己评判自己的输出:

生成候选回答
    ↓
自己打分排序
    ↓
用偏好对训练(DPO)
    ↓
模型既更会生成,也更会评判

打破了"需要人类标注"的限制,实现持续自我改进。

10.4 MatMul-free LM

完全消除矩阵乘法:

  • 权重三值化(-1, 0, +1)
  • 用加法和移位替代乘法
  • 能耗降至1/50
  • 为终端设备LLM铺路

十一、总结

大模型微调的技术演进可以浓缩为:

全参数微调确立基准
    ↓
LoRA实现参数高效
    ↓
量化进一步降低成本
    ↓
指令微调让模型听话
    ↓
RLHF/DPO实现价值对齐
    ↓
混合精度和分布式优化支撑大规模训练
    ↓
自我改进打开超人类对齐之路

记住五个关键点:

  1. 微调是必需的 —— 预训练模型不会自动完成任务或听从指令
  2. PEFT是主流 —— LoRA让微调从数千GPU的特权变成单卡可行的操作
  3. 量化放大PEFT —— QLoRA在48GB GPU上微调65B模型
  4. 指令微调≠对齐 —— 前者教会任务,后者校准价值观
  5. 效率技术层层叠加 —— FlashAttention + ZeRO + FP8 + LoRA组合使用
