Splitwise: Efficient Generative LLM Inference Using Phase Splitting

Splitwise: Efficient Generative LLM Inference Using Phase Splitting

1. TL;DR / 一句话总结

Splitwise 提出了 Phase Splitting（阶段分离） 这一核心概念，将 LLM 推理的 Prompt Processing（提示处理）和 Token Generation（Token 生成）两个阶段分配到异构的 GPU 上分别优化，通过资源需求分析证明两个阶段最优的 GPU 类型不同，实现了相比共置架构 1.4x 吞吐量 / 20% 成本降低 / 2.5x 能效提升。

2.2 现有方案的问题

Insight 1: 一刀切的 GPU 选型是低效的

Splitwise 的核心发现可以用一个类比来理解：如果两种不同任务（挖矿和渲染）有截然不同的硬件需求，为什么要把它们塞进同一台机器？LLM 推理的 PP 和 TG 阶段正是这样的两种任务。PP 需要计算能力（像挖矿），TG 需要内存带宽（像渲染），用同一种 GPU 服务两者必然导致一半的资源被浪费。

Insight 2: FLOPS/BW 比值是 GPU 选型的关键指标

Splitwise 提出了一个简单但有效的 GPU 选型框架：

  • 高 FLOPS/BW 比 GPU → Prompt Processing (H100: 0.59)
  • 低 FLOPS/BW 比 GPU → Token Generation (A100: 0.15)

这个比值本质上反映了 GPU 的计算密度。PP 阶段操作的是 “大矩阵乘法”（高计算密度），TG 阶段操作的是 “频繁的 KV 缓存流式读取”（低计算密度）。

Insight 3: 阶段分离的收益远大于传输成本

与 Mooncake 类似，Splitwise 验证了将 KV 缓存从 PP 节点传输到 TG 节点的开销（5-100 ms，取决于互连方式）小于异构部署带来的收益。特别是在 NVLink 互联场景下，传输近乎免费。

Insight 4: 能效不仅是一个 “绿色” 问题，也是成本问题

Splitwise 显示异构部署的能效是共置部署的 2.5 倍。在云环境中，功耗直接转化为电力成本和冷却成本，因此能效提升直接转化为经济效益。这使得 Splitwise 不仅在技术上更优，在经济上也有竞争力。

8. 优势与局限 (Strengths & Limitations)

8.1 优势

  1. 硬件适配：将两个阶段匹配到各自最优的 GPU 硬件上，避免资源浪费。
  2. 独立扩缩：PP 池和 TG 池可以独立扩缩容，适应工作负载变化。
  3. 经济性：使用 A100（成本较低）处理 TG 阶段，避免在 TG 上浪费 H100 的昂贵计算能力。
  4. 能效显著：2.5x 能效提升，在数据中心规模下节省大量电力成本。
  5. 延迟隔离：PP 的计算突发不影响 TG 的延迟稳定性。

8.2 局限

  1. KV 缓存传输开销：跨节点传输 KV 缓存引入额外延迟（5-410 ms，取决于互连方式）。
  2. 硬件异构管理：需要维护两种不同类型的 GPU 集群，增加运维复杂度。
  3. GPU 配比固定：静态的 PP:TG 配比可能在负载变化时导致资源浪费。
  4. 小模型不划算：对于 7B 以下的模型，传输开销可能超过解耦收益。
  5. 负载均衡复杂性：需要在两个维度（PP 和 TG 池）同时进行负载均衡，调度器设计更复杂。

9. 下游影响与后续工作 (Impact & Follow-ups)

9.1 学术影响

  • ISCA 2024 发表，推动了 LLM 推理阶段分离研究的范式转变
  • “Phase Splitting” 成为 LLM 推理系统的标准分析框架
  • 启发了多个后续工作（Mooncake、DejaVu、Infinistore）

9.2 工业影响

  • Microsoft Azure 的 LLM 推理服务采用类似阶段分离策略
  • 多家云服务商开始提供异构 GPU 推理实例
  • H100+A100 混合集群成为 LLM 推理的热门配置

9.3 后续演进方向

  • 动态 GPU 配比：根据实时负载动态调整 PP:TG 比例
  • 更细粒度的阶段分离：不仅仅 PP/TG，还可以分离 Attention/FFN
  • 跨数据中心阶段分离：PP 在 GPU 丰富的区域，TG 在用户近的区域
  • 与 speculative decoding 结合：PP 阶段生成 draft tokens，TG 阶段验证
