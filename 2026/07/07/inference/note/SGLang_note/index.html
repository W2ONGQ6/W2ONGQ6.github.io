SGLang: Efficient Execution of Structured Language Model Programs

SGLang: Efficient Execution of Structured Language Model Programs

1. TL;DR / 一句话总结

SGLang 提出了一种将语言模型调用视为第一类编程原语的高效推理框架，通过 RadixAttention（基于前缀树的自动 KV 缓存复用）和 结构化生成语言（在 SPMD 编程空间中实现编译器级优化），在多种 LLM 任务上实现了最高 5 倍的吞吐量提升，同时保持了 Python 程序的灵活可编程性。

2. 研究背景与动机 (Background & Motivation)

2.1 问题现状

大型语言模型（LLM）的工作负载日益复杂，不再局限于简单的单轮对话。现代 LLM 应用呈现出以下特征：

  • 多轮调用模式：一个任务需要多次调用 LLM，如思维链推理（Chain-of-Thought）、树状搜索（Tree-of-Thought）、自洽性采样（Self-Consistency）等
  • 共享前缀结构：多次调用间存在大量共享的前缀文本（System prompt、few-shot examples、conversation history）
  • 结构化输出需求：越来越多的应用需要 LLM 输出符合特定格式（JSON、代码、受控词汇表）

2.2 现有系统的不足

系统类型 代表 主要缺陷
纯推理引擎 vLLM, TensorRT-LLM 缺乏高级编程抽象，难以表达复杂调用模式
高级编程框架 LangChain, Guidance 缺乏系统级优化，KV 缓存管理低效，结构化生成慢
编译器方法 LMQL 牺牲了 Python 的灵活性，调试困难

核心矛盾：现有系统无法同时提供高效的运行时执行和灵活的编程接口。

2.3 设计目标

  1. 易用性：保留 Python 的完全表达能力，无需学习新语言或 DSL
  2. 高性能：系统级优化（KV 缓存复用、批处理、并行化）应自动应用
  3. 灵活性：支持任意复杂的调用模式，包括分支、循环、条件判断

SGLang 由两大核心组件构成：编程语言前端 和 运行时后端。

  • 每个 SGLang 程序维护一个全局字符串流 s

3.2.1 核心数据结构：基数树（Radix Tree）

关键特性：

  • 每个节点存储一个 token 序列对应的 KV 缓存
  • 树结构自然表达前缀共享关系
  • 使用引用计数管理内存：当引用计数归零时，LRU 驱逐节点
  • 叶子节点可能被修剪（当内存压力大时），但非叶子节点保留

3.2.2 工作流程

步骤1: 请求到达与Tokenize — 新请求到达，将完整prompt tokenize为token序列

步骤2: Radix Tree最长前缀查找 — 从根节点开始，沿树路径逐token匹配，找到与当前prompt共享的最长公共前缀节点

步骤3: 缓存命中处理 —

  • 命中：直接复用匹配段的所有KV缓存，跳过Prefill阶段（节省计算量和时间）
  • 未命中段：仅对新增的token序列计算KV缓存

步骤4: 生成阶段动态插入 — 自回归生成的新token的KV缓存动态插入Radix Tree中，作为新的叶子节点或扩展现有节点

步骤5: 引用计数与LRU驱逐 —

  • 请求开始：对应路径上所有节点的refcnt++
  • 请求结束：对应路径上所有节点的refcnt–
  • refcnt==0且为叶子的节点：可被LRU策略驱逐
  • 内存压力大时：优先驱逐访问频率最低的叶子节点

3.2.3 与传统方法的对比

方法 缓存策略 粒度 命中条件 典型命中率（多轮对话）
vLLM (PagedAttention) 完全匹配 请求级 完全相同的 prompt ~12%
LMDeploy 前缀哈希 Token 级 前缀完全一致 ~45%
RadixAttention 前缀树 任意长度前缀 任意公共前缀 ~78%

优势：即使 prompt 不完全相同（如插入新轮对话），也能复用公共前缀的 KV 缓存。

3.2.4 内存管理优化

  • 动态修剪：当 GPU 内存不足时，优先驱逐访问频率最低的叶子节点
  • 写时复制（COW）：多个请求共享同一节点时，分支点采用 COW 策略
  • 碎片整理：定期合并相邻的、同属一个请求链路的节点

3.3 运行时系统

3.3.1 批处理调度策略

SGLang 运行时实现了多种调度策略，以最大化 GPU 利用率：

策略 描述 适用场景
连续批处理（Continuous Batching） 动态添加/移除请求 通用场景
预填充优先（Prefill-First） 优先处理新请求的预填充 延迟敏感
前缀感知调度 将共享前缀的请求分组批处理 前缀重用场景

3.3.2 并行生成优化

当程序中存在 s.parallel() 调用时，运行时执行以下优化：

  1. 请求合并：将并行分支作为独立请求提交
  2. 共享前缀传播：Radix Tree 确保所有分支共享前缀的 KV 缓存
  3. 结果收集：所有分支完成后，在 Python 层聚合结果

3.3.3 与现有推理引擎的集成

SGLang 可以与多种推理引擎后端集成：

  • SGLang Native：自研运行时（最高性能）
  • vLLM 后端：利用 vLLM 的 PagedAttention
  • HuggingFace 后端：兼容任意 HuggingFace 模型（最广泛兼容）
  • OpenAI API 后端：兼容 OpenAI 兼容的 API 服务

5. 关键技术洞察 (Key Insights)

Insight 1: 前缀是 LLM 程序中最高效的复用单元

SGLang 的关键发现在于：在复杂的 LLM 调用模式中，共享前缀（而非完全相同的请求）是最常见的复用模式。RadixAttention 的设计正是基于这一洞察 —— 通过基数树精确匹配任意长度的公共前缀，最大化 KV 缓存的复用率。

Insight 2: 嵌入式 DSL 比独立 DSL 更适合生产环境

与 LMQL 等独立编译器方法不同，SGLang 选择在 Python 中嵌入其语言。这带来了三个关键优势：

  1. 开发者无需学习新语言
  2. 可以与任意 Python 库无缝集成
  3. 调试工具（断点、print、IDE 支持）完全可用

Insight 3: 编译器和运行时的边界应精心设计

SGLang 将编译优化（结构化约束、并行计划）推入运行时，而非在编译阶段固定所有决策。这使得系统可以在运行时根据实际的 KV 缓存状态、GPU 内存使用情况和负载动态调整策略。

Insight 4: 结构化生成应编译为有限状态机（FSM）

SGLang 将正则表达式、JSON Schema 和选择约束统一编译为 FSM，在 token 级别约束生成。相比 Guidance 的回溯法（token rejection sampling），FSM 方法避免了浪费的 token 生成和丢弃。

8. 优势与局限 (Strengths & Limitations)

8.1 优势 (Strengths)

  1. 卓越的前缀复用效率：RadixAttention 在长前缀共享场景下可减少 80% 以上的冗余计算。
  2. 即插即用的 Python 体验：开发者无需修改现有 Python 工作流，SGLang 装饰器自动注入优化。
  3. 结构化生成零浪费：FSM 编译确保每个生成的 token 都是有效输出。
  4. 后端无关性：支持多种推理引擎后端，从本地 HuggingFace 到远程 OpenAI API。
  5. 开箱即用的并行性：s.parallel() 自动将分支映射为并行请求，无需手动管理线程或异步。

8.2 局限 (Limitations)

  1. Radix Tree 内存开销：基数树本身需要额外的内存来维护节点结构（约 5-8% 的 KV 缓存大小）。
  2. 冷启动惩罚：第一次执行新前缀任务时，没有优势，甚至因 Radix Tree 查找而略微变慢。
  3. 分布式场景：当前 RadixAttention 主要针对单机多 GPU 设计，跨节点的 KV 缓存共享仍是开放问题。
  4. FSM 编译开销：对于极长的正则表达式或深层嵌套的 JSON Schema，FSM 编译本身可能耗时。
  5. 学习曲线：虽然保留了 Python 语法，但 SGLang 原语（gen, select, s +=）的使用模式仍需学习。

9. 下游影响与后续工作 (Impact & Follow-ups)

9.1 学术影响

  • RadixAttention 被 vLLM 后续版本部分采纳（vLLM v0.3.0+ 引入了 prefix caching 机制）
  • 结构化生成语言的设计理念影响了多个后续框架（Outlines v0.1+, Guidance v0.2+）
  • 论文在 MLSys 社区引发了关于 “LLM 编程原语” 的广泛讨论

9.2 工业应用

  • 多个 LLM 服务商（包括 LMSYS 的 Chatbot Arena）采用 SGLang 作为底层推理引擎
  • 企业级 RAG 系统利用 SGLang 的 KV 缓存复用优化大批量文档问答
  • 代码生成工具利用结构化约束确保语法正确的输出

9.3 后续工作

  • SGLang v2：引入了 Speculative Decoding 和 Multi-LoRA 支持
  • SGLang-Router：智能路由层，将请求分发到最优的模型和后端
  • SGLang-Stream：针对流式场景的优化，降低首 token 延迟
  • 跨节点 KV 缓存：基于 RDMA 的分布式 RadixAttention（与 Mooncake 理念相关）
