Mooncake: A KVCache-Centric Disaggregated Architecture for LLM Serving

1. TL;DR / 一句话总结

Mooncake 提出了一种以 KV 缓存为中心的解耦架构，将 LLM 推理的 Prefill（预填充）和 Decode（解码）阶段分配到不同的 GPU 集群上执行，通过高速 RDMA 网络传输 KV 缓存，在保持低延迟的同时实现了近乎线性的吞吐扩展，解决了传统共置架构中 Prefill 干扰 Decode 延迟的根本矛盾。

2. 研究背景与动机 (Background & Motivation)

2.1 共置架构的根本问题

传统的 LLM 推理系统（vLLM、TensorRT-LLM）采用共置（Colocated）架构：

这存在根本性的性能矛盾：

问题 详情
Prefill 干扰 Decode Prefill（计算密集）占用 GPU 时，Decode 请求被迫等待
资源争抢 内存带宽、SM 计算单元、KV 缓存空间的竞争
尾延迟恶化 长 Prefill 请求导致 Decode 延迟不可预测
扩展性受限 无法为 Prefill 和 Decode 独立分配最优资源

5. 关键技术洞察 (Key Insights)

建议位置：实验与关键发现/技术洞察
放置原因：展示各优化技术对性能的贡献度或关键设计空间的分析探索

Insight 1: KV 缓存是 LLM 推理中的 “一等公民”

Mooncake 将 KV 缓存提升为架构设计的中心概念。传统系统中 KV 缓存仅是 GPU 显存中的临时数据结构，而 Mooncake 将 KV 缓存视为需要在集群中传输、缓存、冗余的关键资源。这种思维转变类似于从单体应用缓存到 Redis 集群的演进。

Insight 2: Prefill 和 Decode 的解耦释放了异构硬件的潜力

共置架构强制 Prefill 和 Decode 共用相同的 GPU，导致”平均值”的硬件选择。解耦后，可以：

  • Prefill 使用 H100（高 FLOPS，FP8 Tensor Core）
  • Decode 使用 A100（大显存，成熟生态）
  • 甚至使用 L40S（成本优化）或 GH200（超大规模）

这种异构部署在共置架构中是不可能实现的。

Insight 3: RDMA 延迟可以接受且值得付出

Mooncake 的一个关键发现是：KV 缓存的 RDMA 传输延迟（35-55 ms）在总 TTFT（300-400 ms）中占比可控（约 10-15%）。用 10-15% 的延迟增加换取 2-3x 的吞吐量提升和解耦架构的灵活性，是非常值得的权衡。

Insight 4: 流水线传输几乎消除了传输开销

通过将 Prefill 计算和 KV 缓存传输流水线化，Mooncake 实现了计算与通信的重叠。这使得传输延迟几乎完全隐藏在计算延迟中，实际的端到端延迟增加远小于传输延迟本身。

8. 优势与局限 (Strengths & Limitations)

8.1 优势

  1. 近线性扩展：Prefill 和 Decode 可独立水平扩展，吞吐量随节点数近线性增长。
  2. 消除 Prefill 干扰：Decode 延迟几乎不受 Prefill 请求影响，P99 延迟稳定。
  3. 异构硬件利用：可为不同阶段选择最优 GPU 型号，成本效益更好。
  4. 资源共享：KV 缓存可在多个 Decode 请求间共享（前缀缓存），比共置架构更高效。
  5. 弹性伸缩：可根据负载独立扩缩 Prefill 或 Decode 节点。

8.2 局限

  1. 网络依赖：需要高速网络（InfiniBand/RoCE），在以太网环境下性能大幅下降。
  2. 额外延迟：RDMA 传输增加了 35-165 ms 的延迟（取决于序列长度）。
  3. 复杂性增加：需要管理两个独立的集群和全局调度器，运维复杂度提升。
  4. 长序列退化：当序列超过 16K 时，KV 缓存传输延迟可能成为瓶颈。
  5. 故障域扩大：解耦架构引入了网络和节点间故障点，需要更复杂的容错机制。
  6. KV 缓存压缩的精度损失：使用 INT8 压缩 KV 缓存可能导致轻微的精度下降。

9. 下游影响与后续工作 (Impact & Follow-ups)

9.1 学术影响

  • 解耦架构成为 LLM 推理系统设计的重要范式
  • 引发了关于 KV 缓存传输协议、压缩策略的研究方向
  • 多个后续工作（Splitwise, DejaVu, Infinistore）受其启发

9.2 工业影响

  • Mooncake 的设计理念被 Moonshot AI (Kimi) 用于其大规模 LLM 服务
  • 多家云服务商开始探索 Prefill/Decode 分离部署
  • 推动了 RDMA 在 AI 推理基础设施中的应用

9.3 后续工作

  • 自适应 KV 压缩：根据网络带宽和延迟要求动态选择压缩率
  • 多级缓存层级：GPU 显存 → CPU 内存 → NVMe SSD → 分布式 KV 存储
  • 跨区域解耦：地理分布式的 Prefill/Decode 部署
  • KV 缓存智能预热：基于请求预测的主动缓存策略
