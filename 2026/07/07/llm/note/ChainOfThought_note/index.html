Chain-of-Thought Prompting Elicits Reasoning in Large Language Models

Chain-of-Thought Prompting Elicits Reasoning in Large Language Models

1. TL;DR / 一句话总结

Chain-of-Thought (CoT, 思维链) 提示是一种简单而强大的技术：在 few-shot 示例中展示中间推理步骤而非仅给出最终答案，即可显著提升大语言模型在算术推理、常识推理和符号推理上的表现。在 PaLM 540B 上，CoT 将 GSM8K 数学问题的准确率从 33% 提升至 57%，超越当时的微调 SOTA。这一技术揭示了 LLM 不仅能够 “给出答案”，更具备 “展示推理过程” 的涌现能力。

2. 研究背景与动机 (Background & Motivation)

2.1 LLM 推理的困境

在 2021-2022 年间，大语言模型（GPT-3, PaLM 等）展现出令人瞩目的语言生成能力，但在数学推理和复杂逻辑问题上表现惨淡：

任务 标准 Few-Shot Prompting 人类水平
GSM8K (小学数学) ~33% ~85%
SVAMP (数学应用题) ~40% ~85%
AQuA (代数) ~30% ~75%
StrategyQA (隐式推理) ~60% ~87%

问题根源：标准的 few-shot prompting 要求模型直接预测最终答案，但多步推理天然需要中间步骤。模型被迫在 “黑箱” 中完成推理，容易产生幻算（arithmetic hallucination）。

2.2 核心洞察

既然人类解决复杂数学问题时会写下中间步骤（草稿纸上的计算过程），为什么不让模型也这样做？

2.3 关键假设

  1. LLM 具备推理能力，但需要正确的 “提示格式” 来激活它
  2. 展示中间推理步骤可以引导模型进行类似的多步推理
  3. 推理的 “工作记忆” 可以通过自然语言的外部化来扩展
  4. 这种能力是规模涌现的 – 仅在足够大的模型上有效

3.1 Chain-of-Thought Prompting 的定义

Chain-of-Thought prompting 是一种特殊的 few-shot prompting 技术，其唯一区别在于 few-shot 示例中包含了从问题到答案的详细推理步骤。

3.5 CoT Prompting 执行流程（逐步骤详述）

步骤 1: 任务识别与示例准备

  • 输入：目标任务类型（算术/常识/符号推理）和具体问题 x
  • 操作：
    1. 分析目标问题的类型和难度级别
    2. 从示例库中选择 3-8 个 CoT 示例（手工编写，覆盖不同推理模式）
    3. 确保示例的多样性：加法/减法/乘法/除法各至少一个（对于算术推理）
    4. 验证每个示例的推理链正确无误
  • 输出：CoT 示例集合 {(q_i, r_i, a_i)}_{i=1}^k

步骤 2: Prompt 构造

  • 输入：CoT 示例 + 目标问题 x
  • 操作：
    1. 按照统一格式排列："Q: " + q_1 + "\nA: " + r_1 + " 答案是 " + a_1
    2. 示例之间用双换行符分隔（\n\n）
    3. 将目标问题放置在最后："Q: " + x + "\nA:"
    4. 不添加额外指令——模型从示例格式中自动学习
  • 输出：完整的 CoT prompt P_CoT

步骤 3: 模型生成

  • 输入：CoT prompt P_CoT
  • 操作：
    1. 将 prompt 送入 LLM，设置 temperature（0 为 greedy，>0 为抽样用于 Self-Consistency）
    2. 模型自回归生成：先输出推理链 r，再输出 “答案是 a”
    3. 生成自然终止于 EOS token 或遇到格式标记
  • 输出：模型原始输出（推理链 + 答案）

步骤 4: 答案提取与验证

  • 输入：模型原始输出
  • 操作：
    1. 方法一（正则匹配）：搜索 “答案是 X” 或 “the answer is X” 模式
    2. 方法二（数值提取）：从输出末尾提取最后一个数值（数学题）
    3. 方法三（多选匹配）：匹配选项字母 A/B/C/D（选择题）
    4. 对比提取结果与标准答案
  • 输出：最终预测答案 pred 和正确性判定

步骤 5: Self-Consistency 聚合（可选）

  • 输入：目标问题 + m 条独立采样的推理链（temperature > 0）
  • 操作：
    1. 对同一问题执行 m 次独立生成（通常 m=40）
    2. 从每条输出中提取最终答案：{a_1, a_2, ..., a_m}
    3. 执行多数投票：pred = argmax_a count(a)
    4. 聚合后准确率显著提升（GSM8K: 57% -> 74.4%）
  • 输出：多数投票后的最终答案 pred_SC

5. 关键技术洞察 (Key Insights)

Insight 1: 推理是一种可以通过 “演示” 激活的涌现能力

CoT 最核心的洞察是：LLM 的推理能力不是通过训练获得的（模型未经过数学推理训练），而是通过适当的提示格式 “解锁” 的。在小模型上，无论怎么提示都没用；但在足够大的模型上，仅仅改变 few-shot 示例的格式就能带来 +20-40% 的准确率提升。这种 “涌现” 特性挑战了 Scaling Laws 中平滑幂律的预期。

Insight 2: 自然语言是 LLM 的 “草稿纸”

人类解决复杂问题时会使用外部草稿纸来扩展工作记忆。LLM 没有真正的工作记忆（KV 缓存虽然存储了历史，但无法显式地进行多步符号操作），CoT 通过自然语言生成中间步骤，本质上是将 KV 缓存用作 “草稿纸”。这是对人类认知策略的直接类比。

Insight 3: CoT 揭示了推理透明度

Standard Prompting 让模型在 “黑箱” 中给出答案。CoT 迫使模型将推理过程 “口语化”，这使得：

  • 推理过程可审查（调试模型错误变得可能）
  • 错误模式可分析（模型在哪种推理步骤上容易出错？）
  • 信任度可建立（用户可以看到 “为什么”）

Insight 4: CoT 的效果与任务类型密切相关

CoT 在三种任务类型上效果特别好：

  1. 算术推理: 需要多步数值计算
  2. 常识推理: 需要调用背景知识进行推理
  3. 符号推理: 需要执行规则化的符号操作

而在简单的知识问答或翻译任务上，CoT 无明显帮助甚至有害。这提供了选择何时使用 CoT 的实用指导。

CoT 之所以能实现推理透明度，底层的 KV 缓存机制是关键：

机制层 作用 CoT 中的具体表现
自注意力 KV 缓存 存储每个 token 的 Key-Value 对 推理链的每个中间步骤都被编码入缓存

8. 优势与局限 (Strengths & Limitations)

8.1 优势

  1. 即插即用：无需重新训练或微调模型，仅改变 prompt 格式。
  2. 显著效果：在多个推理任务上带来 10-40% 的绝对提升。
  3. 可解释性：模型 “展示工作”，推理过程可审查和调试。
  4. 通用性：在算术、常识、符号推理三大类任务上都有效。
  5. 与模型无关：同一组 CoT 示例可用于 GPT-3、PaLM、LaMDA 等多个模型。

8.2 局限

  1. 规模门槛：仅在大模型（>100B 参数）上有效，无法在较小模型上使用。
  2. 示例依赖：CoT 示例的质量和多样性对效果有显著影响，需要人工精心设计。
  3. 生成成本：推理链增加了输出 token 数量（通常 3-5x），增加推理成本。
  4. 幻觉推理：模型可能生成看似合理但逻辑错误的推理链。
  5. 非通用：在简单知识问答、翻译、摘要等任务上无用甚至有害。
  6. 缺乏真正确保正确：CoT 提高了推理可能性，但不保证推理正确。

ReAct Reasoning + Acting 结合 CoT + 工具使用 事实性提升 (FEVER: 60.9 vs 36.7)
Auto-CoT 自动生成 CoT 示例 消除人工设计需求 接近手工 CoT 性能

9.2 行业采用

  • ChatGPT/GPT-4 内部使用类似 CoT 的机制来提升推理质量
  • Anthropic 的 Claude 利用 CoT 展示推理过程
  • 几乎所有 LLM 产品都在内部使用某种形式的 CoT

  • CoT 的理论理解 为什么 CoT 有效？与模型内部机制的关系？
  • 更高效的 CoT 减少推理链的 token 浪费，生成更简洁的推理
