LLM专题-08：智能体 —— 如何让 LLM 使用工具、完成任务？

智能体 (LLM Agents)

LLM Agent 是当代大语言模型研究最活跃的前沿方向之一。它将 LLM 从被动的”文本生成器”升级为主动的”行动者”——能够推理、规划、调用工具、记忆和反思，从而在复杂的真实世界场景中自主完成多步骤任务。本章选取了七个里程碑式的工作，勾勒出 LLM Agent 从概念诞生到实用系统的完整演进图景。

ReAct: Synergizing Reasoning and Acting in Language Models

📝 论文深度笔记

  • arXiv: 2210.03629
  • 发表: ICLR 2023
  • 作者: Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao (Princeton University / Google Research)
  • 简介: ReAct 首次将推理（Reasoning）和行动（Acting）统一到同一个提示范式之中，让 LLM 在解决问题时交替产生推理轨迹和外部行动，开创了工具使用型智能体的基础范式。
  • 核心创新:
    • 设计了”思维-行动-观察”（Thought-Action-Observation）的交替循环范式：模型首先生成推理过程（Thought）来决定接下来该做什么，然后生成具体的行动指令（Action），最后观察行动的执行结果（Observation）并继续下一轮推理——这一循环成为了几乎所有后续 LLM Agent 框架的核心骨架
    • 将推理轨迹（chain-of-thought）与外部行动（如搜索维基百科、执行计算）紧密结合，推理帮助模型决定何时需要外部信息，行动为推理提供事实依据，两者互为补充、相互强化，有效缓解了纯推理中的幻觉和错误传播问题
    • 在知识密集型推理（HotpotQA）、事实验证（FEVER）以及交互式决策任务（ALFWorld、WebShop）上均取得了显著超越纯推理或纯行动方法的结果——在 ALFWorld 上以 34% 的绝对优势超越了模仿学习和强化学习方法
    • 通过广泛的消融实验证明了交替推理与行动的必要性：仅有推理时模型容易产生幻觉，仅有行动时模型容易迷失目标，两者结合才能实现最优的协同效果
  • 代表意义: ReAct 是 LLM Agent 方向的奠基性工作。在它之前，Chain-of-Thought 已有推理范式，但模型只能”想”不能”做”；API 调用也有雏形，但缺乏推理来指导何时调用。ReAct 的贡献在于将”想”和”做”编织成一个有机的循环系统，证明了 LLM 可以通过这种交替交互来与真实世界信息源对接，从而在需要事实依据和交互决策的任务上大幅提升可靠性。这一范式直接影响了 LangChain、AutoGPT 等几乎所有后续 Agent 框架的核心架构设计。ReAct 的论文和代码已成为该领域引用量最高的基础文献之一。

Toolformer: Language Models Can Teach Themselves to Use Tools

📝 论文深度笔记

  • arXiv: 2302.04761
  • 发表: NeurIPS 2023
  • 作者: Timo Schick, Jane Dwivedi-Yu, Roberto Dessi, Roberta Raileanu, Maria Lomeli, Luke Zettlemoyer, Nicola Cancedda, Thomas Scialom (Meta AI Research / Universitat Pompeu Fabra)
  • 简介: Toolformer 提出了一种自监督方法让 LLM 自主学会何时以及如何调用外部 API（计算器、搜索引擎、翻译系统等），无需人工标注即可赋予模型工具使用能力，实现了工具调用与语言建模的无缝融合。
  • 核心创新:
    • 设计了一个精巧的自监督学习流水线：模型首先通过少样本提示在原始文本中生成潜在的 API 调用候选位置，然后实际执行这些 API 调用获取结果，最后通过判断 API 返回结果是否有助于减少后续 token 的预测损失来筛选出真正有用的调用——整个过程中模型”自己教会自己”
    • 将 API 调用以特殊的 token 标记嵌入到标准语言建模框架中，模型在遇到需要事实信息、计算结果、翻译需求或时间信息时，自动在文本流中插入 API 调用，而无需外部控制系统或调用策略网络
    • 仅使用一个 6.7B 参数的 GPT-J 作为基座模型，通过自我训练后获得了大幅提升的零样本性能，在许多任务上甚至与当时大 25 倍的 GPT-3 (175B) 表现相当，展现了工具增强的巨大成本效益
    • 框架天然支持多工具集成：计算器、问答系统、维基百科搜索引擎、翻译系统、日历查询——五种不同类型的工具被无缝整合到同一个模型中，模型学会了根据上下文自动选择合适的工具
  • 代表意义: Toolformer 的意义在于证明了工具使用能力不需要人工精心编写调用策略，模型可以通过自监督的方式内化”何时查、查什么、怎么用”的完整决策链。这一工作的”自力更生”设计哲学——用模型自己判断 API 调用是否有用——极具启发性。它避免了昂贵的人工标注，使工具学习具有高度可扩展性。Toolformer 也是首个将工具调用直接融入自回归语言建模流程的工作，为后续 ChatGPT 插件系统、Function Calling API 等产品化工具使用能力提供了理论基础。Meta AI 通过这一工作展示了一个被低估的事实：即使是中等规模的模型，只要掌握了”借助外部工具”的能力，也能匹敌甚至超越裸奔的大模型。

Voyager: An Open-Ended Embodied Agent with Large Language Models

📝 论文深度笔记

  • arXiv: 2305.16291
  • 发表: NeurIPS 2023
  • 作者: Guanzhi Wang, Yuqi Xie, Yunfan Jiang, Ajay Mandlekar, Chaowei Xiao, Yuke Zhu, Linxi (Jim) Fan, Anima Anandkumar (NVIDIA / MIT / Stanford)
  • 简介: Voyager 是首个基于 LLM 的开放式具身终身学习智能体，在 Minecraft 中自主探索世界、发现技能并持续进步，无需任何人类干预或模型微调，仅通过提示和上下文学习就能不断进化。
  • 核心创新:
    • 设计了”自动课程”（Automatic Curriculum）机制——由 GPT-4 根据智能体当前的技能水平和探索进展，自动提出越来越难的下一目标任务，实现了一种基于语言模型的”新颖性搜索”（novelty search），驱动智能体不断向未探索的领域推进
    • 构建了”持续增长的技能库”（Ever-Growing Skill Library）——智能体将每次成功完成的任务代码存储为可复用技能，以嵌入向量索引存储。当遇到新任务时，系统从技能库中检索最相关的已有技能作为参考，实现了复杂行为的增量组合和灾难性遗忘的有效缓解
    • 提出了”迭代式提示机制”（Iterative Prompting Mechanism）——智能体生成的可执行 Minecraft 控制代码会经过环境反馈、执行错误和自我验证的多轮迭代完善，确保最终输出的代码能够正确完成目标任务
    • 在 Minecraft 这个无限开放的世界中取得了显著超越所有此前方法的探索和学习效率：收集的独特物品数量提升 3.3 倍、探索距离延长 2.3 倍、解锁科技树里程碑的速度快 15.3 倍
  • 代表意义: Voyager 是 LLM 在开放式具身环境中的里程碑之作。它根本上挑战了”强化学习是智能体在开放世界中学习的唯一途径”这一传统认知，证明了 LLM 通过巧妙的提示工程和记忆管理，同样可以实现持续的技能获取和自主探索。其”技能库”概念启发了大量后续工作——将代码作为一种可存储、可检索、可组合的”技能胶囊”，使 LLM Agent 的能力不是一次性消耗而是持续积累。NVIDIA 的这项研究也确立了一个新的评测范式：用 Minecraft 这个足够复杂但又有清晰量化指标的环境来测试 Agent 的长期学习和自主探索能力。

Generative Agents: Interactive Simulacra of Human Behavior

📝 论文深度笔记

  • arXiv: 2304.03442
  • 发表: UIST 2023
  • 作者: Joon Sung Park, Joseph C. O’Brien, Carrie J. Cai, Meredith Ringel Morris, Percy Liang, Michael S. Bernstein (Stanford University / Google Research / Google DeepMind)
  • 简介: “Stanford Smallville”实验将 25 个 LLM 驱动的生成式智能体放置于一个模拟小镇中，赋予每个智能体记忆流、反思和规划能力，观察到大量涌现的社会行为——自发传播消息、组织派对、建立人际关系，开创了 LLM 用于社会模拟和人机交互研究的新范式。
  • 核心创新:
    • 设计了三大核心组件的智能体架构：记忆流（Memory Stream）以自然语言形式全面记录智能体的所有经历；反思（Reflection）定期将底层记忆抽象为高层次的自我认知和对他人的看法；规划（Planning）自顶向下地递归制定和执行日常计划。三个组件共同作用，使智能体的行为展现出令人惊叹的连贯性和可信度
    • 仅以一个种子提示（”Isabella 想办一场情人节派对”）为起点，25 个智能体在两天时间内自发产生了复杂的社交涌现行为：派对邀请在社交网络中扩散、新的人际关系形成、智能体互相邀请约会、12 人收到了派对邀请，最终 5 个智能体准时出现在派对上
    • 通过严格的消融实验证明记忆、反思和规划三个组件各自独立且至关重要地贡献于智能体行为的可信度——缺少任何一个组件都会导致行为质量显著下降
    • 将 LLM 从工具角色转移到”被研究者”角色——该工作不仅展示了技术能力，更开创性地提出了将 LLM Agent 作为人类行为的交互式仿真模型用于社会科学研究和原型设计的思路
  • 代表意义: “Stanford Smallville” 是 2023 年最具传播力和影响力的 AI 论文之一，它不仅是技术突破，更是一次文化现象。它从根本上扩展了人们对 LLM 能做什么的想象力——LLM 不仅可以用做问答和写作，还可以变成一个个有记忆、会反思、能做计划的”数字人”。这项工作对游戏 NPC 设计、社会模拟工具、人机交互研究等领域产生了深远影响。更重要的是，它揭示了 LLM 的一种全新使用方式：不只是”与一个模型对话”，而是”创建一个由多个模型组成的社会”，观察它们的互动涌现出怎样的行为模式。这种从”单体智能”到”社会智能”的范式跃迁，被广泛认为是通往 AGI 的重要路径之一。

SWE-agent: Agent-Computer Interfaces Enable Automated Software Engineering

📝 论文深度笔记

  • arXiv: 2405.15793
  • 发表: NeurIPS 2024
  • 作者: John Yang, Carlos E. Jimenez, Alexander Wettig, Kilian Lieret, Shunyu Yao, Karthik Narasimhan, Ofir Press (Princeton University)
  • 简介: SWE-agent 的核心洞察是将 LLM 视为一种新型的用户类别，专门为其设计了高效的”智能体-计算机接口”（ACI），使 LM 能够像人类开发者使用 IDE 一样自主浏览代码库、编辑文件并修复真实世界的软件缺陷。
  • 核心创新:
    • 提出了”智能体-计算机接口”（Agent-Computer Interface, ACI）的概念——为 LLM Agent 量身定制的命令行界面，包含精心设计的 LM 友好型命令（如查看、搜索、编辑文件）和结构化的反馈格式，显著降低了 LLM 与代码库交互的认知负担
    • 设计了一系列符合开发者直觉但针对 LLM 优化的交互原语——包括文件内容查看（支持行号标记）、代码搜索、文件编辑（通过搜索替换或行范围指定）、测试执行和 lint 检查，使 Agent 能像经验丰富的工程师一样高效地定位和修复问题
    • 在 SWE-bench（真实 GitHub issue 自动修复）评测中取得了发表时的最佳成绩，12.5% 的完整测试集 Pass@1 解决率远超此前任何非交互式方法（此前的 SoTA 仅为 1.96%），在 HumanEvalFix 上达到 87.7%
    • 系统地分析了接口设计对 Agent 行为的影响，发现命令的粒度、反馈的格式和信息的丰富程度直接决定了 Agent 的任务成功率——这一发现为后续所有代码 Agent 的接口设计提供了重要指导
  • 代表意义: SWE-agent 的贡献不止于一个高分的代码修复工具，更在于提出了一个根本性的问题：当 LLM 成为”计算机使用者”时，我们应该如何重新设计计算机接口？传统的命令行和桌面界面是为人类的认知模式设计的，但 LLM 作为用户有着完全不同的能力剖面——擅长解析长文本但容易在过于复杂的界面中迷失，需要结构化的反馈但又不适合处理过于细粒度的视觉信息。SWE-agent 的 ACI 概念为这个问题提供了一个优雅的答案范式，深刻影响了其后如 OpenHands、Devin 等各类代码 Agent 系统的设计。它让社区意识到，构建优秀的 AI 编码助手不仅是提升 LLM 能力的问题，也是人机交互设计的问题。

AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation

📝 论文深度笔记

  • arXiv: 2308.08155
  • 发表: 2023（持续更新的开源社区项目）
  • 作者: Qingyun Wu, Gagan Bansal, Jieyu Zhang, Yiran Wu, Shaokun Zhang, Erkang Zhu, Beibin Li, Li Jiang, Xiaoyun Zhang, Chi Wang (Microsoft Research / Penn State University / University of Washington)
  • 简介: AutoGen 是当前最流行的多智能体对话框架，通过”可对话智能体”（conversable agent）的抽象，让开发者用简洁的代码构建多个 LLM Agent 互相对话协作求解复杂任务的系统，支持人工介入循环。
  • 核心创新:
    • 提出了”可对话智能体”（Conversable Agent）的核心抽象——每个 Agent 可以是一个 LLM、一个工具、一个人类用户、或它们的任意组合，Agent 之间通过标准化的消息传递协议进行对话，使得构建多智能体系统如同让多个角色”开会讨论”一样直观
    • 设计了灵活的人类介入循环（Human-in-the-loop）机制——人类用户可以被自然地作为对话参与者之一，在关键决策点介入提供反馈或修正，同时系统在不需要人类参与时自动推进，很好地平衡了自动化和人工监督
    • 提供了多种开箱即用的对话模式：两个 Agent 之间的辩论式讨论、多 Agent 的顺序协作、分层群聊、嵌套对话等，开发者无需理解复杂的多智能体调度逻辑即可构建多样化的协作模式
    • 在数学问题求解、代码生成、数据分析和问答系统等多样化场景上进行了充分验证，证明了多智能体对话模式在提高答案质量和可解释性方面优于单次 LLM 调用
  • 代表意义: AutoGen 的意义在于将多智能体系统从学术论文中的概念变成可工程化的基础设施。在它之前，构建一个多 LLM 协作系统需要对每个 Agent 的角色、交互协议和信息流进行复杂的定制开发。AutoGen 通过优雅的抽象和丰富的预设对话模式，极大地降低了多智能体应用的开发门槛。它的开源和 Microsoft Research 的背书使其迅速获得了庞大的开发者社区，成为了多智能体框架的事实标准之一。AutoGen 也代表了 LLM 应用的一种重要设计哲学转变——不是让一个超级模型包办一切，而是让多个各有所长的 Agent 通过对话来协作求解，这种”分工协作”的模式往往比单体更具鲁棒性和可解释性。

SWE-bench: Can Language Models Resolve Real-World GitHub Issues?

📝 论文深度笔记

  • arXiv: 2310.06770
  • 发表: ICLR 2024
  • 作者: Carlos E. Jimenez, John Yang, Alexander Wettig, Shunyu Yao, Kexin Pei, Ofir Press, Karthik Narasimhan (Princeton University)
  • 简介: SWE-bench 是首个使用真实 GitHub issue 和对应 Pull Request 构建的代码修复评测基准，包含 2294 个任务分布于 12 个知名 Python 项目中，要求模型像人类软件工程师一样理解问题、定位代码、编写修复并确保测试通过。
  • 核心创新:
    • 构建了完全来自真实开源项目历史的评测数据集——从 GitHub 上采集真实的 issue 描述和对应的合并后 Pull Request 修复作为 ground truth，确保每个任务都是真正在实际开发中出现的、有实际修复价值的软件工程问题
    • 设计了完整的端到端评测流水线：从环境中安装正确的包依赖，到在 Docker 容器中应用模型的代码补丁，再到运行原始的测试套件验证修复是否正确，确保评测结果反映的不是”看起来对”而是”测试通过”的真修复
    • 覆盖了 12 个广泛使用的 Python 开源项目（如 Django、Flask、SymPy、scikit-learn、matplotlib 等），问题类型涵盖 bug 修复、功能添加、性能优化、文档更新等，使评测具有高度的生态代表性和实际意义
    • 在发布时揭示了 LLM 与人类软件工程师之间的巨大鸿沟——Claude 2 仅能解决 1.96% 的问题，GPT-3.5 仅 0.17%，即使是给模型提供了正确文件的线索也只有 4.8% 的解决率
  • 代表意义: SWE-bench 是衡量 AI 编码能力从”写函数片段”走向”改真实项目”的关键里程碑。在它之前，HumanEval 和 MBPP 等基准只要求模型在几行代码的尺度上生成正确的函数体。SWE-bench 则直接挑战了”AI 能否替代初级软件工程师”这个终极问题，要求模型展示跨越数十个文件的代码理解力、问题定位力和多文件协调修改力。它迅速成为整个 AI 编码领域的”高考”——Devin（Cognition, 13.86%）、SWE-agent（Princeton, 12.5%）、OpenHands 等知名代码 Agent 都以 SWE-bench 上的成绩作为核心能力证明。随着技术的飞速进步，SWE-bench Verified 上的最佳成绩到 2024 年底已超过 70%，生动地记录了 AI 编码能力的指数级增长。

Claude Computer Use: The First Frontier GUI Agent

  • arXiv: 2410.18410 (Anthropic model card)
  • 发表: 2024 年 10 月，Anthropic
  • 作者: Anthropic（Claude Computer Use Team）
  • 简介: Anthropic 推出的 Claude Computer Use 是第一个由顶级 AI 公司发布的”计算机操控 Agent”——让 Claude 像人类一样看屏幕截图、移动鼠标、点击按钮、键入文字，通过视觉理解和动作执行完成跨应用的复杂任务，标志着 LLM Agent 正式进入图形化界面操作系统时代。
  • 核心创新:
    • 视觉驱动的 GUI 操控范式：不同于传统的基于 API 调用或代码执行的 Agent，Claude Computer Use 将人机交互简化为两个原语——“看”（接收当前屏幕截图）和”动”（输出鼠标点击坐标、键盘输入和滚动指令）。这种范式使 Agent 可以操控任何软件而无需专门的 API 集成——只要能显示在屏幕上的应用（网页浏览器、Excel、Photoshop、甚至命令行终端），Claude 都能操作。这是 Agent 通用性的极致体现。
    • 屏幕截图 + 空间推理的双重能力：Claude Computer Use 在训练中学习了对屏幕截图的细粒度理解——包括 UI 元素识别（按钮、输入框、菜单）、空间位置推理（这个按钮在屏幕的哪个位置）、和操作序列规划（先点这里、再打那个、然后往下滚动）。在 OSWorld 基准（跨应用 GUI 任务评测）上，Claude Computer Use 取得了当时最佳的成绩（14.9% success rate），超越所有之前的 GUI Agent。
    • 安全边界的系统化设计：作为首个面向公众发布的”Computer Use”功能，Anthropic 为其设计了多层安全机制——（a）受限的操作空间（仅允许特定类型的点击和输入，禁止执行危险操作）；（b）人机协同验证（关键操作需要人类确认）；（c）工具输出的引用追踪（每次工具调用都标注来源，便于审计）；（d）逐步发布策略（从 API 仅限指定合作伙伴开始逐步放开）。
  • 代表意义: Claude Computer Use 是 LLM Agent 从”文本/API 交互”走向”图形界面交互”的破冰之作。它使 Agent 的通用性达到了一个新高度——不再受限于是否有配套的 API，只要能”看屏幕 + 点鼠标”，任何软件都可以被操控。这一范式直接启发了 2025 年的 OpenAI Operator 等竞品，也推动了 OSWorld、AndroidWorld 等 GUI Agent 评测基准的发展。对于企业自动化场景，Computer Use 提供了一种比传统 RPA（机器人流程自动化）更灵活、更智能的替代方案。

OpenHands (formerly OpenDevin): A Platform for Software Development Agents

  • arXiv: 2406.10819
  • 发表: 2024 年 6 月（持续更新的开源项目），All-Hands-AI
  • 作者: Xingyao Wang, Boxuan Li, Graham Neubig 等（CMU / UIUC / Yale 等）
  • 简介: OpenHands 是当前最活跃的开源软件开发 Agent 平台——提供一个完整的、可扩展的开发环境（包含代码编辑器、终端、浏览器），LLM Agent 在此环境中可以规划、编码、测试、调试和审查代码，社区庞大的插件生态使其成为代码 Agent 研究的核心实验平台。
  • 核心创新:
    • 完整的集成开发环境（IDE-for-Agents）：OpenHands 不是仅仅给 LLM 调用命令行 API，而是提供了一个与人类开发者使用的 IDE 类似的完整环境——内置代码编辑器（Agent 可以打开、浏览、修改任意文件）、Web 终端（Agent 可以执行 shell 命令、查看 stdout/stderr）、集成的浏览器（Agent 可以访问 Web 文档和 StackOverflow）。这种”拟人化”的环境设计使 Agent 可以使用与人类开发者相同的工作流程。
    • 可扩展的 Agent 框架：OpenHands 的核心设计是高度模块化的——Agent 策略（ReAct、CoT、SWE-agent式）、代码接口（命令行、编辑器、LSP）、工具集（搜索代码、运行测试、提交 git）、和 LLM 后端（GPT-4o、Claude、开源模型）都是可插拔的组件。研究者可以轻松地替换其中任何一环来测试新想法，而无需从零构建 Agent 环境。
    • 社区驱动的 Agent 能力竞赛：OpenHands 维护了一个实时更新的 SWE-bench Verified 排行榜，记录各种 LLM + Agent 策略组合的成绩及配置细节。这个透明的”竞赛平台”加速了代码 Agent 技术的集体进步——2024 年 6 月从约 20% 起步，到 2025 年初社区贡献的改进已推动成绩逼近 60%。
  • 代表意义: OpenHands 是代码 Agent 研究社区协同进步的基础设施。它的价值不在于提出了一个全新的算法，而在于提供了一个可复现、可对比、可扩展的实验平台——类似于”代码 Agent 领域的 Gym”（强化学习的标准化环境）。在 OpenHands 的推动下，代码 Agent 的研究从”各家搭自己的实验环境、结果无法直接比较”的混乱状态，逐步走向了标准化和系统化。其开源社区也贡献了大量创新的 Agent 策略、工具组合和评估方法。

AgentBench: Evaluating LLMs As Agents

  • arXiv: 2308.03688
  • 发表: ICLR 2024 (Spotlight)
  • 作者: Xiao Liu, Hao Yu, Hanchen Zhang 等（Tsinghua University / Microsoft Research 等）
  • 简介: AgentBench 是首个系统化的 LLM 作为智能体的多维度评测基准——覆盖 8 个真实环境（Web 购物、代码编程、数据库查询、桌面操控、知识图谱问答、棋牌游戏、操作系统、横向思维谜题），首次对 25 个主流 LLM 的 Agent 能力进行了全面评测和排名。
  • 核心创新:
    • 8 个真实交互环境的统一评测框架：AgentBench 的核心是构建了一个统一的 Agent 评测接口——所有环境都使用标准化的观察-行动-奖励循环，Agent 通过相同的协议接收环境状态（自然语言描述或结构化数据），输出行动，接收反馈。8 个环境覆盖了 Agent 能力的各个维度——Web 环境测试 Web 浏览和表单填写能力；代码环境测试调试和重构能力；数据库环境测试 SQL 生成和模式理解能力；桌面环境测试 GUI 操作和文件管理能力；游戏环境测试策略规划能力。
    • 首次系统的 Agent 能力排名：论文评测了 25 个主流 LLM（包括 GPT-4、GPT-3.5、Claude-2、LLaMA-2、Code-LLaMA 等），得出了多个重要发现——（a）GPT-4 在所有环境上全面领先，但不同模型的优势环境不同（Claude 在以工具使用为主的任务上接近 GPT-4，但在需要多轮规划的任务上落后）；（b）开源模型在代码和知识性任务上可与 GPT-3.5 竞争，但在需要探索和规划的开放式环境上大幅落后；（c）工具使用的 zero-shot 泛化能力与模型规模高度相关。
    • “可学习性”和”兼容性”两个新维度：AgentBench 评测了 Agent 的”可学习性”（能否通过环境反馈改进后续决策）和”兼容性”（对不同 Agent 框架的适配难易度），为 Agent 研究和部署提供了超越”静态分数”的实用参考。
  • 代表意义: AgentBench 是”LLM 评测 -> LLM Agent 评测”范式升级的标志性工作。在此前，评测一个 LLM 的”智能”主要靠回答题目（MMLU）和写代码（HumanEval）。AgentBench 开创性地指出——“作为一个智能体的能力”和”作为一个答题者的能力”是不同的维度，需要不同的评测范式。它也是业界至今最大规模的 LLM Agent 能力评测，其结果深刻影响了之后所有 Agent 产品的路线图设计。

WebVoyager: Building an End-to-End Web Agent with Large Multimodal Models

📝 论文深度笔记

  • arXiv: 2401.13919
  • 发表: 2024 年 1 月（ACL 2024 接收），Tencent / SJTU
  • 作者: Hongxin He, Wenli Yao, Kaijie Ma 等
  • 简介: WebVoyager 是首个端到端的多模态网页智能体——不需要 DOM 树或 API，仅通过分析网页截图来决定点击和输入位置，模拟人类”看网页→操作网页”的视觉驱动方式，在真实网站上的任务成功率大幅超越当时所有基于文本的网页 Agent。
  • 核心创新:
    • 纯视觉的网页交互范式：传统网页 Agent（如 WebGPT、WebArena）依赖 DOM 树（网页的 HTML 结构）来识别可交互元素的位置。WebVoyager 彻底放弃了 DOM——Agent 只接收网页截图，通过视觉分析理解网页布局、识别按钮和输入框、推断当前任务状态，然后输出操作指令（如”点击截图坐标 (324, 567) 处的’Send’按钮”）。这种纯视觉范式使 Agent 不受网页后端技术栈的限制——React、Vue、原生 HTML 都一视同仁。
    • 一组真实网站的”日常任务”基准：WebVoyager 构建了包含 643 个真实任务的评测集，覆盖 15 个流行网站（Amazon、Google Maps、Gmail、Wikipedia、GitHub 等）。任务难度从简单（”搜索某商品”）到复杂（”在 Amazon 上找到评分最高的蓝牙耳机，价格为 50-100 美元，将其加入购物车，然后检查购物车总价”）。这些任务模拟了真实用户在日常上网中的行为。
    • 多模态模型的视觉 Agent 能力验证：WebVoyager 在 GPT-4V 和 Gemini Pro Vision 上测试了其视觉 Agent 设计，GPT-4V + WebVoyager 组合取得了 55.7% 的任务成功率——是同时期基于文本 DOM 的最佳 Agent 的约 2 倍（约 25%）。这有力地证明了”视觉感知 > DOM 解析”的网页 Agent 设计哲学。
  • 代表意义: WebVoyager 是多模态 LLM 在 Agent 领域最具说服力的”killer app”之一。它直观地展示了为什么多模态能力对 Agent 至关重要——因为真实世界的信息大量以视觉形式存在（网页截图、手机屏幕、图表），而纯文本接口只能访问这些信息的一个贫瘠子集。WebVoyager 的成功直接影响了后续 Claude Computer Use 和 OpenAI Operator 等商业 GUI Agent 的产品设计路线。

OS-Copilot: Towards Generalist Computer Agents with Self-Improvement

  • arXiv: 2402.07456
  • 发表: 2024 年 2 月，Shanghai AI Laboratory / CUHK 等
  • 作者: Zhiyong Wu, Chengcheng Han, Zichen Ding 等
  • 简介: OS-Copilot 提出了一个通用操作系统 Agent 框架——能够操控 Linux 或 macOS 桌面、Web 浏览器和第三方应用程序，并通过自我改进循环（从过去的交互中学习创建可复用技能）实现持续的能力进化，在多种 OS 环境任务上超越单任务的专用 Agent。
  • 核心创新:
    • FRIDAY——自进化的通用 OS Agent：OS-Copilot 的核心是一个名为 FRIDAY 的自进化 Agent 框架。当面对新任务时，FRIDAY 首先尝试从”技能库”中检索相似的过往成功经验作为参考；如果检索失败或帮助不大，它使用 ReAct 式探索生成解决方案；成功后将新解决方案存储为可复用的”技能”，供未来类似任务使用。这种”事后学习”机制使 Agent 随着使用时间的增长而变得越来越高效。
    • 跨应用的统一操控协议：OS-Copilot 设计了统一的 OS 级别操控接口——不是为每个应用编写对接代码，而是定义了操作系统层面的通用操作（移动光标、点击、键入、截图、键盘快捷键），代理任何图形化应用的操控。实验覆盖了 Linux 和 macOS 双系统、30+ 个不同应用（从 VS Code 到 Excel 到网页浏览器），验证了跨应用、跨系统的通用性。
    • 利用自我指导实现工具创建：OS-Copilot 的一个独特能力是——当现有工具不足以完成任务时，Agent 可以自己编写代码创建新的工具。例如，在需要”批量 resize 100 张图片”的任务中，Agent 发现自己没有内置的批量图片处理工具，于是自动编写了一个 Python 脚本来完成该任务，并将该脚本保存为未来可复用的工具。这种”元工具使用”能力大幅扩展了 Agent 的操作范围。
  • 代表意义: OS-Copilot 将 Agent 研究从”在受控环境中完成预定任务”推动到了”在开放操作系统中自主学习和进化”。它的”自我改进循环”和”能力持续积累”的理念，是对”Agent 能力是一次性赋予的”这一假设的深刻挑战——正如人类通过经验的积累变得越来越能干，Agent 也应该如此。这一框架对 Anthropic Computer Use、OpenAI Operator 等后来的通用 OS Agent 产品的设计思路产生了重要影响。

Multi-Agent Debate and Conversation for Improved Reasoning

  • arXiv: 2305.14325 (Improving Factuality and Reasoning in Language Models through Multiagent Debate)
  • 发表: ICML 2024
  • 作者: Yilun Du, Shuang Li, Antonio Torralba, Joshua B. Tenenbaum, Igor Mordatch (MIT / Google DeepMind)
  • 简介: 这篇开创性论文提出了”多智能体辩论”范式——用多个 LLM 实例以辩论形式相互挑战彼此的回答，通过多轮论战和反驳使最终共识答案的准确率和事实性远超任何单个实例的输出，证明了”群体智能 > 个体智能”在 LLM 中的有效性。
  • 核心创新:
    • 正式的辩论协议设计：多智能体辩论框架定义了严格的多回合辩论协议——（a）所有 Agent 独立生成初始答案和推理；（b）每个 Agent 看到所有其他 Agent 的回答和推理，生成反驳和质疑；（c）每个 Agent 基于他人的反驳更新自己的回答；（d）经过多轮辩论后，通过投票或综合产生最终答案。这个协议模拟了学术同行评审和科学辩论的过程。
    • 跨任务的事实性提升：论文在 6 个不同任务上测试了辩论框架——数学推理（GSM8K）、常识推理（StrategyQA）、事实问答（MMLU 子集）、算术推理、多跳问答和翻译。结果显示，多 Agent 辩论在所有任务上均一致地超越了单 Agent 最佳表现，提升幅度从 5% 到 20% 不等。特别是在需要”第二意见”来纠正错误的任务上，辩论的收益最大。
    • 异议的价值：论文的一个重要发现是——辩论中产生的”分歧”是提升质量的关键。当 Agent 意见一致时（所有人都给出相同答案），辩论没有额外收益；但当 Agent 意见分歧时，辩论过程能够显著纠正大多数错误。这个发现暗示了”认知多样性”在 LLM 群体中的价值——即使是相同的模型、不同的随机种子，也能产生足够的多样性来驱动有意义的辩论。
  • 代表意义: Multi-Agent Debate 开创了”LLM 集体智能”的研究方向。它用一个简洁的实验范式证明了——让 LLM 互相”对话和争论”可以产生比单个 LLM 更准确、更可靠的结果，且这个过程不依赖外部监督或人类反馈。这一发现直接催生了大量的后续工作——包括 AutoGen、ChatDev（软件工程多 Agent）、以及用于事实核查、医学诊断和安全审计的各种多 Agent 框架。它也为”LLM 的群体智慧”（wisdom of the LLM crowd）提供了实证基础。

总结

上述 12 个工作勾勒出了 LLM Agent 领域的完整进化脉络：从推理与行动的融合（ReAct）到自监督的工具学习（Toolformer），从开放式环境中的终身探索（Voyager）到社会行为涌现的模拟（Generative Agents），从 Web 和 OS 操控（WebVoyager、OS-Copilot）到视觉驱动的通用 Agent（Claude Computer Use），从多智能体协作框架（AutoGen）到群体辩论智能（Multi-Agent Debate），从真实代码工程的能力证明（SWE-agent、SWE-bench）到开放评测平台（AgentBench、OpenHands）。这一领域的发展体现了四个核心趋势：第一，LLM Agent 与外部世界的交互界面正在从”API 调用”深化为更复杂、更贴近人类使用习惯的视觉和操作界面；第二，从单 Agent 到多 Agent 协作与辩论正在成为解决复杂任务的标准范式；第三，评测正在从人工构造的玩具任务全面转向真实世界问题（真实 GitHub Issue、真实网站、真实操作系统）；第四，Agent 正从”一次性的工具调用”进化到”持续学习和自我改进的自主实体”。
