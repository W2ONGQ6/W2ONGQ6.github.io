Qwen2.5/Qwen3 MoE: 全局批次负载均衡与统一思考/非思考框架

Qwen MoE: 全局批次负载均衡与统一推理框架

核心信息

Qwen2.5 和 Qwen3 代表了开源 MoE 模型的最新进展（截至 2025 年年中）。系列继承了 DeepSeekMoE 的细粒度专家分割与共享专家设计模式，并创新性地引入：全局批次负载均衡损失（使用全局批次统计取代微批次统计）和统一思考/非思考框架（单个 MoE 模型同时支持快速响应和深度 chain-of-thought 推理）。Qwen3 在 36T token 上预训练，覆盖 119 种语言，采用 4 阶段后训练流程。Qwen3-235B 在多个基准上匹敌或超越 GPT-4o 和 Claude 3.5 Sonnet。

原文摘要翻译

Qwen2.5 将细粒度专家分割和共享专家机制扩展到 64+ 专家/层，每 token 激活 4-8 个路由专家。Qwen3 在此基础上引入全局批次负载均衡损失，避免了逐微批次辅助损失的性能代价。Qwen3 实现了统一思考/非思考框架：单一 MoE 模型支持可切换的快速响应模式和深度 chain-of-thought 推理模式，通过 prompt 或 template 切换。在 36T token 上预训练后，Qwen3-235B 在 MMLU、MATH-500、HumanEval、AIME 2024 等基准上与 GPT-4o 和 Claude 3.5 Sonnet 持平或超越。Qwen3-Next 计划将专家数扩展到 512 个，激活率降至约 3.7%。

创新点

  1. 全局批次负载均衡损失 — 跨多个 micro-batches 累积路由决策的负载统计，在全局批次上应用均衡约束。解决了 micro-batch 内因数据高度相关（同一文档/领域）导致的负载统计偏差——在微批次内看起来”均匀”的负载，在全局看可能是系统偏斜的。全局统计提供更准确的均衡信号，训练更稳定。

  2. 统一思考/非思考框架 — 单个 MoE 模型同时支持两种推理模式：非思考模式（快速直接输出，类似标准对话模型）和思考模式（深度 CoT 逐步推理，输出完整的推理链）。模式切换通过 prompt/template 实现，带思考预算机制（用户可设定推理的计算上限）。这是首个将高效推理和深度推理集成到单个 MoE 模型的工作。

  3. 阶梯式 4 阶段后训练策略 — (1) Cold-start SFT: 基础指令微调 ~50K 样本；(2) Long-CoT SFT: 长链推理微调 ~100K 样本；(3) RL 推理强化: 使用 GRPO（Group Relative Policy Optimization）奖励正确最终答案和合理推理步骤；(4) RLHF 对齐: 优化 helpulness 和安全性的人类偏好。

  4. 超稀疏 MoE 的前沿探索 (Qwen3-Next) — 计划扩展到 512 个专家/层，仅激活约 19 个（3.7%）。如果成功，将把 MoE 的效率推到一个新的极端——总参数量巨大（约 1T params estimation）但每 token 的计算成本接近一个 37B 的密集模型。

一句话总结

Qwen3 以全局批次负载均衡消除 micro-batch 的统计噪声，以统一思考/非思考框架实现单个 MoE 模型内的计算弹性——从快速简答到深度推理的无缝切换——是 2025 年开源 MoE 在效率、能力和实用性三个维度上的最先进代表。

研究问题

核心挑战与子问题

子问题1：micro-batch 负载均衡的统计噪声问题。

传统的 MoE 负载均衡是在每个 micro-batch 的前向传播后计算辅助损失（auxiliary loss）。辅助损失的形式为 loss = alpha * sum_i(f_i * P_i)，其中 f_i 是专家 i 在当前 micro-batch 中被路由到的 token 比例，P_i 是每个 token 选择专家 i 的平均概率。

Micro-batch 通常包含 16-128 个 token，这些 token 来自同一文档、段落或领域（由于训练数据的连续性）。例如，一个 batch 来源于维基百科的”量子力学”文章——所有 token 可能集中路由到”科学推理”相关的专家。在这个”局部世界”里，负载看起来均匀（token 分布在与量子力学相关的几个专家中），但跨 micro-batches 看全局：来自编程文档的 micro-batch 会路由到”代码”专家，来自文学文档的微批次会路由到”语言”专家——各自的”局部均衡”在全局造成了系统偏斜。

量化这个效应: 假设 100 个 micro-batches 来自编程文档。在全局上，”代码逻辑专家”的负载是均值的 2-3 倍，但每个 micro-batch 内（只看编程 document 的 64 个 token），token 均匀分布在编程相关的 5-8 个专家中——看起来”还好”。micro-batch 级别的辅助损失无法检测到这种系统的跨 micro-batch 偏斜。

子问题2：全局批次负载均衡的实现细节和权衡。

Qwen3 的全局批次方法：(a) 在前向传播中记录每个 micro-batch 的路由决策（每个 token 选择了哪个专家）；(b) 累积这些统计直到整个 global batch（如 2048 token × 多 micro-batches）完成；(c) 在全局批次级别计算一次均衡损失；(d) 通过 backward 同时对所有 micro-batches 更新梯度。

额外的实现细节：(a) 路由统计的存储开销很小——每层约 64 个专家的 (token 计数, 平均概率) 对，即 64×2 floats/层；(b) 跨 micro-batch 累积需要额外的同步点（all-reduce 或 gather），增加了约 2-5% 的训练时间开销；(c) 梯度只在 global batch 完成后才更新——与标准的 gradient accumulation 一致，不影响优化器的语义。

子问题3：MoE 中的 CoT 推理连贯性。

CoT 推理需要 2000-4000 token 的连贯逻辑链。如果 MoE 路由在推理链中途将 token 切换到”不擅长”的专家（例如，将逻辑推导的某一步路由到”语言表达”专家而非”逻辑推理”专家），推理可能中断（错误结论）或质量下降（虽然逻辑自洽但表述模糊）。

Qwen3 的关键假设：MoE 专家的专业化是按”推理操作类型”而非”推理主题”发生的。推理的操作类型包括：符号计算（operations on formal symbols）、模式匹配（pattern recognition）、反事实推理（what-if scenarios）、类比推理（analogical mapping）、约束传播（constraint propagation）等。这些操作类型在不同主题的推理任务中重复出现——数学证明和代码调试都可能需要”约束传播”，语法分析和逻辑推理都可能需要”模式匹配”。

在训练过程中，专家通过梯度自然专业化——处理类似”操作”的 token 最终路由到相似专家集合，不论这些 token 来自哪个”主题”。这确保了 CoT 推理链虽然主题可能跨越多个领域（如数学 → 物理 → 工程），但推理操作在连续的 “操作专家” 集合中保持一致。

子问题4：3.7% 激活率的信息论极限。

Qwen3-Next 计划每层 512 个专家，每 token 激活 19 个（3.7%）。以隐藏维度 4096、FFN 中间维度 11008 为例：密集 FFN 的计算量为 2×4096×11008 ≈ 90M FLOPs per token。MoE 的计算量为 2×4096×11008×3.7% ≈ 3.3M FLOPs per token（路由专家的 FFN） + 共享专家的开销。计算节省约 27 倍。

但这提出了信息论的问题：每个 token 仅使用总专家容量的 3.7%（即 512 个专家中访问了 19 个，每个专家的知识容量约为 11008 维度的 FFN 权重）。这 19 个专家能否提供足够的”变换能力”来处理该 token 所需的全部 FFN 计算？

论点支持可行性：(a) 每个专家的 FFN 权重是独立训练的——512 个专家的总参数量远大于密集 FFN（512×11008×4096 ≈ 23B vs 密集的 11008×4096 ≈ 45M），只是每个 token 只激活少数子集；(b) 每个 token 仅需要与其内容相关的特定类型的FFN变换——并不需要整个密集模型的所有能力；(c) 在 DeepSeek-V3 中，约 5.5% 的激活率已经证明了可行性——3.7% 是进一步的推进。

子问题5：全局批次均衡与 DeepSeek-V3 的 bias-based 均衡的优劣比较。

DeepSeek-V3 使用”无辅助损失”的 bias-based 负载均衡：每个专家添加一个偏置项，在前向传播中动态调整偏置以均衡负载——但梯度不回传偏置项（无辅助损失的计算开销）。这完全消除了辅助损失对模型质量的影响。

Qwen3 使用全局批次辅助损失——仍有辅助损失项加入训练目标，但通过全局统计改善了统计质量。

两者的比较：(a) Bias-based 无辅助损失→理论上完全无损但实现更复杂（需要动态偏置调整逻辑、推理时去除偏置）；(b) 全局辅助损失→实现简单但仍有轻微的性能影响（约 0.01-0.02 PPL 的辅助损失代价）。哪种更优是一个开放的实证问题——目前 DeepSeek-V3 和 Qwen3 在性能上是可比的，没有明确的赢家。

数据与任务定义

  • 训练数据: Qwen3 在 36T tokens 上预训练（Qwen2.5 的 2 倍），覆盖 119 种语言
  • 模型配置 (Qwen3-235B): 每层 64 个路由专家 + 8 个共享专家，每 token 激活 8 个路由专家 + 所有共享专家
  • 注意力机制: GQA (64 Q heads, 8 KV heads)，非 MLA（与 DeepSeek-V3 不同）
  • 隐藏维度: 7168, FFN 中间维度: 18944 (每个专家)
  • 全局批次大小: 约 4M tokens
  • 上下文长度: 256K（Qwen3），较 Qwen2.5 的 128K 翻倍
  • 评估基准: MMLU, MATH-500, HumanEval, AIME 2024, LiveCodeBench, LongBench (256K)
  • 对比模型: Llama 3.1 405B, DeepSeek-V3, GPT-4o, Claude 3.5 Sonnet
  • 后训练: 4 阶段（Cold-start SFT → Long-CoT SFT → GRPO 推理强化 → RLHF 对齐）

方法主线

完整的机制流程

步骤1: 细粒度专家分割与共享专家设计

输入: Transformer 层的 FFN 子层权重

操作:

  • 将传统的大 FFN 层（如 7168×18944×3 权重矩阵）拆分为 64 个独立的路由专家（每个专家有独立的 FFN 权重，中间维度缩小为 18944/64 ≈ 296）
  • 额外设置 8 个共享专家（所有 token 都经过它们，不参与路由选择）
  • 路由逻辑: 对于每个 token，计算其与 64 个路由专家的 embedding 相似度 → Top-8 选择 → 8 个被选专家独立处理该 token → 合并输出
  • 共享专家输出与路由专家输出按学习到的权重融合

输出: 细粒度 MoE 层 — 每个 token 经过 8 个路由专家 + 8 个共享专家的 FFN 变换

步骤2: 全局批次负载均衡

输入: 每个 micro-batch 的 Top-K 路由决策

操作:

  • 在前向传播中记录每个 micro-batch 的路由统计：专家 i 收到了多少 token (count_i)，以及每个 token 选择专家 i 的平均概率 (prob_i)
  • 累积这些统计跨越多个 micro-batches（通常 4-16 个 micro-batches 组成一个 global batch）
  • 在 global batch 完成时，计算全局负载均衡损失:
    loss_balance = alpha × sum_i (global_count_i / total_tokens) × (global_prob_i / total_tokens)
  • alpha 是权衡系数（Qwen3 使用约 0.01，较传统 0.02 更小）
  • Gradient 在 global batch 后统一回传

输出: 基于全局统计的准确负载均衡信号，减少 micro-batch 噪声

步骤3: 统一思考/非思考的训练机制

输入: 单个 MoE 模型 + 两种类型的训练数据

操作:

  • 非思考数据: 标准对话指令，答案直接（如 Q: “法国首都是？” A: “巴黎”）— 占训练数据的大部分
  • 思考数据: 长 CoT 推理数据，包含逐步推理步骤（如 Q: “解决这个数学问题” A: “首先…然后…因此…答案是…”）— 占训练数据的少数（约 15-25%）
  • 训练混合: 两种数据混在同一个训练流程中，使用标准的 next-token prediction loss
  • 模式标识: 通过 prompt template 在数据中嵌入模式信号（如 [THINK] token 或特殊的 system prompt）
  • 模型在推理时通过识别 prompt 模式来自动切换行为

输出: 支持双模式切换的单个模型 — 不需要两个独立模型

步骤4: 4 阶段后训练管线

输入: Qwen3 预训练基础模型

操作:

  • 阶段 1: Cold-start SFT（约 50K 高质量指令-回复对，覆盖通用对话、知识问答、基础推理）
  • 阶段 2: Long-CoT SFT（约 100K 长链推理样本，包含完整的推理步骤和最终答案）
  • 阶段 3: GRPO 推理强化（Group Relative Policy Optimization — 一种基于 group 内相对比较的 RL 算法，奖励信号：最终答案正确性 + 推理步骤的连贯性和合理性）
  • 阶段 4: RLHF 对齐（人类偏好数据收集 → 奖励模型训练 → PPO 优化，优化 helpulness 和 harmlessness）

输出: Qwen3-Chat 模型 — 经过全面后训练对齐的对话和推理助手

步骤5: 上下文扩展与长文档能力

输入: 128K (Qwen2.5) 或 256K (Qwen3) 的基础训练上下文

操作:

  • 在训练后期引入长序列数据（通过拼接多文档或使用自然长文档数据）
  • 调整 RoPE 位置编码参数以适应更长序列（如提高 RoPE base frequency 或使用 NTK-aware 缩放）
  • 在 LongBench 上验证 256K 上下文的有效性

输出: 支持 256K 上下文的长文档处理能力

深度分析

1. 全局批次负载均衡：从噪声统计到信号统计

Micro-batch 负载均衡的核心缺陷是一个经典的”辛普森悖论”(Simpson’s paradox)。在每个 micro-batch 内部，负载看起来合理（token 相对均匀地分布在与该 micro-batch 的主题相关的专家中）。但当你聚合全局时，某些专家在聚合后明显过载——它们在多个 micro-batches 中都承担了略高于均值的负载，累积后远超均值。

全局批次方法类似 group normalization vs batch normalization 的升级：batch norm 在 micro-batch 内计算统计（局部），group norm 在通道组上计算统计（更全局、更稳定）。Qwen3 做的是”batch-level → global-batch-level”的升级——统计的粒度从 batch 提升到 global batch，降低了采样噪声。

这个方法的一个副作用是改善了专家专业化——当负载均衡的统计信号更准确时，模型可以更放心地让专家”偏斜”向特定类型的 token（因为均衡损失不会因为 micro-batch 的偶然偏差而错误地惩罚有益的专业化）。

2. 思考/非思考统一：解决 MoE 效率与 CoT 推理的”虚假冲突”

在 Qwen3 之前，直觉上存在一个担忧：MoE 的稀疏激活（每个 token 仅使用少数专家）会损害 CoT 推理的连贯性（因为推理链中途可能切换到”不擅长”的专家）。Qwen3 证明了这种担忧是虚构的——专家按”操作类型”专业化，而非”主题”——使 CoT 推理链始终保持在使用合适的专家集合中。

更深层的原理：CoT 推理本质上是将复杂问题分解为一系列”原语操作”（primitive operations）的序列。MoE 的每个专家恰好学会执行某种类型的原语操作（如符号替换、模式识别、约束检查、类比映射等）。因此，无论推理主题如何（数学、编程、哲学），每个推理步骤都会路由到执行其对应操作类型的专家。

共享专家在这一框架中扮演了”稳定底座”的角色——为所有推理步骤提供基础的 token 语义理解（语言模型的核心能力），而路由专家提供特定的”操作技能”。

3. Qwen3 vs DeepSeek-V3：两条不同的 MoE 效率路径

虽然两者都使用细粒度专家、共享专家、和先进的负载均衡策略，但它们的核心哲学有所不同：

Qwen3 的哲学: “广覆盖 + 深推理” — 通过 36T tokens（119 种语言）的广度预训练和 4 阶段后训练，确保模型覆盖广泛的知识和推理能力。全球化负载均衡确保这个广度在 MoE 架构下可稳定训练。

DeepSeek-V3 的哲学: “极致效率 + 极致成本” — 通过 Multi-head Latent Attention (MLA) 减少 KV cache，通过无辅助损失的 bias-based 均衡消除负载均衡的性能代价。训练数据 14.8T tokens 更少但更精。

两个模型目前性能可比（各在某些基准上略优），证明了 MoE 效率存在多条有效路径——不只有一个”最优解”配置。

4. Qwen3-Next 的超稀疏设计与激活率的信息论边界

3.7% 激活率（512 个专家中激活 19 个）将 MoE 推向了一个极端稀疏的 regime。这是到目前为止最低的公开激活率计划（对比 DeepSeek-V3 约 5.5%, Mixtral 8x7B 的 12.5%）。

信息论的挑战: 对于隐藏维度 D 的 FFN 变换，每个 token 需要的信息量约为 O(D^2) 量级（矩阵乘法的自由度数）。激活 19 个专家提供了 19 × O((D/E)^2) 的自由度（其中 E=512 是专家总数），但还要加上 8 个共享专家的贡献。总自由度 19×(D/512)^2 + 8×D^2 ≈ 0.000072D^2 + 8D^2 ≈ 8D^2 自由度的 FFN 变换能力——这与密集模型的 D^2 自由度相比似乎充足，但前提是 8 个共享专家有足够的容量来承载”通用变换”。

关键的不确定性: 对于极端稀疏的模型，是否会出现”专家过度专业化”（over-specialization）？当每个 token 仅激活 19 个专家时，每个专家必须非常精确地匹配某些 token的特征——如果专家的专业化太过狭窄，它们可能无法服务于略微超出其训练分布的 token。这个问题需要在 Qwen3-Next 的训练中实证验证。

局限和实践挑战

  1. 全局批次均衡的额外同步开销。 跨 micro-batches 累积路由统计需要额外的同步点（all-reduce 或 gather），在分布式训练中增加了约 2-5% 的通信开销。在超大规模训练（K+ GPUs）中，这些同步点可能成为瓶颈——因为路由统计的 global all-reduce 与参数梯度的 all-reduce 竞争网络带宽。

  2. 思考/非思考边界的模糊性。 Prompt 驱动的模式切换在”模糊案例”中可能产生次优选择——某些任务可能介于”需要思考”和”不需要思考”之间（如”解释量子力学”——简单概述不需 CoT，深层推导需要 CoT）。当模型错误地选择模式时（应思考但做了快速回答、应快速回答但做了冗长推理），用户体验和性能都受影响。影响分析: 对边缘 case 的 response 质量可能有 10-20% 的波动。

  3. 超稀疏 MoE (Qwen3-Next 3.7%) 的验证严重不足。 512 专家/层、激活 19 个（3.7%）的配置仅是计划/预研阶段，缺乏大规模训练的实证验证。可能的实际挑战:(a) 路由在超低激活率下可能极不稳定——每个专家的”责任范围”过于狭窄，路由决策的微小变化（如 top-19 的第 19 名和第 20 名 swap）可能导致 token 被送入”完全不对口”的专家；(b) 负载均衡在 512 个专家的粒度下实现全局均衡更难——每个 micro-batch 覆盖的专家子集更小，统计信号更弱；(c) 训练开销: 512 个专家的参数虽大部分不激活，但仍需在 GPU 内存中存储（model parallelism 粒度更细）。

  4. GQA 的长上下文效率劣势。 Qwen3 选择 GQA（而非 DeepSeek-V3 的 MLA）做注意力机制，在长上下文时 KV cache 更大。对于 256K 上下文：GQA 的 KV cache 约为 8 KV heads × 256K × (7168/64) 维 ≈ 约 7.2 MB/层 × 假设 96 层 ≈ 约 700 MB。MLA 的 KV cache 可能压缩到约 200-300 MB。这对高并发长上下文推理（如同时服务多个 128K+ 文档的用户）是一个实质性的限制。

  5. 4 阶段后训练的边际收益未充分消融。 虽然 Qwen3 描述了 4 个后训练阶段，但没有系统地报告每个阶段的边际收益。无法判断: (a) Long-CoT SFT 对最终性能的增量超过 Cold-start SFT 多少？(b) GRPO 增强推理 vs 直接从 Long-CoT SFT 做推理的增益？(c) RLHF 对齐阶段的”对齐税”(alignment tax) 在 Qwen3 上是多少（能力下降 vs 安全性提升的 tradeoff）？缺乏这些消融使社区难以判断他们的后训练 pipeline 的哪些部分是”必不可少”的、哪些是”锦上添花”的。

  6. 119 种语言的训练数据分布极不均衡。 虽声称覆盖 119 种语言，但训练数据的语言分布严重偏向英语和中文（估计共占 70-80%）。剩余的 117 种语言可能在总数据中仅占 20-30%，导致”长尾语言”的模型质量显著低于头部语言。此外，119 种语言可能倾向于激活不同的专家子集——可能自发形成了”语言专属专家”（某些专家几乎只处理特定语言的 token）。这种自发的语言分离可能造成”语言隔离”——跨语言的 transfer learning 可能被 MoE 路由抑制。

  7. 统一思考/非思考的单模型策略与专门模型策略的优势/劣势。 将两个模型的功能塞入一个模型肯定会带来某种”能力压缩”(capabilities compression)——模型参数必须同时支持两种行为模式。如果有一个专门做快速回答的 235B 模型 + 一个专门做深度推理的 235B 模型，两者的综合能力可能超过单个统一的 235B 模型。Qwen3 选择统一方案更多地出于效率（一个模型替代两个）而非极致能力——这在商业部署上有意义，但作为研究探索，”专门 vs 统一”的权衡值得更深入的消融。

可复用洞见

  1. 负载均衡的统计粒度应与数据独立性的粒度一致。 当 micro-batch 内的数据高度相关（来自同一文档/领域），micro-batch 的负载统计噪声显著。提升统计到 global-batch 级别（跨多个独立 micro-batches）能大幅降低噪声。这个原则可推广：任何基于 batch 统计的约束或损失（batch norm, layer-wise auxiliary loss）都应检查 batch 内数据是否真的独立。

  2. MoE 的高效推理与深度 CoT 推理不矛盾。 Qwen3 统一框架证明了稀疏激活不会损害推理连贯性——关键前提是专家按操作类型（而非主题）专业化。这扫除了”高效 MoE 不适合推理模型”的心理障碍，为未来的”高效推理模型”研究铺平了道路。

  3. 后训练管线是 MoE 能力的关键杠杆。 Qwen3 的 4 阶段后训练（尤其是 Long-CoT SFT + GRPO）对最终推理能力的贡献可能超过预训练阶段增加更多数据。这表明对于 MoE 模型（已经参数丰富但激活稀疏），后训练的”能力定向”效果（通过精心设计的训练信号引导模型到特定的能力分布）极其重要。

  4. 思考预算 = 计算预算的语义化、面向用户的封装。 允许用户用”思考深度”（而非毫秒延迟或浮点运算）定义计算预算，是产品化 AI 的一个巧妙策略。它将底层的计算弹性转化为面向用户的价值主张——“给我快速答案”/“花点时间仔细思考”——是连接技术能力和用户体验的桥梁。

  5. 从 Qwen2.5 到 Qwen3 的 scaling 路径揭示了”语言覆盖”的多维度价值。 训练数据从 18T → 36T（翻倍）和语言从 30 → 119 种（4 倍），虽然不是一一对应（数据增加 + 语言覆盖扩大 + 后训练深化同时发生），但多语言覆盖对跨语言泛化、稀有语言性能、甚至可能对英语和中文通过跨语言 transfer 有正向影响。这为”language coverage as a capability amplifier”提供了初步的实证基础。

  6. 细粒度 MoE + 全局批次均衡 + 4 阶段后训练 = 一个可复用的”MoE 成熟配方”。 Qwen3 的架构设计和训练策略形成了一个完整的 MoE 开发 pipeline，从数据处理到最后的后训练对齐——可作为未来 MoE 项目的基线配方。

我的笔记

Qwen3 最让我印象深刻的是将 MoE 从”纯效率导向的架构”升级为”效率+能力统一的架构”。在 Qwen3 之前，MoE 主要被视为一种”用更大的模型总参数换取更低的推理成本”的方法——效率是卖点，但能力通常是”不劣于密集模型”而非”优于密集模型”。Qwen3 改变了这个叙事：MoE 的能力（学习多种操作类型、灵活切换推理模式）可能成为超越密集模型的竞争优势。

全局批次负载均衡的核心理念——“均衡统计的粒度应与数据统计独立性的粒度一致”——具有远超 MoE 负载均衡的普适性。这是统计学的基本原理（统计推断的质量取决于样本的独立性），但在 DL 训练中经常被忽视（因为 batch 处理和 micro-batch gradient accumulation 的 convention 已经深入人心）。Qwen3 做了一个简单但明智的”粒度升级”——我期待这个洞见被更广泛地应用于其他类似场景（如训练稳定性诊断、curriculum learning 的阶段切换判断等）。

思考/非思考统一框架开创了”按需推理”的产品模式。这背后是一个重要的用户价值洞察：用户愿意为复杂问题接受更长的延迟（以换取更好的答案），但讨厌为简单问题支付不必要的等待成本。统一框架让用户在同一个模型、同一个界面中做出这个选择——不需要了解两个模型的区别、不需要切换 app 或 API endpoint。这种”计算弹性”的感觉是自然且符合直觉的——人类在回答”你好吗”时也不会进入深思模式。

Qwen3-Next 的 3.7% 激活率计划很大胆，但我认为这是一个”必要的科学探索”而非”必然会成功的方向”。我们正处于 MoE 激活率的探索前沿——从 12.5% (Mixtral) → 5.5% (DeepSeek-V3) → 3.7% (Qwen3-Next plan)。在某个点上，极低的激活率必然触及信息论的下限——每 token 所需的”FFN 变换多样性”超过了少数专家能提供的。3.7% 是否在那个下限之上？这是一个只有实验能回答的问题。但我赞赏 Qwen 团队尝试突破这一边界——即使失败，也会教会我们 MoE 的激活率下限是多少。

最后，Qwen3 让我想到一个关于开源 LLM 竞争的重要趋势。过去，”开源对抗闭源”的方法是训练更大的模型（更接近 GPT-4 的规模）。现在，”开源对抗闭源”的策略已经多元化了：(a) 效率路径 (MoE——Qwen3/DeepSeek-V3 在远低算力下匹敌 GPT-4o)；(b) 能力路径 (思考/非思考统一——开源模型提供闭源尚未提供的功能)；(c) 语言路径 (119 种语言——覆盖闭源模型不足的长尾语言)。这种”不对等的竞争”（不同维度上的差异化）比简单的”规模军备竞赛”更加健康和可持续。

后续问题

  1. 全局批次负载均衡和 DeepSeek-V3 的 bias-based 均衡能否结合？能否在全局批次上使用 bias-based 统计来完全消除辅助损失？

  2. Qwen3-Next 的 3.7% 激活率的信息论下限是什么？在什么激活率以下 MoE 路由开始”不够看”（无法为每个 token 提供有效 FFN 变换）？

  3. 思考/非思考模式切换时路由模式如何变化？两种模式是否激活了不同的专家子集（即模型的两套”大脑回路”）？

  4. 119 种语言是否倾向于激活不同的专家子集？是否存在自发形成的”语言专属专家”？如果是，这对跨语言 transfer learning 是帮助还是阻碍？

  5. GQA 在 256K 上下文上是否确实比 MLA 有显著的 KV cache 劣势？能否用量化 KV cache 或其他技术来弥补？

  6. 4 阶段后训练中每个阶段的独立贡献（消融）是否可以量化？Long-CoT SFT 的贡献是否大于 GRPO？是否可以跳过某些阶段？
