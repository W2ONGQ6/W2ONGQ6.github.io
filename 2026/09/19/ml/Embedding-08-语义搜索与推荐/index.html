二、ANN 算法（近似最近邻）

2.1 为什么需要 ANN？

暴力搜索复杂度：

  • ：文档数（百万级）
  • ：向量维度（768）

ANN 解决方案：牺牲少量精度（<5%），换取 100-1000 倍加速

2.2 主流 ANN 算法

HNSW（Hierarchical Navigable Small World）

优点：

  • 查询速度快（对数复杂度）
  • 召回率高（>95%）
  • 增量更新友好

IVF（Inverted File Index）

核心思想：聚类 + 倒排索引

2.3 算法对比

算法 召回率 速度 内存 适用场景
HNSW 95-99% 很快 大 高召回率需求
IVF 90-95% 快 中 平衡方案
IVF+PQ 85-90% 很快 小 大规模（>千万）

六、评估指标

6.1 离线指标

  • Recall@K：Top-K 中命中真实物品的比例
  • NDCG@K：归一化折损累积增益

6.2 在线指标

  • CTR（点击率）：点击数 / 曝光数
  • CVR（转化率）：购买数 / 点击数
  • 多样性：推荐物品类别分布

  • Wide & Deep 排序

7.2 淘宝多兴趣召回

  • 用户 → 多个兴趣 Embedding
  • 每个兴趣独立召回后聚合

八、总结

8.1 关键技术栈

层级 技术 工具
Embedding BGE, E5 Sentence-Transformers
向量检索 HNSW, IVF FAISS, Milvus
排序模型 DNN PyTorch
在线服务 缓存 Redis, Kafka

8.2 最佳实践

  1. 召回多样化：多路召回策略
  2. ANN 选择：百万级用 HNSW
  3. 实时更新：增量更新 Embedding
  4. 冷启动：内容 Embedding + 热门推荐
  5. 评估体系：离线 + 在线 A/B 测试
