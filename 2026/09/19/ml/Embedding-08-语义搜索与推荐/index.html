二、ANN 算法（近似最近邻）

2.1 为什么需要 ANN？

暴力搜索复杂度：

  • ：文档数（百万级）
  • ：向量维度（768）

ANN 解决方案：牺牲少量精度（<5%），换取 100-1000 倍加速

2.2 主流 ANN 算法

HNSW（Hierarchical Navigable Small World）

优点：

  • 查询速度快（对数复杂度）
  • 召回率高（>95%）
  • 增量更新友好

IVF（Inverted File Index）

核心思想：聚类 + 倒排索引

2.3 算法对比

算法 召回率 速度 内存 适用场景
HNSW 95-99% 很快 大 高召回率需求
IVF 90-95% 快 中 平衡方案
IVF+PQ 85-90% 很快 小 大规模（>千万）

2.4 索引参数也属于模型质量的一部分

ANN 的“近似”并非固定误差。HNSW 的 M、efConstruction、efSearch，以及 IVF 的 nlist、nprobe 都会改变速度、内存和召回。正确的调参方式是拿同一批 query 同时跑精确 Flat 索引与 ANN 索引：

然后画出 ANN Recall@K - P95 延迟 - 内存 的曲线，选择满足服务 SLO 的点。不要只看向量库报告的 QPS；索引加载、过滤、网络、reranker 和缓存未命中都会进入用户实际看到的延迟。

带过滤检索还需要单独测试。若先取 Top-K 再过滤，候选可能被过滤空；若先按租户、权限或类目过滤，索引性能可能下降。权限过滤必须优先保证正确性，不能为了召回而事后过滤。

3.2 双塔只负责召回，不负责最终排序

推荐系统通常是多阶段漏斗：

双塔把 user 和 item 编到可索引的同一空间，换来百万物品中的快速召回；它没有在 query / item 之间做充分特征交互。因此价格、库存、时段、位置、已购状态等强约束，通常应在过滤、精排或重排层处理。

3.3 训练目标与负例决定“召回什么”

正反馈可来自点击、收藏、加购和购买，但它们的语义不同，最好保留事件类型和权重。负例也不应只有随机物品：

  • 曝光未点击：更接近真实竞争集，但受位置与曝光策略偏差影响；
  • batch 内负例：高效，适合对比学习；
  • 同类 hard negative：区分相似商品或内容；
  • 随机负例：简单但对模型帮助有限，可保留少量维持覆盖。

5.2 向量更新要有版本和删除语义

物品下架、内容改版、用户撤回授权和模型更新都会使向量失效。每条向量建议保存 entity_id、embedding_version、updated_at、availability 和权限 / 租户字段。删除既要从主数据删除，也要从 ANN 索引、缓存和日志派生表中失效；模型切换则采用“新索引全量构建 → 小流量验证 → 别名切换 → 保留回滚窗口”的迁移方式。

六、评估指标

6.1 离线指标

  • Recall@K：Top-K 中命中真实物品的比例
  • NDCG@K：归一化折损累积增益

6.2 在线指标

  • CTR（点击率）：点击数 / 曝光数
  • CVR（转化率）：购买数 / 点击数
  • 多样性：推荐物品类别分布

6.3 不只看 CTR：指标有方向性

单独优化 CTR 可能把系统推向标题党、重复内容或低质量短期点击。一个更平衡的指标面板应同时覆盖：

维度 示例指标 要防止的问题
相关性 Recall@K、NDCG@K、MRR 只看平均值，忽略长尾用户
商业结果 CTR、CVR、GMV、留存 点击上升但转化或留存下降
体验 多样性、覆盖率、新颖度、重复率 只推爆款或单一类别
系统 P95 延迟、空结果率、索引新鲜度 离线好、线上超时
安全公平 投诉率、敏感类别曝光、群体切片 反馈回路放大偏见

线上实验应预先定义主指标、护栏指标、实验时长和显著性方法。不要根据中途偶然上升的 CTR 频繁停实验；同时检查新老用户、不同地区和冷启动物品等切片，避免平均提升掩盖关键人群退化。

七、从离线分数到线上实验

7.1 何时相信离线指标？

离线 Recall@K 是对“历史正例是否被召回”的近似，不能完全模拟用户对新结果的反应。出现以下情况时，离线与线上尤其容易背离：训练日志的曝光策略变化、内容供给更新、用户兴趣快速漂移、展示位置改变，或评价指标未计入多样性与库存。

因此建议先离线淘汰明显较差的方案，再做小流量 A/B；将 query / user、候选、排名、展示位置、策略版本和反馈事件串起来记录，才能诊断线上变化。

7.2 可解释的召回日志

每个最终展示的物品至少记录：request_id、user / query version、召回通道、原始相似度、过滤原因、各阶段 rank、模型 / 索引版本与展示位置。出现“为什么给我推荐这个？”时，日志比重新猜测当时的在线状态可靠得多。

九、总结

9.1 关键技术栈

层级 技术 工具
Embedding BGE, E5 Sentence-Transformers
向量检索 HNSW, IVF FAISS, Milvus
排序模型 DNN PyTorch
在线服务 缓存 Redis, Kafka

9.2 最佳实践

  1. 召回多样化：双塔只是一路，需结合规则、热门、内容和探索通道。
  2. ANN 必须实测：按精确搜索对照调索引，不用规模经验代替 Recall / P95 数据。
  3. 实时更新要版本化：向量、索引、缓存和删除语义必须一致。
  4. 冷启动是产品问题也是模型问题：内容特征、热门兜底、探索和反馈采集要配合。
  5. 评估体系贯穿离线到线上：既看相关性，也看体验、延迟、安全与长期留存。
