专栏定位

本专栏系统介绍 Embedding 模型的核心技术：从数学原理、训练目标到检索与推荐的线上系统。它不把 Embedding 当作“调用一个 API 得到数组”，而是把它视为一个可设计、可评估、可迭代的信息检索组件。

读完后，你应该能回答四个实际问题：

  • 为什么两个模型都能输出向量，检索效果却可能相差很大？
  • 如何把业务中的 query、文档、点击或问答对转成可靠的训练数据？
  • 什么时候该用双编码器、重排序器、稀疏检索或它们的组合？
  • 当 RAG 回答不准时，怎样区分是切分、召回、排序还是生成环节出了问题？

什么是 Embedding？

**Embedding（嵌入）**是将高维稀疏数据（如文本、图像）映射到低维稠密向量空间的技术。核心思想：语义相似的对象在向量空间中距离接近。

一条贯穿全专栏的工程主线

这里有一个容易被忽略的原则：模型排行榜只能帮助缩小候选范围，不能替代自己的评测集。 文档长度、语言、领域术语、相关性的业务定义和延迟预算，都会改变“最佳模型”的答案。第 03 篇因此侧重选型维度与评测协议，而不是把某一天的分数当作永久结论。

术语速查

术语 一句话解释 常见误区
双编码器（Bi-encoder） query 与文档独立编码，可预先建库 快不代表自动理解细粒度关系
交叉编码器（Cross-encoder） query 与文档一起输入并充分交互 精度高，但不适合全库逐条打分
ANN 用近似搜索换取低延迟 索引参数会影响召回，不能只测模型
Hard negative 看似相关、实际不应命中的样本 可能含漏标正例，必须抽检
Recall@K 正确结果是否进入前 K 个候选 高 Recall 不等于最终答案一定好
NDCG@K 同时考虑位置和多级相关性 需要可靠的相关性标注
