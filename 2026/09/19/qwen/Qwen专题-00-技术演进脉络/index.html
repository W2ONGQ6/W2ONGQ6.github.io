引子：为什么需要从“家族”理解 Qwen

只看版本号，会把 Qwen 的发展理解成“1 → 2 → 3”；只看排行榜，又容易把 Math、Coder、VL 和 Omni 当作相互独立的产品。更有解释力的视角是：Qwen 持续把数据生成、能力训练、架构效率和实际应用连接起来。

例如，Qwen3 技术报告明确写到使用 Qwen2.5-VL 提取 PDF 文本，使用 Math 和 Coder 分支生成领域数据。专用模型因此既是成果，也成为下一代基础模型的数据工具。本篇围绕这种联系建立阅读框架，具体论文请从全景指南进入。

一、先区分三种“演进”

层次 发生了什么变化 典型例子 需要什么证据
基座演进 数据、结构、训练目标发生变化 Qwen2.5 → Qwen3；Qwen3 → Next 技术报告、模型配置
能力分化 共同基座接受任务专门训练 Math、Coder、Embedding 任务数据、后训练流程、领域评测
系统演进 模型接入工具、检索和交互管线 Qwen-Agent、Qwen Code、语音系统 执行框架、接口、端到端评测

这三层并不一一对应。更强的后训练版本可能沿用原架构；更好的智能体结果可能来自模型与工具框架的共同改进；增加视觉输入则需要读取模型与处理器的完整配置。

二、2023：建立语言、视觉和音频的共同起点

Qwen Technical Report

  • 论文：2309.16609，首发于 2023-09-28。
  • 作者 / 机构：Jinze Bai 等，Qwen 团队、阿里巴巴。
  • 模型发布：首批 Qwen-7B / Chat 于 2023 年 8 月发布，后续补充更多尺寸。

简介。 初代 Qwen 同时讨论预训练基座、经过人类对齐的聊天模型，以及代码、数学、工具使用等能力。它从一开始就面向“可继续训练的模型 + 可交互的助手”两类用途。

核心创新与实践重点。 多语言语料、稳定训练和面向中文的能力建设构成基础；SFT 与 RLHF 将续写能力转化为对话行为；工具调用使模型可以请求外部计算，而不只依赖参数中的知识。

同年的 Qwen-VL 将视觉特征与语言模型连接，支持图像问答、文字读取和定位；Qwen-Audio 则把语音、环境声、音乐等多任务纳入音频语言训练。两者使输入形式扩展，但不意味着早期文本基座天然就能接收像素或波形。

代表意义。 早期已经形成后续长期保留的结构：语言模型提供推理与生成骨架，各模态通过自己的编码、对齐和训练进入系统。

三、2024：多尺寸基座与专用模型相互促进

1. Qwen1.5 与 Qwen2：可用性也是技术路线的一部分

Qwen1.5 扩展尺寸与框架适配；Qwen1.5-MoE 探索把稠密模型已有知识迁移到稀疏专家结构。到了 Qwen2，开放模型同时覆盖稠密和 MoE，语言覆盖与长上下文能力进一步加强。

尺寸矩阵的价值不只在“有更多型号”。小模型适合本地推理、分类和低延迟任务，大模型可作为高质量生成器或蒸馏教师。研究者也能在相近接口下比较规模、训练方式和部署成本。

2. Qwen2.5：更多数据，更完整的后训练

Qwen2.5 技术报告 给出的变化包括：预训练数据由 7T 增至 18T token、超过百万条 SFT 样本以及多阶段强化学习。结果不只体现为数学或知识题分数，也体现在结构化输出、长文生成和指令遵循。

这些能力常常决定实际可用性。例如，一个模型即使能解释 JSON，也可能在要求“只返回 JSON”时添加说明文字；下游解析就会失败。后训练需要把“知道格式”进一步变成“稳定服从格式约束”。

3. Math、Coder、VL：为通用能力建立专门训练场

数学有可验证的答案，代码有编译器与测试，视觉文档含有网页语料缺少的表格、图示和版式。这些分支提供了三种互补的信号：结果反馈、执行反馈与新数据来源。

专用训练仍有取舍：数学指令模型未必适合开放聊天；代码测试不能覆盖全部业务语义；文档抽取若未经过质量控制，还会把 OCR 错误带入预训练数据。它们的作用需要结合过滤与验证理解。

四、2025 上半年：推理成为可调节的计算过程

从 QwQ 到 Qwen3

QwQ-32B 官方发布介绍了从冷启动 checkpoint 出发、利用数学答案验证和代码执行奖励扩大强化学习的方法。这里的重点是：训练反馈可以部分自动化，模型能够在回答前进行更长的推导和检查。

这四步分别回答：模型如何形成推理输出模式、怎样提高解题能力、怎样兼顾快速回答，以及怎样恢复和提升综合助手能力。小尺寸模型还采用强到弱蒸馏，不能假设每个模型都独立完整地跑了相同流程。

为什么“统一”之后又出现分开的版本

2025 年 7 月的 Qwen3 更新将 Instruct 与 Thinking 分开发布。这反映了不同部署需求：有的应用需要稳定的直接回答和延迟，有的愿意为复杂推理提供更大输出预算。

因此，统一模式与专用模式可以并存。它们分别优化切换便利性与特定运行方式，并不是版本命名中天然保持不变的约定。

五、2025 下半年：降低长上下文成本，扩展交互范围

Qwen3-Next：两类瓶颈分别处理

Qwen3-Next-80B-A3B 模型卡公开了 80B 总参数、约 3B 激活参数的混合结构。MoE 减少每 token 的专家计算，Gated DeltaNet 与门控注意力交替处理长上下文。

这个变化很适合从实际工作负载理解：当输入是一整个仓库或长文档时，仅减少前馈网络计算并不能消除注意力缓存和预填充成本；架构需要同时处理序列长度造成的开销。

多模态：从“读懂输入”走向可操作的输出

Qwen3-VL 继续改善细粒度视觉特征与视频时间表示；Qwen3-Omni 支持多模态输入以及文本和语音输出；Qwen-Image 提供图像生成与编辑。它们解决不同问题，不是一个 Omni checkpoint 就能覆盖全部输出方式。

Image-Layered 更进一步，将一张图像分解成 RGBA 图层。这里能力提升来自输出表示的变化：图层可以独立移动、缩放和合成，给后续编辑提供结构，而不只是生成更好看的平面图片。

六、2026：原生多模态与长任务执行

Qwen3.5-397B-A17B 模型卡将其列为带视觉编码器的因果语言模型，强调视觉语言早期融合、混合注意力和稀疏 MoE。它代表视觉能力更深入地进入共同训练体系。

根据官方仓库发布记录，Qwen3.6 进一步关注编码工作流和跨轮思考保留，Qwen3.8 关注编程、专业工作与长任务智能体执行。开放的 Qwen3.8-2.4T-A95B公开了混合结构和参数配置；关于训练配方的讨论应停留在公开资料能够支持的范围内。

一个实际含义是：评测单轮回答已经不够。面对“修改功能并验证”的任务，系统需要记住约束、读取已有文件、理解工具报错、修复错误并确认结果。能力来自模型、上下文管理和执行环境的共同作用。

七、用五个问题阅读后续每一篇

  1. 能力从哪里来？ 预训练知识、专用数据、蒸馏、奖励，还是工具提供的信息？
  2. 成本发生在哪里？ 权重、KV Cache、专家通信、视觉 token，还是交互轮数？
  3. 反馈是否可信？ 最终答案、测试用例或偏好评分覆盖了哪些目标？
  4. 版本边界在哪里？ Base、Instruct、Thinking、量化和托管版本是否一致？
  5. 如何在自己的任务上验证？ 用正确率之外的延迟、成功率与失败类型补足判断。
