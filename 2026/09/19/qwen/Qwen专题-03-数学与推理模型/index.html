核心问题：更多思考怎样变成更可靠的答案

推理模型的特点不只是回答更长。Qwen 的相关工作涉及三种相互连接的机制：用高质量数学数据建立能力，用可验证结果训练回答策略，以及在推理时分配更多计算或调用工具。

本篇沿 Qwen2.5-Math → QwQ → Qwen3 后训练展开。需要始终区分：生成推导、执行验证和形式化证明并不是同一件事。

一、四种提高解题质量的方式

方法 增加了什么 反馈来自哪里 主要代价
CoT 显式的中间推导 训练示例或结果奖励 输出更长，中间仍可能出错
TIR 程序与外部计算 执行器返回结果 工具环境、调用与错误恢复
Best-of-N 多个候选解 投票、验证器或奖励模型 多次采样与筛选成本
推理 RL 调整模型的解题策略 正确答案、测试或其他奖励 训练 rollout 和验证成本

它们可以结合，但评测时必须注明组合。例如带 Python 执行器的 TIR 结果不能直接当成纯模型单次回答的正确率。

二、Qwen2.5-Math：贯穿训练与推理的自我改进

  • 论文：Qwen2.5-Math Technical Report: Toward Mathematical Expert Model via Self-Improvement，2024-09-18 首发。
  • 作者 / 机构：An Yang 等，Qwen 团队、阿里巴巴。
  • 模型：1.5B、7B、72B 的 Base / Instruct，以及 Qwen2.5-Math-RM-72B 奖励模型。
  • 实现：Qwen2.5-Math 官方仓库。

简介

相比主要面向英文 CoT 的 Qwen2-Math，Qwen2.5-Math 扩展到中英文数学与工具辅助推理。报告的核心是把“生成候选 → 评价质量 → 改进数据和模型”贯穿预训练、后训练与推理。

核心创新一：数据生成与筛选形成迭代

预训练阶段利用已有数学模型生成数据；后训练阶段通过大量采样训练奖励模型，再用奖励模型筛选 SFT 数据。改进后的 SFT 模型可以产生更高质量的候选，继续帮助更新奖励模型，并最终用于强化学习。

这并非凭空产生可靠知识。迭代能否改进，取决于任务的答案、验证方式以及奖励模型是否有足够区分力。如果生成器和评分器共享同一种错误，重复筛选也可能强化错误。

核心创新二：Tool-Integrated Reasoning

TIR 将语言推理与程序执行交织起来。例如求一个高次多项式的实根时，模型先建立方程，再调用计算工具求候选值，最后代回检查约束。外部计算承担精确数值或符号处理，语言模型承担问题分解与结果解释。

只有模型生成了程序而没有执行器，流程就不完整；程序输出也不能未经检查直接作为答案，尤其要注意单位、定义域和数值误差。

核心创新三：推理时使用奖励模型筛选

奖励模型可以从多个候选中选择更有希望的答案。它提高的是特定采样与筛选预算下的系统表现，不能据此说基础生成分布的单次正确率获得了同等提升。

代表意义

Math 分支展示了专用数据和验证反馈如何互相促进，同时成为后续通用模型的领域数据来源。官方也明确表示该系列主要用于中英文数学任务，不建议把它直接当作通用助手。

三、QwQ-32B：扩大结果奖励驱动的强化学习

  • 官方发布：QwQ-32B: Embracing the Power of Reinforcement Learning，2025-03-06。
  • 作者 / 机构：Qwen Team，阿里巴巴。
  • 实现与评测：QwQ 官方仓库。
  • 版本区别：QwQ-32B-Preview 是 2024 年的探索版本，不能与正式 QwQ-32B 混用结论。

简介

QwQ-32B 建立在 Qwen2.5 系列基础上，是专门面向推理的稠密模型。公告描述了从冷启动 checkpoint 出发，使用结果奖励扩大强化学习的流程。

核心创新

第一阶段：数学和代码的可验证奖励。 数学使用答案准确性验证，代码使用执行服务器与预定义测试。相比只让奖励模型评价一段文字“看上去是否合理”，这些反馈能更直接地约束一部分任务结果。

第二阶段：补充通用能力。 在数学和代码之后，使用通用奖励模型和规则验证器进一步训练，改善指令遵循、人类偏好与智能体能力。专项能力与综合可用性因此需要分别优化。

与环境交互。 代码执行或工具返回结果可以改变接下来的推理方向。这里模型学到的不只是静态解题文本，也包括依据反馈修正行动。

代表意义与边界

QwQ 展示了中等规模稠密模型配合强化学习的潜力。官方与更大模型的比较是指定基准与预算下的比较，不意味着全部能力、训练成本和延迟都相等。公开公告没有披露的完整优化器、数据量或奖励权重，不能从其他模型训练配方中补齐。

运行时应遵循 QwQ 自己的采样建议，避免直接照搬普通聊天模型的贪心解码。官方文档特别提示重复输出与较长思考带来的问题；应用应观察最终答案是否真的产生，而不是只统计输出 token 数。

四、Qwen3：把深度推理与快速回答组合起来

  • 论文：Qwen3 Technical Report，2025 年 5 月，An Yang 等。
  • 范围：以下四阶段描述针对 Qwen3 首发旗舰模型的后训练流程。

阶段一：Long-CoT Cold Start

使用带可靠答案或代码测试的题目，构建经过筛选的长推理示例，让模型先学会推理回答的基本模式。冷启动不是单纯增加输出长度，而是提供可学习且质量可控的起点。

阶段二：Reasoning RL

在数学、代码等任务上继续强化学习，以结果反馈提高解决难题的能力。可靠的验证可以缩小“表达流畅但答案错误”的空间，不过奖励仍然只覆盖它能检查的目标。

阶段三：Thinking Mode Fusion

将带推理路径与直接回答的数据混合做 SFT，并设计聊天模板，使同一模型支持两种回答方式。这样，查询简单事实时可以直接输出，处理复杂约束时可以分配更长的推理预算。

阶段四：General RL

继续优化广泛任务的助手能力。报告中的阶段对比也观察到某些高难度推理任务存在回落，说明通用性与专项峰值之间可能发生权衡。“最后阶段更多”并不意味着每一个指标单调上升。

较小模型：Strong-to-Weak Distillation

小模型使用教师生成数据与在策略蒸馏传递推理、直接回答和模式切换能力。不能把旗舰模型的完整后训练过程视为所有小尺寸 checkpoint 的实际训练日志。

如果只设置很小的 max_new_tokens，模型可能在思考尚未结束时被截断，最终答案根本没有生成。Qwen3 报告中的预算控制会在达到思考阈值时插入停止思考指令，再让模型基于已有推理回答；这与直接截断整段输出不同。

应用要留出最终回答预算，并检测结束原因。对于用户请求严格 JSON 的场景，还应明确哪些字段是内部推理，哪些字段才是可解析的最终内容。

六、版本与控制方式对照

模型版本 思考行为 使用时注意
QwQ-32B 推理专用 按 QwQ 模板和采样建议运行
Qwen3 首发（2504） 支持两种模式 enable_thinking 是模板控制；软指令需结合模板理解
Qwen3-Instruct-2507 仅非思考模式 不需要再传 enable_thinking=False
Qwen3-Thinking-2507 仅思考模式 应提供充分生成预算
Qwen3-Next / Coder-Next 按具体 checkpoint 区分 Coder-Next 模型卡明确列为非思考模式
Qwen3.8 官方列出 reasoning_effort、preserve_thinking 核对模型卡、服务与聊天模板是否支持相应参数

资料入口：Qwen3 官方仓库、Coder-Next 模型卡、Qwen3.8 官方仓库。不同代际对历史推理的保留方式也会变化，不能统一删除或统一回传。

七、怎样评估“更会推理”

建立固定题集后，同时记录答案正确率、最终答案缺失率、平均输出长度、工具调用次数与总耗时。对数学题检查答案提取规则，对代码题检查测试覆盖，对开放分析题检查引用证据。

单次采样、多次投票和奖励模型筛选应单独报告。长链推导可能包含错误推理后碰巧得到正确结果；若任务要求严格证明，就需要证明检查器或专家审查，而不是只接受一个正确的数字。
