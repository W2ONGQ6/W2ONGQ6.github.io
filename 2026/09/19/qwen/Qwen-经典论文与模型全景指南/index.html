Qwen 经典论文与模型全景指南（2023–2026）

从通义千问到模型家族：先建立一张地图

Qwen（通义千问）并不是一个不断增大参数量的单一模型。它同时包含通用语言模型、数学与代码模型、视觉语言模型、音频与全模态模型、图像生成模型，以及用于检索的 Embedding 和 Reranker。理解这个家族，关键在于看清：哪些能力来自共同基座，哪些来自专门训练，哪些又反过来推动下一代基座。

本专栏参考 DeepSeek 专栏的组织方式，以“技术演进 + 分方向精读”串联代表性论文、官方技术报告和开放权重模型。每篇围绕问题背景、核心机制、代表意义和工程取舍展开，适合从入门阅读逐步走向论文与实现。

阅读范围：覆盖 2023 年初代 Qwen 至 2026 年公开资料中的代表性路线，资料核对日期为 2026-09-19。本文是技术选读目录，不宣称穷尽全部模型、API 产品和版本。论文首发时间、权重发布时间与后续更新会分别说明；仅有公告的版本不补写未公开的训练细节。

二、先读懂命名，再比较模型

同一个“Qwen”前缀，不代表相同架构、训练目标或输入输出接口。

名称片段 含义 容易混淆的地方
Base / 无 Instruct 后缀的基座 主要学习序列预测，适合继续训练或特定评测 不能默认按聊天助手使用；具体仍看模型卡
Chat / Instruct 做过对话或指令后训练 不保证每个版本都有可切换的思考模式
235B-A22B 名义总参数约 235B，每 token 激活约 22B 显存不能只按 22B 权重估算
2507、2512 版本标识，通常对应年/月 同一代不同日期版本可能更换上下文和模板行为
Thinking 为显式推理优化的版本 不等于所有任务都更快或更准确
VL / Omni 视觉语言 / 多模态交互分支 VL 不自动具备音频生成；Omni 也不等于任意模态输出
Embedding / Reranker 向量表征 / 候选相关性排序 不是用于直接回答问题的聊天模型
Image / Image-Edit 图像生成 / 图像编辑 不能用普通文本生成接口替代专用图像管线

一个特别重要的版本差异是：2025 年 4 月的 Qwen3 支持思考与非思考切换；Qwen3-2507 的 Instruct 和 Thinking 是分开的模型。 后来的 Next、Coder 和 3.8 还需检查各自模型卡，不能统一套用一段提示模板。

三、按能力演进看时间线

下表中的日期以权重或官方发布为主；论文报告可能晚于发布。每个技术专题另列论文日期。

阶段 代表事件 技术重心
2023.08–11 Qwen-7B、Qwen-VL、Qwen-Audio；后续补齐更大与更小尺寸 语言基座、对话对齐和多模态分支起步
2024.02–06 Qwen1.5、Qwen1.5-MoE、Qwen2 多尺寸生态、稀疏专家、多语言和 GQA
2024.08–11 Qwen2-VL、Qwen2.5、Math / Coder、QwQ-32B-Preview 专用数据、动态分辨率和推理探索
2025.01–04 Qwen2.5-VL / Omni、QwQ-32B、Qwen3 可验证奖励、端到端交互、思考模式融合
2025.06–09 Embedding / Reranker、Qwen3-2507 / Coder、Image、Next、Qwen3-Omni / VL 检索、代码执行、图像生成与混合注意力
2025.12–2026.02 Image-Layered、Qwen3-ASR / TTS、Coder-Next、Qwen3.5 可编辑表示、专用语音、原生视觉语言基座
2026.04–08 Qwen3.6、Qwen3.8 开放模型 编码智能体、长任务执行和跨轮推理控制

2026 年的更新依据 Qwen 官方仓库、各分支仓库和模型卡记录。尤其要区分 开放权重模型与托管服务：例如 Qwen3.8-2.4T-A95B 模型卡将开放模型列为因果语言模型，而托管的 Qwen3.8-Max 另提供视觉输入等功能，不能直接画等号。

四、四条贯穿全系列的技术主线

1. 数据与能力互相促进

Qwen2.5 报告将预训练数据规模从 Qwen2 的 7T token 扩展到 18T；Qwen3 报告进一步给出 36T token。扩张不只是收集更多网页：代码和数学模型参与合成数据，视觉模型用于提取文档文本，新的基座再支撑更强的专用模型。数据质量、分布和验证机制与规模同样重要。

2. 分别优化“模型有多大”和“上下文有多长”

MoE 让单个 token 只经过部分专家，降低前馈网络计算；GQA 减少 KV 头数；Qwen3-Next 将 Gated DeltaNet 与门控注意力混合，减少部分层对完整历史 KV 的依赖。三者处理不同瓶颈，不能把激活比例直接当作吞吐提升倍数。

3. 从生成答案走向与环境交互

Math 的工具辅助推理、QwQ 的结果验证、Coder 的代码执行以及视觉模型的界面操作，都把“输出是否合理”转化为部分可检查的反馈。反馈可靠性决定了训练和部署的上限：测试通过可能只是覆盖了部分情况，正确的最终答案也不意味着每一步证明都成立。

4. 多模态能力逐渐进入共同基座

早期 VL 和 Audio 主要通过专门分支引入新输入。Omni 进一步处理音视频时间对齐和语音输出；Qwen3.5 的官方材料则强调视觉语言早期融合训练。与此同时，Image、ASR、TTS 等仍保留专门结构与目标，不能把整个家族想象成一套通用权重。

五、建议的阅读路线

  • 第一次系统了解 Qwen：00 → 01 → 03，再按兴趣进入视觉、音频或代码分支。
  • 关注推理系统与显存成本：01 → 02 → 08，重点看总参数、激活参数、KV Cache 和真实负载。
  • 准备做代码智能体：03 → 04 → 08，先理解反馈训练，再建立工具执行与评测闭环。
  • 准备做文档或音视频产品：05 → 06 → 08；需要生成海报、编辑图像时补读 07。

六、如何使用本专栏的证据

每篇的“简介、核心创新、代表意义”尽量对应官方报告；机制示例和工程建议则作为解释与实践推导给出。涉及数据规模、专家数量和上下文长度时，会注明具体版本。

阅读性能表时，至少对齐模型版本、思考模式、输入输出长度、采样次数、工具与评测框架。本文不把不同条件下的榜单拼成统一排名，也不把“开放权重”理解成训练数据、训练代码和所有 API 能力都已公开。

论文入口以 arXiv 原文为主；部署参数以目标 checkpoint 的模型卡为准。代码示例用于展示接口与流程，运行仍需对应依赖、模型权重与硬件。
