核心问题：通用模型的能力如何积累

Qwen 的基础模型路线同时推进三件事：扩大高质量训练数据、让不同规模的模型稳定训练，以及把序列预测能力转化成可用的助手行为。架构决定计算方式，数据决定模型接触什么，后训练决定它如何使用学到的能力。

本篇依次阅读 Qwen、Qwen2、Qwen2.5 和 Qwen3 技术报告，并把没有独立同名报告的 Qwen1.5 作为产品与工程演进节点。MoE、推理和多模态细节分别放到后续专题。

一、代际对照：规模只是其中一个维度

版本 报告或发布节点 公开资料中的训练规模 值得关注的变化
Qwen 报告首发 2023.09；模型自 2023.08 发布 后续官方仓库记录部分型号达到 3T token 中文与多语言基础、Chat 对齐、工具使用
Qwen1.5 2024.02 发布；MoE 于 2024.03 发布 本文不填写跨型号统一数值 多尺寸、框架兼容、稀疏专家探索
Qwen2 2024.06 发布，报告首发 2024.07 7T token，见后续 Qwen2.5 报告回顾 GQA、多语言、稠密与 MoE 并行
Qwen2.5 2024.09 发布，报告首发 2024.12 18T token 数据质量、长文、结构化输出、多阶段后训练
Qwen3 2025.04 发布，报告首发 2025.05 36T token 119 种语言与方言、模式融合、强到弱蒸馏

这些数字描述相应报告的训练数据规模，不是所有衍生型号、后续版本都使用完全相同语料的承诺。不同 tokenizer、重复训练策略和计算配置，也会影响 token 数之间的可比性。

二、Qwen Technical Report：构建基础与对齐两层能力

  • 论文：Qwen Technical Report，2023-09-28 首发。
  • 作者 / 机构：Jinze Bai 等，Qwen 团队、阿里巴巴。
  • 配套实现与版本记录：Qwen 官方仓库。

简介

报告将预训练语言模型 Qwen 与面向交互的 Qwen-Chat 分开描述。前者学习广泛文本中的规律，后者通过指令示范和人类对齐学习如何回答问题、遵循要求和使用工具。

核心创新与技术要点

第一，语言覆盖需要落实到分词与语料。 对中文等语言而言，如果一个常用表达被切成过多 token，相同内容会占用更长序列。分词效率会影响训练数据的有效覆盖，也影响推理费用。词表更大同时增加嵌入与输出层参数，不能只追求最少 token。

第二，基础模型与聊天模型服务不同目标。 预训练的下一个 token 预测目标并不天然要求模型遵守角色边界、简洁回答或按指定格式输出。SFT 用示例约束行为，RLHF 利用偏好反馈进一步调整回答分布。

第三，工具使用需要数据中的交互结构。 模型必须理解何时发起调用、怎样组织参数，以及如何继续处理返回结果。让模型看到某个函数的名字，并不等于它已经学会稳定使用函数。

代表意义与边界

初代 Qwen 为后续系列建立了“基础模型 → 对话对齐 → 专项能力”的组织方式。实际复现要注意早期模型依赖自定义代码与不同许可证；不能把 Qwen3 的加载方式和授权说明直接回填给初代权重。

三、Qwen1.5 与 Qwen2：从单个模型到可选择的基座

  • Qwen1.5 发布：2024-02，见 Qwen 系列官方发布记录。
  • 论文：Qwen2 Technical Report，2024-07-15 首发。
  • 作者 / 机构：An Yang 等，Qwen 团队、阿里巴巴。

简介

Qwen1.5 强化模型尺寸与使用生态；Qwen2 则公开了稠密与 MoE 并行的模型矩阵。对开发者而言，共同接口下的多个尺寸意味着可以根据算力、延迟和质量要求选择起点。

核心创新与技术要点

GQA 改变了注意力缓存的成本。 多个 Query 头共用更少的 Key / Value 头，因此可以减少 KV Cache。它保留不同 Query 的查询能力，同时压缩缓存与部分访存开销。GQA 并不使完整注意力的长序列预填充成本变成线性。

多语言能力需要跨语言的数据工程。 语种覆盖数字只表明训练范围，不能保证每种语言质量一致。清洗、去重、语言识别、领域平衡以及后训练指令覆盖，都会影响最终体验。

长上下文不是一个独立开关。 位置表示扩展、长序列训练和评测需要协同进行。能在长输入中找出一句话，和能综合整篇文档中的分散证据，是不同能力。

代表意义

Qwen2 的价值在于可作为多种专用训练的基础，而不只是一款聊天产品。评估时要分开 Base 与 Instruct，不能把基座的 few-shot 测试分数与聊天模型的直接回答结果混成同一条曲线。

四、Qwen2.5：数据与后训练共同推动可用性

  • 论文：Qwen2.5 Technical Report，2024-12-19 首发。
  • 作者 / 机构：An Yang 等，Qwen 团队、阿里巴巴。
  • 开放模型：0.5B、1.5B、3B、7B、14B、32B、72B 等稠密型号；报告中的托管 MoE 产品另行区分。

简介

Qwen2.5 把预训练规模扩大到 18T token，并通过超过百万条 SFT 样本和多阶段强化学习提升综合助手能力。报告特别关注长文生成、结构化数据分析和指令遵循。

核心创新与技术要点

数据规模扩展必须伴随质量控制。 去重减少记忆性重复，过滤降低低质量内容比例，数据混合决定语言与专业知识的学习分配。合成数据可以补足稀缺任务，但错误、单一风格和教师偏差也可能被放大。

后训练优化的是一组相互牵制的目标。 一个答案可以事实正确但格式错误，也可以很符合用户偏好却缺少依据。SFT 提供行为起点，强化学习继续调整候选回答的偏好，而不是把所有目标压成简单的“更长更好”。

开放稠密模型与托管 MoE 不是同一套配置。 Qwen2.5 报告同时介绍了开放权重与 Turbo / Plus 等托管型号。把报告中的 MoE 描述套到 Qwen2.5-7B-Instruct 等开放稠密模型，会导致结构和显存估计错误。

代表意义

Qwen2.5 支撑了 Math、Coder、QwQ 和多模态分支，说明强基座可以降低专项训练的起点成本。但这种关联不意味着所有分支都只进行了简单 SFT：代码继续预训练、视觉对齐、音频编码等仍需要专门设计。

五、Qwen3：领域数据反哺基座，推理能力走向小模型

  • 论文：Qwen3 Technical Report，2025 年 5 月首发。
  • 作者 / 机构：An Yang 等，Qwen 团队、阿里巴巴。
  • 首发矩阵：稠密 0.6B / 1.7B / 4B / 8B / 14B / 32B；MoE 30B-A3B / 235B-A22B。

简介

Qwen3 将预训练数据扩大到 36T token，覆盖 119 种语言与方言，并在首发系列中支持思考与非思考模式。相比只强调大模型峰值，它也关注如何把能力传递给可部署的小模型。

核心创新一：三个预训练阶段各有目的

报告描述的预训练路线为：大规模通用知识学习 → 加强 STEM、代码等高知识密度内容 → 长上下文训练。其长序列阶段将训练序列从 4,096 扩展至 32,768 token；实际 checkpoint 的配置与进一步外推长度需另查模型卡。

这种课程安排可以理解为：先建立广泛的表达与知识基础，再强化更复杂的分布，最后为长距离依赖提供训练机会。它不意味着早期阶段“没有数学”，而是训练配比与重点发生变化。

核心创新二：使用已有模型构建更好的训练数据

报告明确提到，Qwen2.5-VL 用于从 PDF 提取文本，Math 与 Coder 模型用于合成领域数据。这使模型家族形成迭代关系：专用模型帮助获得更难获取、更可验证的内容，通用基座再吸收这些数据。

例如，PDF 中的公式和表格若被简单按字符顺序拼接，逻辑关系可能丢失。视觉模型可以改善抽取，但仍应通过版面检查、符号校验或抽样复核，判断数据是否适合进入训练。

核心创新三：强到弱蒸馏

Qwen3 对较小模型使用离策略和在策略蒸馏。前者学习教师生成的回答；后者让学生在自己的生成分布上获得教师信号，从而减少“训练时只见过教师路径，推理时却走入陌生状态”的差距。

论文中的对比显示蒸馏在其设定下具有训练效率优势。这是特定教师、学生与任务上的结果，不能推广成“蒸馏永远比强化学习更好”。

代表意义与后续边界

Qwen3 将高质量领域数据、多尺寸架构和推理后训练结合起来。后续 Qwen3-2507 改成分别提供 Instruct / Thinking；Qwen3.5 又进入原生视觉语言路线。因此，“Qwen3”相关经验在迁移到新型号时，至少要重新核对输入模态、模板和运行依赖。

六、如何判断一次基座升级是否适合自己

不要只拿一组公开数学题做决策。可以建立一个小而固定的业务评测集，覆盖知识问答、结构化抽取、长文证据综合、中文表达和拒绝无依据推断等任务，并记录以下结果：

维度 推荐观察量 能发现的问题
内容质量 正确率、证据覆盖、人工偏好 知识缺失或回答偏移
指令遵循 JSON 解析率、字段完整率 有知识但输出不可用
长上下文 不同位置证据的召回与综合 只会局部检索、遗漏中间信息
运行成本 首 token 延迟、总耗时、峰值显存 更强模型超出资源预算
稳定性 重复采样失败率、异常输出类型 偶尔成功掩盖不稳定行为

固定模型 revision、推理模板、采样参数和预算后，升级结果才可解释。下一篇进一步分析架构怎样影响这些运行成本。
