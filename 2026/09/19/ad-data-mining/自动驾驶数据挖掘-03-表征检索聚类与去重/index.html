自动驾驶数据挖掘-03：表征检索聚类与去重

一、为什么规则之后还需要检索

规则适合定义明确的信号，却难穷尽施工设施外观、光照与遮挡组合。表征检索将图像、对象或片段转成向量，使用户能从文本、示例图片或已知失败片段寻找相似数据。

相似的定义需要与任务一致。两张都很暗的图片在视觉上相近，但只有一张包含改道冲突；单靠整图相似度容易找到“长得像”，却没找到“问题相同”。

二、先设计表征层级

层级 表达能力 建议保留的补充信息
整帧图像 环境、整体外观 相机视角、时间、位置
对象裁剪 局部外观与类别 3D 距离、可见性、轨迹 ID
多帧片段 动作与场景演化 帧采样规则与时间戳
交互图 自车与其他对象关系 坐标、速度、优先权或道路拓扑

可以先用结构化字段筛选“夜间 + 候选改道”，再在向量空间搜索施工设施或特定遮挡模式。这比在全库只做一次文本向量检索更容易解释。

三、CLIP 与 DINOv2 各提供什么

CLIP：文本与图像的共同检索空间

Learning Transferable Visual Models From Natural Language Supervision研究通过图文配对训练获得可迁移的视觉语言表示。对数据挖掘，它提供“输入自然语言，查找相关图片”的基础。

例如“夜间道路上施工锥引导车辆绕行”可以作为初始查询，但文本描述中的动作、否定和细粒度位置关系未必都被准确编码。应人工检查前列结果，拆分过长查询，必要时加入正负示例。

DINOv2：以视觉特征寻找相似内容

DINOv2: Learning Robust Visual Features without Supervision研究通用视觉特征及数据整理。它适合以图搜图、聚类或寻找外观变化，但没有天然保证任意文本都与其特征处于同一空间。

两类论文提供的是表征基础，不能据此直接宣称道路长尾召回率达到某个数值。模型、采样和索引方式都需在驾驶数据上重新验证。

四、相似度、索引和重排

对已归一化的向量，可以使用内积：

大库通常通过近似近邻索引获得候选，再用较精细的片段模型、时序条件或人工规则重排。索引加速改变了近邻搜索的近似程度，需要与精确搜索比较召回和延迟。

记录 encoder checkpoint、输入分辨率、归一化方式、向量维度和索引版本。更换 encoder 后，旧文档向量与新查询向量通常不能直接混用。

五、聚类用于覆盖，不等于发现了新场景

聚类可以把大量相似内容归组，帮助观察数据分布并从每组挑代表。但聚类结果受特征、距离、簇数和数据密度影响，“新簇”可能来自镜头脏污、不同车型或图像压缩变化。

检查聚类时，需要同时看每簇的样例、元数据分布、道路与行程来源，以及与目标失败的关系。低密度点既可能是有价值长尾，也可能是损坏数据。

对于已知问题，可以在聚类后按路段、天气、遮挡和对象尺度分层选取。不要默认每个簇配额相同就是最佳训练分布。

六、分三层处理重复

  1. 字节级重复：同一文件或上传重试，可使用内容哈希识别。
  2. 时间与事件重复：同一 episode 的重叠片段或邻帧，需要依据时间区间与行程信息合并。
  3. 语义近重复：不同时间采集但内容高度相近，可在向量空间形成重复组，再结合任务保留代表。

去重不能过度：同一路口晴天与暴雨、遮挡前与遮挡后，可能正是重要变化。被折叠的成员清单应该保留，便于重新检查和估计实际曝光。

训练 / 验证 / 测试的隔离应在 episode、路线等较高层级处理，不能先随机分帧再去重。

七、把一次检索变成可审核的任务

为施工案例记录查询文本、正负示例、过滤条件、检索模型、候选 Top-K、重排版本和人工命中判断。复核重点包括：场景是真施工还是路边常设设施，改道关系是否成立，是否包含模型做出决策前后的记录。

交付给主动学习环节的候选，至少应有语义判断、重复组、可用传感器与质量状态。这样，“相似度很高”才不会被误当成“应该立即标注”。
