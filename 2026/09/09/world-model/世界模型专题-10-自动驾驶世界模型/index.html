引言：驾驶世界模型必须同时回答“看见什么”和“撞不撞”

自动驾驶天然适合世界模型：有海量行车视频，动作和车辆状态可同步记录，规划又需要预演其他交通参与者的反应。但驾驶也是最容易被画质欺骗的领域。一段未来视频即使非常逼真，只要车辆位置偏几十厘米、漏掉一个被遮挡行人，规划结论就可能完全相反。

因此驾驶世界模型并非单一技术路线，而是围绕四种表示竞争：RGB 视频、BEV/3D occupancy、点云与隐式 latent state。它们分别优化可视化、几何安全、传感器预测和规划效率。

本篇建立统一比较框架；已有自动驾驶专栏中的单篇论文细节可作为补充阅读，而不在这里重复堆叠摘要。

二、四种表示空间

2.1 RGB 视频：信息完整、最易检查

GAIA-1、DriveDreamer、Drive-WM、Vista 等根据历史多相机画面和控制生成未来视频。优势是保留纹理、天气、信号灯和长尾对象，可直接用于数据增强与人工审查。

弱点是三维位置隐含在像素中；多相机之间还必须保持同一对象、同一时刻的几何一致。视频质量指标改善，不保证碰撞距离更准。

2.2 BEV/occupancy：直接表达可通行空间

OccWorld 把 3D occupancy 量化为离散 token，再预测未来占据演化。规划器可直接检查轨迹经过的体素是否被占：

这种表示利于碰撞、安全边界和语义几何，但依赖 occupancy 标签或可靠的预训练感知，且体素分辨率与计算成本冲突。

2.3 点云：保留度量几何

ViDAR 从多视角图像预测未来 LiDAR point cloud，Copilot4D 使用离散 diffusion 建模点云序列。点云提供尺度和深度，适合度量评测；但稀疏点对纹理、信号灯状态和遮挡语义表达较弱。

2.4 隐式 latent：最快，但最难审计

DriveWorld、Think2Drive、World4Drive 等让潜状态直接服务预测、RL 或规划，无需把每个未来完整解码。优势是训练和 rollout 高效，可针对任务保留动态结构；风险是 latent omission 难被发现，开环规划分数也可能掩盖真实闭环失败。

三、GAIA-1：驾驶视频成为动作条件世界

GAIA-1 将 video、text 与 action token 放入序列模型，再由 diffusion decoder 生成未来。它展示模型可根据车辆动作改变场景，并在生成中表现道路结构、交通规则和参与者行为。

其里程碑意义不是首个视频预测，而是把规模化真实驾驶数据 + 多模态条件 + action controllability明确包装为 generative world model。此后驾驶世界模型快速分化为三类用途：

  • 生成稀有场景和训练数据；
  • 对候选规划做视觉预演；
  • 作为潜空间 simulator 训练策略。

但日志数据里的动作来自人类司机，严重危险动作很少。模型对于“如果此刻突然猛打方向”通常处于外推状态，这正是安全规划最不能盲信的区域。

五、OccWorld 与 ViDAR：为什么几何空间重要

驾驶安全关心的是未来某位置是否被占，而非像素是否悦目。OccWorld 用 VQ-VAE 压缩 3D occupancy，再由 Transformer 预测未来 token 和自车规划；ViDAR 则从视觉特征出发，以可微渲染方式预测未来点云。

它们代表两种几何监督：

  • occupancy 预测“空间单元是否被占及其语义”；
  • point cloud 预测“未来可由 LiDAR 观测到哪些表面点”。

几何表示仍不是完整世界：交通灯、手势、意图和道路规则难完全塞进占据体素。因此前沿系统常用视觉/VLM 提供语义，用 occupancy/point cloud 提供几何，再让 latent dynamics 或 planner 融合。

六、世界模型作为预训练任务

DriveWorld 不把生成未来本身当终点，而以 4D scene forecasting 预训练 backbone，再迁移到 3D detection、motion prediction 和 planning。逻辑是：能预测未来的表示必须理解哪些对象会动、如何被遮挡以及道路结构怎样持续。

这与 Fast-WAM 的结论呼应：世界建模的收益可能主要来自训练时塑造表示，部署时未必需要完整生成未来。对自动驾驶尤其重要，因为实时预算严格，显式 diffusion rollout 很难在每个规划周期执行多次。

七、Think2Drive：在隐式世界模型里做闭环 RL

Think2Drive 在 CARLA 中用 learned latent world model 训练驾驶策略，把昂贵 simulator 交互转化为更多 latent imagination。它针对的不只是模仿学习误差，而是策略偏离专家轨迹后的恢复：

这条路线的关键审计问题是 simulator-to-model-to-policy 三层差距。若 learned model 没覆盖碰撞前的极端状态，RL 可能学会利用它；若只在 CARLA 验证，也不能直接推出真实道路安全。

因此世界模型内 RL 应结合 uncertainty、真实/高保真回放抽检和 adversarial scenario generation。

八、从开环指标到闭环指标

驾驶论文常用两类评价，但不能混为一谈。

8.1 开环

给定真实历史，预测未来轨迹或场景：

  • trajectory L2/ADE/FDE；
  • collision rate against logged future；
  • occupancy IoU/mIoU；
  • point-cloud Chamfer distance；
  • FID/FVD、视频人评。

问题是 logged future 只对应人类实际采取的一个动作。一个不同但安全的规划可能被判错，一个与日志接近但无法恢复扰动的策略可能得高分。

8.2 闭环

策略动作会改变下一状态，评测持续反馈：

  • route completion / driving score；
  • 碰撞、越线、红灯、舒适度；
    -干预次数与恢复能力；
    -长尾场景和对抗扰动；
    -模型不确定时的降级行为。

闭环更接近部署，却受 simulator realism 影响。最佳实践是开环诊断、闭环 simulator、日志重放和受控真实测试分层组合。

九、驾驶世界模型的核心错觉

9.1 Ego-action causality illusion

模型看似响应方向盘，实际可能只记住训练数据中动作与道路曲率的共现。应在相同初始状态下系统扫过反事实动作。

9.2 Multi-view consistency illusion

各相机单独都逼真，不代表共同对应同一 3D 世界。需要跨视角重投影、对象身份和深度一致性。

9.3 Safety-by-generation illusion

生成未来中没有碰撞，不代表真实执行安全。模型可能直接漏掉障碍或让其他车辆不合理避让。

9.4 Open-loop progress illusion

轨迹 L2 更低不代表闭环更强。策略必须在自己造成的新状态中持续恢复。

小结：驾驶把“世界模型是否有用”变成安全问题

RGB 路线覆盖语义和长尾，occupancy/point cloud 提供可测几何，latent model 提高训练与规划效率。它们没有唯一赢家，更现实的方向是分层组合，并用动作反事实、多视角一致与闭环安全共同验收。

下一篇暂时离开具体领域，建立世界模型的统一评测框架。因为无论是游戏、机器人还是驾驶，最危险的错误都不是画面难看，而是模型对错误行动给出过于自信的好未来。
