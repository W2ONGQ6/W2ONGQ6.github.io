目标：搭一套可训练、可检查的端到端模型

本专题实现的模型由一个共享时序 BEV encoder 和五个任务 head 组成：

obs 在本文中专指动态交通参与者（vehicle / pedestrian / cyclist）的实例级表征；occ 表示体素语义占据；freespace 是面向行驶的二维可通行区域。三者监督不同，不能拿一个二值 BEV mask 混用。

依赖与边界

建议先在 nuScenes 风格的六相机数据上复现，BEV 范围设为 m、 m，分辨率 0.5 m。代码强调接口与训练逻辑，不应直接接管真实车辆；上车前还需要冗余感知、确定性安全约束、功能安全流程与封闭场地验证。

关键参考

  • Lift-Splat-Shoot：显式相机特征视角变换；
  • BEVFormer：时空 BEV 表征；
  • UniAD：规划导向的全栈联合学习；
  • Occ3D：占据预测数据与评测；
  • Flow Matching：条件连续生成的训练目标。

五个模块的发展脉络

模块 经典路线 关键转折 本专题首版
BEV 表征 IPM、LSS、BEVDet BEVFormer 的时空 query；BEVDepth 的深度监督 显式 lift-splat + ego-motion warp
Obs 2D/3D box detector、CenterPoint PETR/StreamPETR 的 3D query 与时序对象记忆 center heatmap + box/velocity regression
Map 栅格分割、HDMapNet VectorMapNet / MapTR 的 vector query 和拓扑 多层 BEV mask，后续可接 vector decoder
Occ 语义场景补全、体素 CNN SurroundOcc、Occ3D、TPVFormer 将环视感知推向 3D 占据 小型稠密 voxel decoder + visibility mask
Planning 规则/MPC、行为克隆 UniAD/VAD 的规划导向联合训练；扩散与 flow matching 的多模态候选 条件 FM 采样 + 约束代价选择

这五项并非简单并列：BEV 提供共享几何坐标；obs/map/occ/freespace 提供不同粒度的场景约束；planning 在这些约束下生成并筛选自车未来。后文每个模块均给出可替换的经典实现路线，而不是把首版代码误当作唯一解。

开始之前

先固定一个原则：每个张量都要有坐标系、单位、时间戳和有效 mask。模型训练最难定位的错误通常不是网络层，而是 ego pose、相机内外参、未来轨迹与栅格标签没有落在同一个参考系。
