KV Cache 该丢弃什么：Token 驱逐与稀疏

KV Cache 该丢弃什么：Token 驱逐与稀疏

本文是 KV Cache 全方位技术指南 专题的深剖篇之一。架构进化史从模型设计上减小每 token 的 KV，量化减小每个元素的比特。这一篇讲第三条正交轴——减少 token 数：既然 KV Cache 随序列线性增长，能不能只保留重要 token 的 KV，丢掉其余？这是一批「推理期、免训练（post-hoc）」的方法：StreamingLLM、H2O、Scissorhands、SnapKV、PyramidKV、Quest。它们的分歧在于两个问题——判据是什么（凭什么说一个 token 重要）、丢还是不丢（永久驱逐 vs 动态选取）。

一、总问题：重要性怎么判定

KV Cache 显存随序列长度线性增长（每 token、每层都要存 K、V），长上下文/大 batch 下成为主要显存瓶颈。核心想法很朴素：只保留重要 token 的 KV。但「重要」怎么定义？主要有三类判据：

判据 含义 代表方法
注意力分数 被关注得多的 token 重要（累积或瞬时） H2O、Scissorhands、SnapKV、PyramidKV
位置 初始 token + 最近 token 重要 StreamingLLM
query 相关性 与当前 query 相关的才重要（动态） Quest

核心张力在于：注意力分数是 query 依赖的——一个 token 对过去的 query 不重要，不代表对未来 query 不重要。

  • 永久驱逐类（H2O/StreamingLLM/SnapKV/Scissorhands/PyramidKV）赌「重要性可持续」——现在不重要的以后也不重要，可以扔。
  • 动态选取类（Quest）不赌——保留全量 KV，只对每个 query 动态选一部分算。

下面逐个拆解。

二、StreamingLLM：注意力汇与滑动窗口

StreamingLLM（MIT/Meta，ICLR 2024，arXiv 2309.17453）。这是 KV Cache 指南提过的「注意力汇」的原始工作。

2.1 关键发现：Attention Sink

模型会把大量注意力异常地分配给最初几个 token，即使它们语义上并不重要——它们充当注意力的「水槽（sink）」。

为什么？直觉是 Softmax 需要分母、总得把注意力「倒到某处」。当没有特别该关注的 token 时，注意力就默认倒向最初几个 token（它们对所有后续位置都可见）。

2.2 后果与解法

朴素的窗口注意力（只留最近 KV）一旦文本超过缓存长度、把最初 token 丢掉，质量会崩溃——因为 sink 没了。

解法：保留少量初始 sink token 的 KV + 最近 token 的滑动窗口。就这么简单。

  • 免微调（另有可选项：预训练时加专用 placeholder sink token 可进一步改善）。
  • 收益：可稳定处理 400 万（4M）token 及以上；相对滑窗重算基线最高 22.2× 加速。
  • 局限：这是「无需微调地泛化到无限长度」，不是真正扩展上下文窗口——被移出窗口的中间信息会丢失（此为对机制的合理解读）。

三、H2O：Heavy-Hitter Oracle

H2O（Heavy-Hitter Oracle）（NeurIPS 2023，arXiv 2306.14048）。

3.1 核心：少数 token 贡献大部分注意力

论文发现：少数 token（称 Heavy Hitters, H2）贡献了绝大部分注意力值，且这些 token 的出现「自然、并与高频共现强相关」。

3.2 做法

  • 驱逐策略动态保留「最近 token + Heavy Hitter」的平衡。
  • 把问题形式化为动态子模优化（dynamic submodular），并给出近似贪心的理论保证。
  • 判据：按累积注意力分数识别 heavy hitter（累积分数的具体式子在正文）。

3.3 收益

20% heavy hitter 预算下，相对 DeepSpeed Zero-Inference / HF Accelerate / FlexGen，吞吐最高 29× / 29× / 3×；同 batch 延迟最多降 1.9×（OPT-6.7B/30B）。免训练，但仍是永久驱逐——被扔的 token 找不回来。

四、Scissorhands：重要性持久性假说

Scissorhands（arXiv 2305.17118）。

4.1 假说：Persistence of Importance

重要性持久性假说：只有在某一步有实质影响的 pivotal token，才会显著影响未来的生成；早期重要的 token 倾向于持续重要。

这正是所有「永久驱逐」方法的理论底气——如果重要性会持久，那把当前不重要的扔掉就是安全的。

4.2 做法与收益

  • 固定预算下，以更高概率保留 pivotal token、丢弃非关键 token；免微调。
  • 收益：KV 推理显存最高 5× 压缩且不损质量；叠加 4-bit 量化最高 20×——又一次印证「驱逐与量化正交可叠加」。

五、SnapKV：用观察窗口投票

SnapKV（2024，arXiv 2404.14469）。标题很妙：LLM Knows What You are Looking for Before Generation。

5.1 核心观察

每个 attention head 在生成时稳定地关注 prompt 中特定的注意力特征，而这个模式可以从 prompt 末尾的**「观察窗口（observation window）」**提前读出来——在生成开始前就知道该留哪些 KV。

5.2 做法

用观察窗口的注意力，为每个 head 选出「聚簇的（clustered）重要 KV 位置」并压缩 prefill KV（聚类用 pooling/投票，细节在正文）。这是一次性的 prefill 压缩，特别适合长 prompt、短生成。

5.3 收益

16K 输入下生成速度 3.6×、显存效率 8.2×；16 个长序列数据集上与基线相当；单张 A100-80GB 可处理 380K token，NIAH（大海捞针）精度损失可忽略。

六、PyramidKV / PyramidInfer：逐层预算金字塔

前面的方法多是所有层用同样的 KV 预算。这两个工作发现：不同层该给不同预算。

6.1 金字塔式信息漏斗

PyramidKV（arXiv 2406.02069）的核心观察：

注意力在低层广泛分散，逐层向特定上下文汇聚，到高层聚焦到少数关键 token——像一个信息漏斗。

因此：低层多留 KV、高层少留，预算逐层递减（金字塔形）。

  • 收益：LongBench 上仅保留 12% KV 即持平全量；极端 0.7% 预算下 TREC 相对最优基线最多 +20.5 绝对精度；NIAH 中 LLaMA-3-70B 仅留 128 条 KV 达 100.0。

6.2 PyramidInfer：把节省提前到 prefill

PyramidInfer（ACL 2024，arXiv 2405.12532）与 PyramidKV 共享「逐层递减」思想，但切入点不同：

  • PyramidKV 对已算好的全量 KV 剪枝；
  • PyramidInfer 在 prefill 阶段就少算 KV，靠注意力权重一致性逐层提取关键 KV，关注层间依赖 + prefill 本身的显存。
  • 收益：相对 Accelerate 吞吐 2.2×，KV Cache 显存降 >54%。

这个「浅层敏感、深层聚焦」的规律，和 CacheGen 给浅层更多量化比特是同一个洞察的两种利用。

七、Quest：查询感知、不丢 KV

Quest（ICML 2024，arXiv 2406.10774）。它是这批方法里的「异类」——不永久丢 KV。

7.1 核心：关键性是 query 依赖的

Quest 的立场：一个 token 的「关键性」取决于当前 query，所以不能永久驱逐。它的做法：

  • 保留全量 KV；
  • 按页（page/block） 维护每页 Key 的 min/max 边界；
  • 用当前 Query 估计每页的关键性，只加载 Top-K 关键页做注意力，跳过其余。

因为存的是 min/max 摘要，同一批 KV 可以对每个新 query 重新评估——这是它和永久驱逐的本质区别。

7.2 收益与代价

  • 收益：self-attention 最高 2.23×，推理延迟降 7.03×，长依赖任务精度损失可忽略。
  • 代价：显存不降（仍存全量 KV），省的是注意力计算和带宽，不是显存。

八、分类与选型

维度 永久驱逐（丢 KV） 动态选取（不丢 KV）
方法 StreamingLLM / H2O / SnapKV / Scissorhands / PyramidKV/Infer Quest
省什么 省显存（但信息不可逆丢失） 省计算/带宽（显存不降）
预算 固定预算（H2O/Scissorhands/SnapKV）；逐层预算（PyramidKV/Infer） —

选型建议：

  • 显存是硬约束（放不下）→ 用永久驱逐（H2O/SnapKV/PyramidKV）。
  • 显存够但要提速（算力/带宽瓶颈）→ 用 Quest（不丢 KV，只跳过无关页）。
  • 流式无限长输入 → StreamingLLM。
  • 长 prompt 短生成 → SnapKV（prefill 一次性压缩最划算）。

九、与「可训练稀疏」的范式区别

本文所有方法都是 post-hoc、免训练——在已训好的模型上、推理期做取舍。它们赌的是「预训练模型里已经有可利用的稀疏结构」。

而 NSA 与 MoBA 走的是另一条路——把稀疏写进训练、改架构，让模型在训练中学会如何稀疏：

post-hoc 的优势是即插即用、不用重训；可训练稀疏的优势是训推一致、精度更有保障。两者是 KV 稀疏化的两代思路，下一篇专门讲后者。
