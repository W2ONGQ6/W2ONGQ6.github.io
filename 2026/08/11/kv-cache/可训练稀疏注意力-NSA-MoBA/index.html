可训练稀疏注意力：NSA 与 MoBA

可训练稀疏注意力：NSA 与 MoBA

本文是 KV Cache 全方位技术指南 专题的深剖篇之一，也是「架构与算法专项」的收官。上一篇 Token 驱逐讲的是推理期、免训练的稀疏（H2O/StreamingLLM 等）——在已训好的模型上事后丢 KV。这一篇讲 2025 年最前沿的范式转变：把稀疏写进训练。DeepSeek 的 NSA 和 Kimi 的 MoBA 让模型在预训练阶段就学会「该关注哪里」，从而做到训推一致、端到端可优化、长程召回不丢——这是从「事后稀疏」到「原生可训练稀疏」的一次跃迁。

一、为什么要「原生可训练」稀疏

上一篇的 H2O、StreamingLLM 等都是在推理时丢弃/驱逐 KV。它们有三个共同局限：

  1. 训练-推理不一致：训练用 full attention、推理却用稀疏，模型没「见过」稀疏，行为可能偏移。
  2. 信息不可逆丢失：事后驱逐的 token 无法恢复，长程召回精度受损。
  3. 不可端到端优化：稀疏模式不参与梯度，模型无法学习「怎么稀疏才最好」。

于是 2025 年出现了新方向——原生（native）/可训练（trainable）稀疏：在预训练/持续训练阶段就用稀疏模式，让稀疏结构可学习、可微分。NSA 论文原文强调「natively trainable … end-to-end training」。

代表就是 DeepSeek 的 NSA 和 Kimi/Moonshot 的 MoBA。

二、NSA：三分支硬件对齐稀疏

NSA（Native Sparse Attention），DeepSeek 2025（arXiv 2502.11089），全称强调 Hardware-Aligned and Natively Trainable。

2.1 三条并行分支

NSA 对每个 query 并行走三条注意力分支，策略集 ：

  • ① 压缩（compression）：把连续 K/V 块聚合成块级表示，捕捉粗粒度的全局模式。压缩块大小 l = 32，滑动步长 d = 16。
  • ② 选择（selection）：块级 top-n 保留最重要的块。选择块大小 l′ = 64，选中块数 n = 16（含固定的 1 个 initial block + 2 个 local block）。
  • ③ 滑动窗口（sliding window）：处理局部上下文，窗口 w = 512。单设这一分支，是为了防止其他分支走「捷径」只学局部——把局部模式交给专门的窗口分支，压缩/选择分支就能专注全局。
  • 门控融合：三分支各有独立 K/V，输出按学习到的门控分加权求和，门控分 由输入特征经 MLP + sigmoid 得出。

2.2 硬件对齐

NSA 强调「算术强度平衡（arithmetic intensity-balanced）」的算法设计——块级结构适配现代硬件（Tensor Core、连续内存访问），让稀疏真正转化为实测加速而非理论 FLOPs 下降。这一点很关键：很多稀疏方法理论省算力，但因访存不规整而跑不快。

2.3 性能

  • 训练（Triton NSA vs FlashAttention-2，64k）：前向 up to 9.0×、反向 6.0×。
  • 解码（64k）：up to 11.6×，来自 KV 访问量下降。随长度递增：8k 4×、16k 6.4×、32k 9.1×、64k 11.6×。
  • 质量：在通用 / 长上下文 / 指令推理任务上「maintains or exceeds Full Attention」——稀疏还能不掉甚至超过全注意力。

三、MoBA：把 MoE 思想搬进注意力

MoBA（Mixture of Block Attention），Kimi/Moonshot 2025（arXiv 2502.13189）。名字就点明思路——把 MoE 的「门控选专家」搬到注意力的「门控选块」。

3.1 核心机制

  • 上下文长 N 切成 n 个块，块大小 ，每个 query 通过 top-k 门控只选相关的块做注意力。
  • 门控打分：块 的分数 = query 与该块 keys 的 mean-pooling 的内积。

  • 因果保证：对未来块（ ）打分设为 ；query 所在的当前块始终包含并施加因果掩码。

3.2 无缝切换与继续训练

MoBA 最实用的一点：它「设计成 full attention 的替代品，参数量完全相同」，因此可以逐层在 full/sparse 之间切换，也能在已有模型上继续训练。

一个漂亮的 hybrid recipe：前 90% token 用 MoBA、最后 10% 用 full attention，loss「几乎与全注意力相同」。

3.3 关键数字

  • Scaling law 实验：块大小 512、top-3。8K 时稀疏度 81.25%，32K 时 95.31%。
  • Llama-8B-1M-MoBA：块大小 4096、top-K 12，1M 时 95.31% 稀疏。
  • 效率：1M prefill up to 6.5×；10M 16× reduction in attention computation time。
  • 质量对齐：RULER@128K 0.7818（MoBA）vs 0.7849（Full）；LongBench@32K 0.4828 vs 0.4821——几乎无损。
  • 生产：已部署支撑 Kimi 的长上下文请求；开源在 github.com/MoonshotAI/MoBA。

四、NSA vs MoBA

两者都是可训练的块稀疏，但机制取向不同：

维度 NSA MoBA
机制 三分支并行（压缩+选择+滑窗）门控加权求和 单一 MoE 式门控，每 query 选 top-k 块
块选打分 selection 分支块级 top-n query · mean-pooled keys 内积 top-k
局部性处理 独立 sliding window 分支 强制包含当前块
门控 MLP+sigmoid 对三分支加权（软融合） top-k 硬选块（类 MoE routing）
主打加速 训练前向 9.0× / 反向 6.0× / 解码 11.6×@64k prefill 6.5×@1M、16×@10M
与 full attn 关系 新的注意力结构 参数完全一致，可无缝切换

一句话区分：NSA 用三条互补分支 + 软门控融合（压缩抓全局、选择抓重点、窗口抓局部）；MoBA 用单一 MoE 式硬路由选块，并强调与 full attention 参数一致、可自由切换。前者更像「重新设计注意力」，后者更像「给注意力装一个可切换的稀疏路由」。

五、范式差异：native vs post-hoc

把这一篇和上一篇对照，就看清了 KV 稀疏化的两代思路：

Post-hoc（上一篇） Native/Trainable（本篇）
代表 H2O、StreamingLLM、SnapKV、Quest NSA、MoBA
稀疏在哪引入 推理时 训练时
稀疏可学习吗 否（固定启发式） 是（端到端梯度）
训推一致 否 是
优势 即插即用、不用重训 训推一致、精度有保障、长程召回不丢
代价 赌模型已有稀疏结构 需要（继续）训练

两者不是取代关系，而是不同约束下的选择：手上只有现成模型、不能重训，用 post-hoc；能参与（继续）训练、追求长上下文极致质量与速度，用 NSA/MoBA。而无论哪代稀疏，都与架构缩减、量化正交——这就是 KV Cache 优化的全景：减 token 数（稀疏）× 减每 token 的 KV（架构）× 减每元素比特（量化），三轴叠乘。
