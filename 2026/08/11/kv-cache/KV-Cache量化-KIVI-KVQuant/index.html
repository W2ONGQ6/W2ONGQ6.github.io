KV Cache 量化：KIVI / KVQuant / FP8

KV Cache 量化：KIVI / KVQuant / FP8

本文是 KV Cache 全方位技术指南 专题的深剖篇之一。架构进化史减少每 token 的 KV，Token 驱逐减少 token 数。这一篇讲第三条正交轴——减少每个元素的比特数：能不能把 FP16 的 KV Cache 压到 INT8、INT4 甚至 2-bit？关键洞察是 Key 和 Value 的分布截然不同，必须用不同的量化粒度——这催生了 KIVI、KVQuant 等一批「非对称」方案。vLLM 篇讲过 FP8，这一篇把整个低比特谱系讲全。

一、为什么 KV 量化与权重量化不同

KV Cache 通常以 FP16 存储，长上下文下是主要显存来源。自然想到量化到 INT8/INT4/2-bit。但 KV 量化比权重量化棘手，因为二者性质不同：

权重量化 KV 量化
静态性 静态，可离线校准 激活，动态生成
时序 无 随解码不断追加，有时序（不同位置分布不同）
处理时机 离线一次 在线、逐 token
异常值敏感度 中 高

结论：KV 量化更依赖在线、逐 token 的处理，且对异常值（outlier） 极其敏感。这就引出了整个领域最重要的一个观察。

二、核心洞察：Key 与 Value 分布不同

KIVI 对 LLM 的 KV 元素分布做了细致研究，得出一个被后续工作反复印证的结论：

Key 应按 channel（per-channel）量化，Value 应按 token（per-token）量化。

为什么这么不对称？关键在 outlier channel（异常通道）：

  • Key 在某些特定 channel 维度上存在大幅度异常值。如果按 token 量化（一个 token 的所有 channel 共用一个 scale），异常通道会把整个量化范围拉大，导致其他正常通道精度崩溃。按 channel 分组则把异常隔离在它自己的通道里，不污染别人。
  • Value 没有这种明显的通道级异常，per-token 就够了。

这个「K 和 V 区别对待」的思想，是 KIVI、KVQuant 等几乎所有 KV 量化工作的共同基石。（outlier 通道的详细解释在各论文正文，摘要多只给结论。）

三、量化粒度谱系

理解几种粒度，才能看懂各方法的取舍：

粒度 含义 精度 元数据开销 典型用于
per-tensor 整张张量一个 scale 最差 最省 粗放场景
per-token 每个 token 一个 scale 中 中 Value
per-channel 每个通道一个 scale 好（隔离通道 outlier） 中 Key
group-wise 通道内再分小组（如每 32 个元素） 精度/开销折中 较高 KIVI 的分组量化

这又是一个 RUM 式的权衡——KV 量化的主要收益是降显存 + 降带宽（注意力多为 memory-bound，省带宽直接提速）。

四、KIVI：免调优的 2-bit 非对称量化

KIVI（ICML 2024，arXiv 2402.02750），全称 A Tuning-Free Asymmetric 2bit Quantization for KV Cache。

4.1 核心设计

  • 2-bit 量化，Key per-channel、Value per-token（§2 的结论就出自这里）。
  • tuning-free：免调优、免重训，即插即用。
  • residual（近期 token 全精度）：保留少量最近 token 的 KV 为全精度，其余量化到 2-bit。这是因为最近 token 对当前生成最关键，且它们还没「攒够」一个完整量化组。

常被引用的实现值为 residual length = 128、group size = 32，但这两个数不在论文摘要里（出自正文/代码）。引用前建议以官方仓库为准。

4.2 收益

峰值显存 2.6× 下降（含权重）、batch 最高 4×、吞吐 2.35×–3.47×，质量几乎不变。2-bit 还能做到质量几乎不掉，靠的就是「K/V 分别用对粒度 + 近期 token 保全精度」这套组合。

五、KVQuant：冲刺千万级上下文

KVQuant（NeurIPS 2024，arXiv 2401.18079），副标题直接喊出 Towards 10 Million Context Length。

它面向超长上下文，用四项技术把 KV 压到极低比特还几乎不掉精度：

  1. Per-Channel Key Quantization：沿更匹配分布的维度量化 Key（同 §2）。
  2. Pre-RoPE Key Quantization：在 RoPE 之前量化 Key。因为 RoPE 的旋转会打乱 Key 的通道分布、破坏量化，所以抢在旋转前量化。
  3. NUQ（Non-Uniform Quantization）：逐层敏感度加权的非均匀数据类型——不是等宽的量化 bin，而是按数据分布疏密分配。
  4. Per-Vector Dense-and-Sparse：逐向量隔离异常值，把少数 outlier 单独存（稀疏），压缩剩余部分的量化范围。

收益：3-bit 下 Wikitext-2 与 C4 困惑度损失 < 0.1；LLaMA-7B 单张 A100-80GB 支持 100 万 token、8 卡支持 1000 万；定制 CUDA kernel 相对 fp16 矩阵-向量乘最高约 1.7×。

Pre-RoPE 量化这个细节和 MLA 的解耦 RoPE遥相呼应——都是在处理「RoPE 的位置旋转会干扰对 KV 的压缩/吸收」这一共同难题，只是一个在量化前旋转、一个把 RoPE 解耦出单独维度。

六、FP8：硬件原生、工程最简

H100 等硬件原生支持 FP8，KV Cache 用 FP8 通常 near-lossless（近乎无损）。vLLM 与 TensorRT-LLM 都支持（框架支持属业界事实，具体以官方文档为准；vLLM 篇已单独讲过）。

对比要点：

  • 优点：无需 min/max 分组、硬件直算，工程最简，精度损失最小。
  • 缺点：压缩率不如 INT4/2-bit（8-bit vs 4/2-bit）。

FP8 是「想省事、有 H100」的默认选择；要极限压缩才上 KIVI/KVQuant 这类低比特方案。

七、QServe/QoQ 与 Atom：4-bit KV

这两个是把 KV 量化放进「权重-激活-KV 联合量化」大框架里的代表。

7.1 QServe / QoQ

QServe（arXiv 2405.04532），算法叫 QoQ（quattuor-octo-quattuor，拉丁语 4-8-4）：

  • W4A8KV4 = 4-bit 权重 + 8-bit 激活 + 4-bit KV。
  • 进步式量化（progressive quantization）：降低 W4A8 GEMM 的反量化开销（现有 INT4 反量化在 GPU 上有 20–90% 运行时开销）。
  • SmoothAttention：缓解 4-bit KV 的精度损失。
  • 收益：相对 TensorRT-LLM，Llama-3-8B 1.2×（A100）/1.4×（L40S），Qwen1.5-72B 2.4×/3.5×；L40S 甚至超过 A100 上的 TRT-LLM，成本约 3× 下降。

7.2 Atom

Atom（arXiv 2310.19102）：W4A4 服务量化，「混合精度 + 细粒度」，相对 FP16 端到端吞吐最高 7.7×、相对 INT8 2.5×，精度损失可忽略。

注：Atom 摘要只明确 W4A4（权重-激活），是否把 KV 也量化到 INT4、以及粒度细节，摘要未确认（正文有对 KV 的处理，以 PDF 为准）。

八、对比表与选型

方法 比特 K 粒度 V 粒度 免训练 精度损失 场景
KIVI 2-bit per-channel per-token 是 几乎不变 通用低显存/大 batch
KVQuant 3-bit（及更低） per-channel（pre-RoPE）+NUQ+稀疏 per-token+稀疏 是（免调） <0.1 ppl（3-bit） 超长上下文（1M–10M）
FP8 KV 8-bit（FP8） 硬件原生 硬件原生 是 near-lossless H100 工程最简
QServe/QoQ 4-bit KV（W4A8KV4） +SmoothAttention +SmoothAttention 需量化流程 SmoothAttention 缓解 高吞吐服务
Atom W4A4（KV 位宽摘要未确认） 未确认 未确认 需量化流程 可忽略（W4A4） 高吞吐服务

选型建议：

  • 有 H100、想省事 → FP8，近无损。
  • 要极限省显存、免重训 → KIVI（2-bit）。
  • 百万级以上超长上下文 → KVQuant。
  • 端到端服务吞吐优先 → QServe/QoQ（W4A8KV4）或 Atom。

别忘了正交叠加：量化可以和架构缩减（GQA/MLA）、Token 驱逐（如 Scissorhands + 4-bit = 20×）叠着用——这是压缩 KV 的三条正交轴。
