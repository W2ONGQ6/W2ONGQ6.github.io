从 MQA 到 MLA：KV Cache 缩减的架构进化史

从 MQA 到 MLA：KV Cache 缩减的架构进化史

本文是 KV Cache 全方位技术指南 专题的深剖篇之一。vLLM、SGLang、Mooncake 讲的都是「KV 已经生成后怎么管」。这一篇往回追一步问：能不能从模型架构上，让 KV Cache 一开始就更小？ 答案是一条清晰的进化线——MQA → GQA → MLA → CLA/YOCO，分别从注意力头维度、隐藏维度、层维度三个正交方向压缩 KV。理解这条线，就理解了为什么 Llama 用 GQA、DeepSeek 用 MLA、以及下一代模型的设计张力。

一、MHA 基线：瓶颈从哪来

标准多头注意力（MHA）的 KV Cache 大小（字节）：

前面的 2 是 K 和 V 各一份。这个公式就是整条进化线的「靶子」——后面每个方法都是在某个因子上做文章。

为什么它是瓶颈？ 训练时可沿序列长度并行，但自回归解码逐 token 串行，每一步都要重新加载全部 K/V 张量。MQA 论文原文点明：瓶颈是「反复加载庞大的 keys/values 张量的内存带宽成本」。也就是说——

解码是 memory-bandwidth-bound（访存受限），不是 compute-bound。KV Cache 越大，每步搬运的数据越多，就越慢。

所以缩减 KV Cache 不只是省显存，更是直接提速。这条线上所有工作的动机都在这里。

二、MQA：所有头共享一组 KV

MQA（Multi-Query Attention），Shazeer 2019（arXiv 1911.02150）。

核心思想：query 保持多头，但所有 head 共享一组 K/V。

  • KV 减少：公式里 n_heads → 1，即降到 1/n_heads。这是巨大的压缩（比如 32 头就是 32×）。
  • 质量影响：论文称「相对基线只有轻微质量下降，但解码快得多」。注意——论文摘要没给具体速度倍数或质量分数。
  • 代价：后续 GQA 论文的复现指出 MQA 质量损失更明显、训练可能不稳（这是 GQA 存在的动机）。
  • 代表模型：PaLM、Falcon、StarCoder 等（属通识）。

MQA 太激进——一步从 n_heads 压到 1，质量掉得让人肉疼。于是有了折中方案。

三、GQA：MHA 与 MQA 的插值（当前事实标准）

GQA（Grouped-Query Attention），Google 2023（arXiv 2305.13245）。

核心思想：query head 分成 G 组，每组共享一组 KV。它是 MHA（G = n_heads）和 MQA（G = 1）之间的插值：

  • Uptrain（从 MHA 转换）：不用从头训。从已有 MHA checkpoint 出发，把同组的 KV 投影做 mean-pooling，再继续训练——代价仅 5% 原始预训练算力。
  • 结果：「uptrain 后的 GQA 质量接近 MHA，速度接近 MQA」——两全其美。
  • 代表模型：Llama2-70B、Llama3 全系、Mistral 7B 等。这就是为什么说 GQA 是当前事实标准——几乎所有主流开源模型都用它。

GQA 优雅，但它压的还是 head 维度。DeepSeek 换了个方向。

四、MLA：低秩压缩与解耦 RoPE

MLA（Multi-head Latent Attention），DeepSeek-V2（arXiv 2405.04434）。这是 KV Cache 指南已提到的「MLA 革命」，这里讲透机制。

4.1 核心：低秩联合压缩

不再共享 head，而是把 KV 低秩压缩成一个 latent 向量，只缓存这个 latent，推理时再上投影重建：

DeepSeek-V2 的确切维度：d_model=5120、层数=60、头数 n_h=128、head_dim=128，而 kv_lora_rank = 512、qk_rope_head_dim = 64。

关键技巧——矩阵吸收：推理时 可被吸收进 、 吸收进 ，于是 K/V 从不需要显式物化，只缓存那个 512 维的 。

4.2 为什么要解耦 RoPE

这里有个精妙的冲突。RoPE 对 K/Q 都做位置相关的旋转。若把 RoPE 加到压缩后的 key 上，旋转矩阵会卡在 与 之间——而矩阵乘不满足交换律，于是 无法再被吸收进 ，吸收技巧失效，每个前缀 token 都得重算 key。

解法（decoupled RoPE）：额外引入一路携带 RoPE 的多头 query 和一个共享的解耦 key ，拼接到压缩 query/key 上；这个解耦 key 也进缓存。位置信息由这一小路专门承载，压缩主路保持可吸收。

4.3 效果：又省又强

每 token 每层 KV 对比（元素数）：

方法 KV/token（元素） 能力
MHA Strong
GQA Moderate
MQA Weak
MLA Stronger

MLA 每层每 token 只存 元素。论文原话：相当于**「只有 2.25 组的 GQA，但性能强于 MHA」**；相对 DeepSeek 67B，KV Cache 减少 93.3%。

这就是「又省又强」的秘密：低秩压缩省显存，但 512 维 latent 仍保留足够表达力，解耦 RoPE 保住位置信息——压缩的是冗余，不是信息。

五、CLA：层间共享 KV

CLA（Cross-Layer Attention），MIT 2024（arXiv 2405.12981）。

前面 MQA/GQA/MLA 都在单层内做文章。CLA 换了个维度：相邻层之间共享 K/V。

  • 在 MQA/GQA 已经让多个 query head 共享 KV 的基础上，再让相邻层共用一份 KV。
  • KV 减少：在 MQA 之上再减 2×，论文原话「再减 2× 而质量几乎与原始 MQA 相同」。
  • 在 1B/3B 从头训练实验中，CLA 相对传统 MQA 提供了显存/精度权衡上的帕累托改进。
  • 正交性：CLA 减的是 layer 维度，与 MQA/GQA 减的 head 维度正交，可组合（如 GQA + CLA）。

六、YOCO：全局只缓存一份

YOCO（You Only Cache Once），微软 2024（arXiv 2405.05254）。

注：常见引用里有把 YOCO 写成 arXiv 2405.05946 的，那其实是一篇量子物理论文，正确 ID 是 2405.05254。

CLA 是相邻层共享，YOCO 更彻底——全局只缓存一份 KV。

6.1 decoder-decoder 结构

  • self-decoder：用高效注意力（gated retention 或 sliding-window， 缓存）产出一份全局 KV。
  • cross-decoder：所有层通过 cross-attention 复用这唯一一份 KV。

6.2 prefill 提前退出

因为 cross-decoder 只需要 self-decoder 的输出，prefill 时可以在进入 cross-decoder 前提前退出，砍掉至少一半层，prefill 从 降到 。

6.3 惊人的数字（均来自论文）

  • KV 显存：65B 模型减少约 80×；65B 上 1GB 显存可服务 128K token，而 Transformer+GQA 仅 1.6K。
  • Prefill 加速：1M context 71.8×；512K「从 180 秒降到不足 6 秒」。
  • 吞吐（512K）：Transformer 4.5 tok/s vs YOCO 43.1 tok/s（9.6×）。
  • 上下文扩展到 1M token，近乎完美的 needle retrieval。

七、三条正交的压缩轴

把整条进化线收束成一张图，就是三个正交方向：

方法 KV/token 相对基线 缩减维度 质量影响 代表模型
MHA 1×（基线） — 基线 GPT 系、Llama1
MQA 1/n_heads head 轻微下降，可能训练不稳 PaLM、Falcon
GQA G/n_heads head ≈MHA（uptrain 5% 算力） Llama2/3、Mistral
MLA ≈2.25 组 GQA；-93.3% vs 67B 隐维度（低秩） 强于 MHA DeepSeek-V2/V3
CLA MQA 再 ×½ layer（层间） ≈MQA 研究原型
YOCO ~80× less（65B） layer（全局单份） 保持（1M 检索近满分） YOCO-3B

正交意味着可叠加：GQA + CLA、MLA + 层间共享，都是合理组合。这也是理解未来模型架构的钥匙——KV Cache 的缩减不是单选题，而是在这三条轴上组合选点，与后面的量化（减每个元素的比特）、驱逐/稀疏（减 token 数）进一步正交叠加。

一句话总结：KV Cache 的架构级缩减是三条正交轴——MQA/GQA 减 head、MLA 用低秩减隐维度、CLA/YOCO 减 layer。GQA 是当前事实标准，MLA 是「又省又强」的范式突破，三轴可自由组合，也可与量化、稀疏正交叠加。
