哈希表：用空间换时间

哈希表的核心价值在于将查找操作的时间复杂度降到 O(1)，代价是额外的 O(n) 空间。它特别适合解决”某个值是否出现过”、”两个元素是否存在配对关系”这类问题——只要能把”查找”变成”取值”，就能把朴素的 O(n²) 暴力降到线性时间。

1. 两数之和

难度：Easy | 标签：哈希表 | 🔗 LeetCode 第 1 题

题目描述：给定一个整数数组 nums 和一个整数目标值 target，请你在数组中找出和为目标值的那两个整数，并返回它们的下标。每种输入只对应一个答案，且同一个元素不能重复使用。

示例：nums = [2,7,11,15], target = 9 → 返回 [0,1]（因为 nums[0] + nums[1] = 2 + 7 = 9）。

思路解析：

朴素做法是双重循环枚举所有配对，时间 O(n²)。关键观察是：遍历到元素 x 时，我们需要的是 target - x 是否已经出现过，以及它的下标。用哈希表 seen 记录”值 → 下标”的映射，每次查询只需 O(1)，整体降到 O(n)。由于一边遍历一边查询，天然避免了用同一个元素两次的问题。

复杂度：时间 O(n)，空间 O(n)。

2. 字母异位词分组

难度：Medium | 标签：哈希表、排序 | 🔗 LeetCode 第 49 题

题目描述：给定一个字符串数组 strs，请将其中所有字母异位词（字母组成相同、排列不同的单词）归为同一组，返回所有分组结果（顺序不限）。

示例：strs = ["eat","tea","tan","ate","nat","bat"] → 返回 [["bat"],["nat","tan"],["ate","eat","tea"]]。

思路解析：

字母异位词的本质是：字母组成相同，排列不同。要把它们归到一组，需要一个”标准化表示”作为哈希键。最直接的方式是对每个单词的字符排序，排序后相同的字符串即为同一组异位词。以排序结果作为字典的 key，value 存放该组的所有原始单词，遍历一遍即可完成分组。

对于每个长度为 k 的单词，排序耗时 O(k log k)，n 个单词总计 O(nk log k)，空间 O(nk)。

复杂度：时间 O(nk log k)，空间 O(nk)（k 为单词最大长度）。

进阶思路：也可以用长度为 26 的字符频次数组作为 key（tuple(count)），时间降到 O(nk)，适合字符集固定为小写字母的场景。

3. 最长连续序列

难度：Medium | 标签：哈希表 | 🔗 LeetCode 第 128 题

题目描述：给定一个未排序的整数数组 nums，请你找出其中数字连续的最长序列的长度（序列元素在原数组中不要求连续），要求时间复杂度为 O(n)。

示例：nums = [100,4,200,1,3,2] → 返回 4（最长连续序列为 [1,2,3,4]）。

思路解析：

题目要求时间 O(n)，排序是 O(n log n) 因此不可用。关键观察是：只从每段连续序列的起点开始向右延伸，才不会重复计算。如何判断 x 是起点？只需检查 x - 1 是否不在集合中。若不在，说明 x 就是某段序列的开头，然后逐步查 x+1, x+2, ... 直到断开，记录长度。虽然有嵌套循环，但每个数至多被访问两次（一次作为起点触发，一次作为序列延伸被查到），均摊仍是 O(n)。

复杂度：时间 O(n)，空间 O(n)。
