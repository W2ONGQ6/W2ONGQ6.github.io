LeetCode Hot100-03：滑动窗口与子串

滑动窗口：动态区间上的一次扫描

滑动窗口的核心节奏是：右指针不断扩张纳入新元素，一旦窗口违反约束，左指针向右收缩直到约束重新满足，整个过程仅需 O(n) 完成一次线性扫描。本篇在经典滑窗题目之外，也收录了前缀和+哈希（处理含负数的子数组求和）和单调队列（维护窗口极值）这两类解决”子串/子数组”问题的近亲技巧，它们与滑窗共享”在连续区间上高效推进”的思维内核。

1. 无重复字符的最长子串

难度：Medium | 标签：滑动窗口 | 🔗 LeetCode 第 3 题

题目描述：给定字符串 s，找出其中不含重复字符的最长子串的长度。

示例：s = "abcabcbb" → 3（子串 "abc"）

思路解析：用哈希表 char_index 记录每个字符最近一次出现的下标，左指针 left 标记当前无重复窗口的起点。右指针 right 逐字符向右扩张：若当前字符已在窗口内（即 char_index[c] >= left），则将 left 直接跳到该字符上一次位置的下一位，从而在 O(1) 内完成收缩，无需逐步移动；每一步都用 right - left + 1 更新答案最大值，最终得到全局最长无重复子串长度。

复杂度：时间 O(n)，空间 O(k)（k 为字符集大小，ASCII 下最多 128）。

2. 找到字符串中所有字母异位词

难度：Medium | 标签：滑动窗口、字符频次 | 🔗 LeetCode 第 438 题

题目描述：给定字符串 s 和 p，找到 s 中所有 p 的字母异位词的起始索引，异位词要求字符种类和频次完全相同但顺序可以不同。

示例：s = "cbaebabacd", p = "abc" → [0, 6]（"cba" 和 "bac" 均为 "abc" 的异位词）

思路解析：异位词要求字符种类和频次完全一致，因此窗口大小固定为 len(p)。用两个长度为 26 的频次数组分别统计模式串 p 和当前窗口的字符频次，初始化时先填满第一个窗口；随后滑动时每步”移入右端新字符、移出左端旧字符”，只更新两个计数即可，然后比较两数组是否相等——相等则记录左端点。由于数组长度固定为 26，每次比较是 O(26) = O(1)，整体线性。

复杂度：时间 O(n)，空间 O(1)（固定 26 字母频次数组）。

3. 和为 K 的子数组

难度：Medium | 标签：前缀和、哈希表 | 🔗 LeetCode 第 560 题

题目描述：给定整数数组 nums（元素可为负数）和整数 k，返回连续子数组和恰好等于 k 的子数组个数。

示例：nums = [1, 1, 1], k = 2 → 2（[1,1] 出现两次）

思路解析：数组中存在负数，窗口和随右指针扩张不单调递增，因此无法用”和过大则收缩左指针”的经典滑窗策略——收缩后和可能反而更大。正确做法是前缀和+哈希：设 prefix[i] 为前 i 个元素之和，子数组 [j+1, i] 的和等于 prefix[i] - prefix[j]。若该差等于 k，即 prefix[j] = prefix[i] - k，则说明存在一个以 i 结尾、和为 k 的子数组。用哈希表 seen 边扫描边记录每个前缀和出现的次数，每到位置 i 就查询 seen[prefix_sum - k] 累加到答案，从而一次遍历完成统计。

复杂度：时间 O(n)，空间 O(n)。

4. 滑动窗口最大值

难度：Hard | 标签：单调队列、滑动窗口 | 🔗 LeetCode 第 239 题

题目描述：给定整数数组 nums 和滑动窗口大小 k，返回每个位置窗口内的最大值组成的数组。

示例：nums = [1,3,-1,-3,5,3,6,7], k = 3 → [3,3,5,5,6,7]

思路解析：暴力每窗口求最大值是 O(nk)，瓶颈在于”移出旧元素后重新找最大值”。单调递减双端队列（deque）可将其降为 O(n)：队列里存下标，始终保持队列内对应值从大到小排列。右指针 right 到来时，先从队尾弹出所有值 ≤ nums[right] 的下标（它们在当前和未来窗口中永远不可能是最大值），再将 right 入队尾；若队首下标已滑出窗口（< right - k + 1），则弹出队首。此时队首即为当前窗口最大值的下标，当 right >= k - 1 时记录答案。

复杂度：时间 O(n)（每个元素至多入队/出队各一次），空间 O(k)。

5. 最小覆盖子串

难度：Hard | 标签：滑动窗口、字符频次 | 🔗 LeetCode 第 76 题

题目描述：给定字符串 s 和 t，返回 s 中涵盖 t 所有字符（含重复）的最小子串；若不存在则返回空字符串。

示例：s = "ADOBECODEBANC", t = "ABC" → "BANC"

思路解析：窗口大小不固定，需要动态收缩。用 need 哈希表记录 t 中每个字符还需要多少个，missing 计数器记录当前窗口总共还差多少字符才能覆盖 t。右指针 right 扩张时，若纳入的字符恰好满足了 need（即 need 值从正数降到 0），则 missing 减一；当 missing == 0 时窗口已覆盖 t，此时尝试移动左指针收缩：若移出的字符使 need 值从 0 升回正数（说明该字符是必要的），missing 加一，收缩终止。每次 missing == 0 时用当前窗口长度更新最短答案并记录起点。

复杂度：时间 O(|s| + |t|)，空间 O(|t|)。
