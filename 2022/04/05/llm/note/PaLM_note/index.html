PaLM: Scaling Language Modeling with Pathways

PaLM: 用Pathways系统扩展语言建模

核心信息

  • 标题: PaLM: Scaling Language Modeling with Pathways
  • 标题翻译: PaLM：用Pathways系统扩展语言建模
  • 作者: Aakanksha Chowdhery, Sharan Narang, Jacob Devlin 等 67 位作者
  • 机构: Google Research
  • 发表时间: 2022年4月5日（arXiv），2023年发表于JMLR
  • 发表渠道: Journal of Machine Learning Research (JMLR), Volume 24, 2023
  • arXiv: 2204.02311
  • 论文链接: https://arxiv.org/abs/2204.02311
  • 论文类型: 规模化实验 + 系统工程论文
  • 模型参数: 540B（5400亿）
  • 截至2024年引用数: 超过5,000次

原文摘要翻译

大规模语言模型已被证明在广泛的任务上取得了卓越的性能。虽然关于扩展的一些讨论集中在训练更多数据或更大模型上，但训练最大规模模型的系统能力也同样至关重要。我们介绍了PaLM（Pathways Language Model），一个5400亿参数的、密集解码器仅Transformer模型，使用Google的Pathways系统在6144块TPU v4芯片上训练。通过Pathways系统，我们高效地协调跨两个TPU v4 Pod的模型和数据并行，实现了57.8%的模型FLOPs利用率——这是当时如此大规模语言模型训练的最高训练效率。我们通过大量实验系统性地展示了继续扩展大语言模型的优势。PaLM在数百个自然语言、代码和数学推理任务上实现了突破性的性能。我们观察到群组多语言理解、推理和代码生成能力的显著涌现。PaLM在BIG-Bench基准上展示了令人印象深刻的自然语言理解和生成能力。例如，540B PaLM在一系列推理基准上取得了最先进的结果，包括在GSM8K数学推理基准上使用8样本提示达到了58%的准确率，而无需在数学数据上进行任何微调。它在超过三分之二的BIG-Bench任务上展现了突破性的能力。大量基准测试和BIG-Bench任务显示了模型规模扩大带来的不连续改进，意味着随着模型扩展到最大规模，性能突然大幅跃升。

创新点

1. Pathways分布式训练系统

核心思想: PaLM在Google全新的Pathways分布式计算基础设施上训练，实现了跨两个TPU v4 Pod（共6144块芯片）的高效协同训练，模型FLOPs利用率（MFU）达到惊人的57.8%。

Pathways系统的关键能力:

  • Pod间通信: 传统TPU训练限制在单个Pod内（最多2048块芯片）。Pathways首次实现了跨Pod的模型并行+数据并行协同调度，将可用的TPU规模扩展到6144块
  • 模型与数据并行的灵活组合: 在3072个TPU芯片上做数据并行，在模型维度上再做2路张量并行，高效协调两种并行策略
  • 57.8% MFU的含义: 这意味着在训练中，54.5%的TPU FLOPs被用于实际计算，仅有42.2%的时间/算力被通信、同步等开销消耗

为什么重要: PaLM证明了万卡级（6000+芯片）高效训练大模型的工程可行性。这一里程碑级成就为后来Gemini系列的更大规模训练奠定了基础。57.8% MFU在当时的同规模模型中是最高的（Megatron-Turing NLG 530B约30%）。

2. Chain-of-Thought推理能力的涌现

核心思想: PaLM最大的技术发现是——540B参数模型在不需要任何专门数学训练数据的情况下，通过Chain-of-Thought（CoT）提示，在GSM8K数学推理任务上达到了58%的准确率，超越了当时使用专门微调的SOTA模型（55%）。

CoT提示的设计:

  • 在问题前提供8个带有详细推导步骤的示例（而非仅提供答案）
  • 步骤包括: 提取已知信息、设未知数、建立方程、逐步求解
  • 模型会模仿这种”逐步思考”的模式来回答新问题

为什么重要: 这一发现引爆了2022-2023年的LLM推理研究。它证明了”推理能力”不是需要特殊架构或训练方法才能获得的能力，而是纯粹随规模涌现的。这意味着”让模型更大”是获得推理能力的可行路径。PaLM也展示了CoT方法的威力——一个相对简单的prompt策略可以解锁大模型惊人的隐藏能力。

3. 多语言能力的突破

核心思想: PaLM在780B高质量多语言token上训练，覆盖100+种语言。540B模型展示了超强的跨语言Zero-shot能力——在从未专门训练的翻译任务上，few-shot翻译表现接近甚至超越了专门的微调系统。

多语言设计:

  • 训练数据中英语约占78%，多语言约占22%
  • 没有使用任何平行语料（所有数据都是单语）
  • 模型自然学习了跨语言的语义对齐

为什么重要: PaLM挑战了”多语言能力需要专门的多语言训练”的观点。它证明了: 即使训练数据中仅有22%是非英语，一个足够大的模型也能涌现出强大的跨语言理解和生成能力。

4. 系统的涌现曲线分析

核心思想: PaLM在BIG-Bench（150+个多样化任务）上进行了跨8B/62B/540B模型规模的系统测试，首次捕获了大量任务的”涌现曲线”——性能从接近随机到大幅超越的突然跳跃。

涌现的现象特征:

  • 在模型从62B扩展到540B时，多个任务出现不连续的性能跳跃
  • 例如，某些逻辑推理任务在62B上约5-10%，在540B上飙升至60-80%
  • 这类跳跃在小模型（8B→62B）上完全不存在

为什么重要: 这为GPT-3提出的”涌现”概念提供了大规模的系统实证。它暗示了持续扩展模型的巨大潜在价值——我们可能只看到了冰山一角。

5. 源代码生成能力的涌现

核心思想: PaLM虽然在训练数据中包含代码（约5%的GitHub数据），但未进行任何代码特定的微调。540B模型通过few-shot提示，在代码生成和理解任务上展现了强大的能力。

具体表现:

  • 在HumanEval（代码生成基准）上few-shot效果与经过代码微调的模型竞争
  • 能够理解和修复代码错误（debugging）
  • 能够将代码从一种语言翻译到另一种

为什么重要: 代码能力是理解模型通用智能的重要窗口——代码需要精确的语法、逻辑推理和抽象思维。PaLM在这方面的表现进一步支持了”通用能力随规模涌现”的假设。

一句话总结

PaLM通过在6144块TPU v4芯片上使用Pathways系统以57.8%的高效利用率训练了540B参数模型，首次系统性地证明了Chain-of-Thought推理、多语言理解和代码生成等高级能力是纯粹随规模涌现的——模型无需任何任务特定微调，仅通过规模扩展和适当的提示策略即可获得突破性的性能，从而直接改变了LLM推理研究的方向。

研究问题

核心挑战

到2022年，LLM领域面临三个核心瓶颈:

  1. 训练系统的扩展瓶颈: 训练500B+参数的模型需要远超单台机器或单个Pod的计算能力，但跨Pod的训练面临通信带宽瓶颈和同步挑战

  2. 推理能力的获取: GPT-3证明了规模带来上下文学习能力，但复杂推理（如数学、逻辑）仍然是大模型的弱项——需要架构创新还是规模就足够？

  3. 多语言和代码能力: 能否通过统一的”数据+规模”方案获得跨语言和跨模态的能力？还是必须为每种能力设计专门的训练策略？

PaLM的回答

  1. 系统瓶颈: Pathways系统证明了跨Pod高效训练的可行性——6144芯片、57.8% MFU是可实现的

  2. 推理能力: 不需要专门架构——Chain-of-Thought提示（一个简单的prompt技巧） + 足够大的规模能使数学推理能力自然涌现

  3. 多语言+代码: 在训练数据中包含少量目标语言/代码（22%多语言，5%代码）就足以让大模型涌现跨领域能力

数据与任务定义

训练数据

PaLM的训练数据是一个精心构建的高质量多语言混合语料，总计780B token:

数据来源 比例 说明
社交媒体对话 50% 多语言对话数据

GitHub 5% 代码数据
Wikipedia 4% 多语言百科
新闻 1% 多语言新闻

语言分布: 英语约78%，其他100+种语言约22%

数据过滤:

  • 移除低质量、重复和有害内容
  • 使用训练数据的质量分类器进行过滤
  • 去重（模糊和精确匹配）

评估任务

BIG-Bench: 150+个多样化NLP任务——这是PaLM的核心评估基准

  • 包含逻辑推理、笑话解释、概念映射、因果判断等非传统NLP任务
  • 按任务类别分组: NLP、数学、常识推理、逻辑推理等

推理基准:

  • GSM8K: 小学数学应用题（8K个问题）
  • StrategyQA: 需要隐式多步推理的问答
  • SVAMP: 数学应用题变体测试
  • AQuA: 代数应用题

翻译:

  • WMT英德、英法翻译
  • 多语言零样本翻译

代码生成:

  • HumanEval: 164个Python编程问题
  • MBPP: 974个Python编程任务

整体架构

PaLM使用纯解码器-仅Transformer（Decoder-only），与GPT-3和LLaMA类似:

架构细节:

  • 并行公式: 注意力投影 $Q$, $K$, $V$ 和FFN输入在同一层中并行计算，提高训练吞吐
  • SwiGLU激活函数（替代标准ReLU/GELU）
  • RoPE（Rotary Position Embedding）位置编码
  • 无偏置项（bias）——所有线性层只有权重，没有偏置
  • 共享输入/输出嵌入矩阵
  • Pre-LayerNorm（RMSNorm）

机制流程


Figure 2: 来源—原论文。

阶段一: 分布式训练（Pathways系统）

关键创新: Google的Pathways系统通过以下机制实现了跨Pod高效训练:

  1. Pod间通信调度: 使用PaLM独特的”2048路数据并行 + 3路模型并行”调度策略，将通信和计算重叠
  2. SPMD编程模型: 整个模型使用单程序多数据（SPMD）范式编写，自动编译到不同的硬件拓扑
  3. 激活重计算: 在前向传播时不存储激活，反向传播时重新计算——以计算换内存，在TPU上特别有效

57.8% MFU的分解:

  • 计算时间: 约57.8%
  • 通信开销: 约20%（Pod内） + 约15%（Pod间）
  • 其他开销: 约7.2%（流水线气泡、同步等）

阶段二: 预训练

标准自回归语言建模，与GPT-3/LLaMA相同。

阶段三: Chain-of-Thought推理（评估）

对于GSM8K等数学推理任务，PaLM使用Chain-of-Thought提示:

CoT Prompt结构:

为什么CoT有效: CoT提示强迫模型在回答前先”写出推理过程”，这样:

  1. 将复杂问题分解为简单步骤
  2. 每步的计算量小，模型可以准确处理
  3. 中间结果帮助保持推理的连贯性
  4. 错误可以在后续步骤中检测和纠正

阶段四: 涌现能力评估

在BIG-Bench的150+个任务上，系统比较8B/62B/540B三个尺度的性能。

深度分析


Figure 5: 来源—原论文。

涌现现象的”证据金字塔”

PaLM为”涌现”提供了迄今最系统的证据:

证据层级 内容
顶层 BIG-Bench 150+任务的大规模曲线
中层 数学推理(4.1→29.3→58.0)的三点跳跃
底层 代码生成(3.6→13.1→26.2)的两阶段跳跃

这些曲线的共同特征: 8B→62B的提升是线性的；62B→540B的提升是非线性的（在某些任务上跳跃了10倍以上）。

CoT推理的”免费午餐”性质

PaLM最惊人的发现之一是CoT的成本效益比:

  • 不需要修改模型架构
  • 不需要专门的训练数据
  • 不需要微调
  • 仅需要在prompt中改变格式（从”直接给答案”到”逐步推理”）
  • 效果: 从”接近随机”到”超越微调SOTA”

这类似”免费午餐”——几乎零成本获得了推理能力的大幅提升。

Pathways系统的里程碑意义

PaLM在系统层面完成了此前被认为是”不可能”的工程挑战:

  • 跨Pod训练: 使用超过一个TPU Pod的芯片做同一个模型的训练（此前TPU训练限制在单个Pod）
  • 57.8% MFU: 证明了万卡级训练的效率问题是可以解决的
  • SPMD可扩展性: 证明了单程序多数据模型在大规模下的可行性

这些工程突破对后续Google的Gemini系列的训练至关重要——没有Pathways就没有Gemini。

局限

1. 训练成本极高

100天 x 6144 TPU v4芯片 = 天文数字的能源和资金成本。

2. CoT的不可靠性

即使有CoT，在需要10+步推理的复杂数学问题上，PaLM仍会出错——且错误通常难以检测。

3. 训练数据的质量问题

50%来自”社交媒体对话”——这部分数据的质量和潜在偏见问题。

4. “涌现”的解释不足

论文提出了涌现的现象，但未解释涌现机制——只是演示了它。

可复用洞见

1. CoT提示是解锁推理能力的钥匙

简单改变prompt格式就能获得质变——在任何LLM应用中都应该首先尝试CoT。

2. 系统效率与模型质量同样重要

57.8% MFU是PaLM成功的关键——没有高效的训练系统，540B无法经济地训练。

3. 少量领域数据的”启发式”效应

仅5%代码数据、22%多语言数据就足以让大模型涌现代码和多语言能力——“撒一点种子就能长成森林”。

我的笔记

PaLM与Google AI策略

PaLM是Google对OpenAI GPT-3的战略回应。它标志着Google从”研究分散”到”聚焦大模型”的战略转变。Pathsays系统的成功直接支持了后续Gemini的开发——Gemini某种程度上是PaLM的multimodal后继。

CoT的深远影响

PaLM引爆的CoT研究直接导致了:

  • “Let’s think step by step”（Kojima et al., 2022）——零样本CoT
  • Tree-of-Thoughts (Yao et al., 2023) ——扩展CoT到树状搜索
  • Self-Consistency (Wang et al., 2023) ——多次采样+投票
  • ReAct (Yao et al., 2023) ——推理+行动交织

这些工作构成了2023年LLM推理研究的核心脉络。

后续问题

1. 涌现的预测模型
