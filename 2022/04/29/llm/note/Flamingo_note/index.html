Flamingo: a Visual Language Model for Few-Shot Learning

  • 机构: DeepMind

  • 发表渠道: NeurIPS 2022

原文摘要翻译

仅有少量示例就能快速适应新任务的能力是人类智能的一个标志。我们介绍了 Flamingo，一个具有这种能力的视觉语言模型（VLM）系列。Flamingo 的关键架构创新包括：(1) 将强大的预训练视觉模型和语言模型通过 Perceiver Resampler 连接；(2) 在交错的图文数据上训练，使模型自然学会在文本和图像之间切换；(3) 使用门控交叉注意力机制将视觉信息注入语言模型的每一层。Flamingo 模型在 16 个多模态基准上取得了当时最佳结果，包括视觉问答、图像描述和视频理解等任务，且在这些任务上仅使用少量（甚至零个）针对新任务的图文交织示例就达到了强大的性能，在许多情况下超越了使用数千个标注样本微调的专用模型。

创新点

  1. Perceiver Resampler 架构：将任意数量视觉 token 压缩为固定数量”视觉摘要”token（如 64 个），高效注入 LLM——解决了可变长度视觉特征与固定 Transformer 接口之间的矛盾。

  2. 交织图文预训练：在约 400 亿图文交错网页文档上训练，使模型自然理解”文本-图像-文本”的交互模式，而非简单的单图描述。

  3. 门控交叉注意力（Gated XATTN）：每层通过可学习门控参数控制视觉-语言融合，初始化为零以保护预训练 LLM 的知识——确保视觉信息的融入是渐进可控的。

  4. 强大的少样本多模态能力：仅需 prompt 中提供少量图文交替示例，就在多个任务上超越全微调专用模型。

一句话总结

Flamingo 通过 Perceiver Resampler + 门控交叉注意力 + 交织图文预训练，确立了冻结视觉编码器/LLM + 轻量连接模块的 VLM 架构范式，首次证明多模态少样本学习可大规模可行。

研究问题

如何构建一个能够理解图文交织内容、且能通过少量示例适应新视觉任务的通用视觉语言模型？关键挑战在于：如何将任意数量视觉特征高效输入固定大小的语言模型？如何在不破坏 LLM 已有语言能力的前提下融入视觉信息？

子问题分解

  1. 视觉-语言接口问题: 视觉编码器输出的 token 数是可变的（取决于图像分辨率），而 Transformer LLM 的输入接口是固定的。如何桥接这个维度不匹配？
  2. 知识保持问题: 当向预训练 LLM 注入视觉信息时，如何保证 LLM 的原始语言能力（如语法、推理、世界知识）不被”覆盖”？
  3. 训练数据格式问题: 传统的图文对（image, caption）只提供单图单文的对应，但真实的多模态对话是图文交错的。如何构建和利用交错数据？
  4. few-shot 泛化问题: 能否让模型看到少量示例后，在多模态任务上获得类似 LLM 上下文学习的泛化能力？

数据与任务定义

训练数据

  • 交织数据集 M3W：约 4300 万网页，包含约 400 亿图文交错 token
  • 图文对数据集：ALIGN（18 亿图文对）+ LTIP（3.12 亿图文对）
  • 视频数据：共约 2700 万短视频片段

数据混合策略

  • 训练时按比例混合三种数据源：图文交错数据（主）、图文对数据（辅）、视频数据（辅）
  • 交错数据提供了”上下文”（多图多文之间的逻辑关系），图文对数据提供了”对齐”（单图单文的对应），视频数据提供了”时序理解”
  • 数据混合比例的消融实验表明：纯图文对训练无法产生 few-shot 能力，交错数据是关键

评测任务（16 个多模态基准）

  • 图像描述: COCO Captions、Flickr30K、NoCaps
  • 视觉问答: VQAv2、OK-VQA、VizWiz、TextVQA
  • 视频理解: MSRVTT QA、MSVD QA、ActivityNet QA、LSMDC
  • Few-shot 泛化: 在上述任务上仅使用 4-32 个示例
  • 零样本: 部分任务在完全不提供示例的情况下评测

机制流程

Step 1：视觉特征提取

  • 输入: 单张图像（或多张图像/视频帧序列）
  • 操作:
    • 使用冻结的 NFNet-F6 视觉编码器对输入图像进行前向计算
    • 从编码器的中间层提取空间特征图（spatial feature map）
    • 特征图被展平为一组视觉 token V = {v_1, v_2, …, v_N}
    • N 的数量取决于图像分辨率：对于 288x288 的输入，N 约为 400
    • 对于视频输入，对每一帧独立提取特征，然后通过时间感知的 Perceiver 聚合
  • 输出: N 个视觉特征向量（每个维度为 d_vis = 1024 或类似），数量 N 可变
  • 关键设计: 视觉编码器被完全冻结（不参与训练），确保其预训练的视觉理解能力不被破坏

Step 2：Perceiver Resampler 压缩

  • 输入:
    • N 个视觉特征向量（来自 Step 1，N 可变，通常 100-1000+）
    • L 个可学习的 latent query token（L 固定，如 64）
  • 操作:
    • Perceiver Resampler 是一个基于交叉注意力的压缩模块
    • Latent query tokens 作为 queries，视觉特征向量作为 keys 和 values
    • 通过多层交叉注意力，L 个 query token “查询”视觉特征中的相关信息并凝聚为压缩表示
    • 交叉注意力的计算：Q_latent * K_visual^T / sqrt(d) -> softmax -> * V_visual
    • 输出维度固定为 L x d_llm（匹配 LLM 的隐藏维度）
    • Perceiver 内部可能包含自注意力层（在 latent tokens 之间）以进一步交互
  • 输出: L 个视觉摘要 token（尺寸固定为 L x d_llm），L = 通常 64
  • 为什么是 64？: 消融实验表明 64 是信息容量与计算效率的最佳折中。更少的 token（如 16）导致信息损失，更多的 token（如 256）增加计算开销而收益递减

Step 3：门控交叉注意力注入

  • 输入:
    • L 个视觉摘要 token（来自 Step 2）
    • LLM 中每一层的文本隐藏状态 H_text（来自自注意力层的输出）
  • 操作:
    • 在 LLM 的每一个 Transformer 层中，在自注意力之后、FFN 之前插入额外的交叉注意力层
    • 交叉注意力：queries = H_text, keys = X, values = X（X 为视觉 token）
    • 门控机制：输出 = tanh(alpha) * CrossAttention(H_text, X) + H_text
    • tanh(alpha) 是门控参数，alpha 初始化为 0，tanh(0) = 0
    • 训练初期：门控输出为 0，LLM 以纯文本模式运行——保护预训练知识
    • 随着训练推进：alpha 增大，tanh(alpha) 从 0 增长到接近 1——视觉信息渐进式融入
  • 输出: 视觉增强的文本隐藏状态
  • 门控的深层机制: 门控不只在训练初期保护 LLM，更在每层独立学习如何融合视觉信息。不同层的 tanh(alpha) 最终值可能不同：
    • 浅层的 alpha 可能较小（不融合太多底层视觉信息到语言处理中）
    • 深层的 alpha 可能较大（在高层语义处理中更依赖视觉信息）

Step 4：文本生成

  • 输入: 视觉增强的文本表示（经过所有 Transformer 层处理后）
  • 操作:
    • LLM（Chinchilla 70B）在视觉增强的文本表示基础上进行自回归生成
    • 生成时支持图文交错输出——可以在生成文本的中间位置插入图像
    • 对于多图像输入：不同图像的视觉 token 通过 Perceiver 独立处理后，按其原始位置插入文本序列
    • 对于视频输入：多帧的视觉 token 按时间顺序插入
  • 输出: 文本（可包含图像标记）
  • 与纯文本生成的区别: 在每一步自回归生成时，已生成的 token 能通过因果注意力看到所有之前 token（包括图像 token），从而在生成决策中持续利用视觉上下文

关键结果

16 个基准上的 Few-shot 表现

Flamingo（80B 参数，3 个变体）在 16 个多模态基准中 6 个以 few-shot 设置超越了使用完整训练集微调的 SOTA 模型。

Few-shot 示例数的平滑提升

与 LLM 的涌现性（emergent abilities）不同，Flamingo 在 0-shot -> 4-shot -> 8-shot -> 32-shot 上展现了近乎平滑单调的性能提升曲线。关键发现：

  • 0-shot 到 4-shot：最大跳跃（平均 +8-12 个百分点）
  • 4-shot 到 8-shot：小幅提升（+2-4 个百分点）
  • 8-shot 到 32-shot：继续提升但边际递减（+1-3 个百分点）

这一平滑曲线说明多模态 ICL（上下文学习）与纯文本 ICL 不同——多模态 ICL 不存在突然涌现的”临界点”，而是从极少量示例（4-shot）开始就稳定受益。这暗示多模态 few-shot 学习的机制可能与纯文本不同——视觉示例为模型提供了直接的”模板”而非间接的”推理模式激活”。

深度分析

Perceiver Resampler 为什么必要

视觉编码器通常输出数百到数千个 patch token，直接注入 LLM 会导致：

  1. 计算复杂度爆炸: 注意力机制的复杂度为 O(N^2)，1000 个视觉 token 意味着自注意力中 100 万次交互，且每个 token 都要与文本 token 交互
  2. 文本信息淹没: 如果视觉 token 远多于文本 token，LLM 的注意力会被视觉信息主导，降低语言理解能力
  3. 注意力模式破坏: LLM 经过训练优化了文本 token 之间的注意力模式，突然注入大量视觉 token 会破坏这种模式

Perceiver Resampler 将视觉信息压缩为固定 64 token 是空间/信息的高效折中：

  • 保留足够视觉细节的同时控制计算成本
  • 64 个 token 大约与 2-3 个句子的文本长度相当——在 LLM 的注意力预算中占比合理
  • 实验表明 64 token 下损失的视觉信息对大多数任务影响很小（对比 128 token 的微小提升）

Resampler 的工作原理：可以类比为一个人看一张图并做笔记——不是用 1000 个词描述每个像素，而是用 64 个要点总结关键信息。latent query token 就是模型学习的”注意要点”的能力。

门控机制的巧妙性

tanh(alpha) 从 0 开始（alpha 初始化为 0），意味着训练初期视觉交叉注意力输出为零——LLM 最初以纯文本模式运行。随着训练，alpha 逐渐增大，视觉信息逐步融入。

这种”先文本后视觉”的设计确保了：

  1. 保护 LLM 知识: 训练初期 LLM 不受视觉信息的”干扰”，其预训练的文本理解能力完全保留
  2. 渐进式对齐: 视觉信息不是一次性注入而是逐步融入——模型有时”学会”如何利用视觉信息，而不是被视觉信息”冲垮”
  3. 可解释的门控: 我们可以查看每层 tanh(alpha) 的值来理解视觉依赖程度——某些层可能完全关闭视觉输入（tanh(alpha) 接近 0），说明该层不需要视觉信息
  4. 自然的正则化: 如果视觉信息对某个任务有害（误导），门控会自动降低 tanh(alpha)，这是一种内置的”鲁棒性开关”

与 residual connection 的关系：门控交叉注意力本质上是一个条件化的残差连接——视觉信息作为残差叠加到文本表示上。门控参数控制残差的规模。这种设计与 ResNet 的核心思想一脉相承：让网络学习”需要时添加残差，不需要时跳过”。

三组件冻结策略

Flamingo 仅训练连接模块和相关组件（约 10B），冻结视觉编码器和 LLM——这在 2022 年是极为前瞻性的设计选择：

组件 参数量 可训练? 理由
NFNet-F6 视觉编码器 ~500M 否（冻结） 保留预训练的视觉理解能力
Chinchilla 70B LLM 70B 否（冻结） 保留预训练的语言能力
Perceiver Resampler ~2B 是 需要学习视觉-语言映射
门控交叉注意力层 ~8B 是 需要学习如何层融合视觉信息
总计 ~80B ~10B (12.5%) –

这种冻结策略后来被 BLIP-2（冻结+冻结+Q-Former）和 LLaVA（冻结+冻结+线性投影）验证为最优范式。其核心洞见是：

  • 不要重新训练已经学会的东西: 视觉编码器已经知道如何看，LLM 已经知道如何理解语言——唯一需要学习的是两者之间的”翻译”
  • 计算效率: 只训练 12.5% 的参数，训练成本降低约 8 倍
  • 灾难性遗忘防护: 冻结编码器和 LLM 天然避免了灾难性遗忘——不会因为视觉训练而忘记文本知识

Flamingo 是整个现代 VLM 架构的”设计蓝图”——它的三组件冻结策略、连接模块设计和交织预训练理念被后续几乎所有 VLM 继承或参考。

局限

1. 闭源且不公开数据: Flamingo 模型权重和训练数据均未公开，仅为技术报告。这不仅影响可复现性，更阻碍了社区对 VLM 安全性和公平性的独立研究。开源社区只能通过观察 Flamingo 的行为来逆向工程其架构细节——这与现代 AI 研究的开放科学原则背道而驰。

2. 视觉编码器瓶颈: NFNet-F6 在 2022 年时是最先进的卷积网络之一，但与后续的 ViT-G/DFN（Data Filtering Network）和 SigLIP 相比有明显差距。视觉编码器的质量直接影响 VLM 的上限——如果视觉编码器无法准确识别物体，LLM 再强大也无济于事。Flamingo 的某些视觉 QA 任务上的表现受限于此。

3. 训练成本极高: 尽管仅训练 10B 参数，但”训练”与”推理”是两个独立概念——405 亿图文交错 token + 18 亿图文对需要在前向过程中通过冻结的 70B LLM 和 NFNet——反向传播虽只更新 10B 参数，但前向传播仍需全模型计算。这导致训练需要在 TPUv4 大规模集群上进行，成本对多数研究机构来说难以承受。

4. 推理延迟: Perceiver Resampler + 每层额外的交叉注意力增加了推理开销：

  • 每张图像需要经过 Perceiver（推理时不可跳过——即使只有 1 张图）
  • 每层 LLM 需要计算额外的交叉注意力（比纯文本多约 10-20% 的 FLOPs）
  • 对于多图像/视频输入，Perceiver 需要对每帧独立处理后再聚合——线性增加
  • 这种开销量级虽然可接受，但在实时应用中（如机器人、AR）可能成为瓶颈

5. Perceiver 的信息压缩损失: 将任意大小的视觉特征压缩为固定 64 个 token 必然存在信息损失：

  • 对于简单图像（单一物体，简单背景），64 token 可能冗余（信息过拟合）
  • 对于复杂场景（拥挤场景，大量细节），64 token 可能不足（信息欠拟合）
  • 没有自适应的压缩率——无论输入复杂度如何，总是 64 token
  • 理论上，动态压缩率（复杂场景用更多 token，简单场景用更少）会更优，但设计复杂度高

6. Few-shot 性能的不一致性: 虽然 Flamingo 在 6 个基准上超越了微调模型，但在 10 个基准上仍逊色。特别是：

  • VQAv2 上差距仍大（63.1 vs 76.4）——通用视觉问答仍是挑战
  • TextVQA 上差距大（36.1 vs 54.2）——OCR/文字相关任务薄弱
  • COCO Caption 上差距大（CIDEr 99.8 vs 138.0）——few-shot 描述质量不如全微调

7. 长距离推理的局限: Few-shot 示例以图文交错的形式提供，但在长示例序列中：

  • 早期示例可能被后方的示例”遗忘”
  • 视频理解中，多帧信息通过 Perceiver 聚合时缺乏帧间精细交互
  • 复杂的多跳推理（如”A 与 B 的关系是什么？B 与 C 呢？A 与 C 呢？”）在 few-shot 下准确率快速下降

8. 对视频任务的粗糙处理: Flamingo 将视频视为”图片序列”——每帧独立通过视觉编码器，然后通过时间感知 Perceiver 聚合。这种方法丢失了帧间的运动信息和光流信息——模型可能知道”第 1 帧有什么，第 2 帧有什么”，但不一定理解”物体从第 1 帧到第 2 帧在向左移动”。

可复用洞见

  1. 冻结策略是 VLM 的正确路径：将视觉编码器和 LLM 冻结，仅训练连接模块——这一范式被后续工作反复验证为最优。其深层原理是”不要动已经工作的部分，只连接它们”。

  2. 门控初始化为零：在引入新的模态信息时，从”无影响”开始渐进式学习——这一技巧可广泛用于多模态和 adapter 设计。它不仅适用于视觉-语言，也适用于任何”向预训练模型注入新模态”的场景。

  3. 交织训练 > 图文对训练：模型看到图文交错的数据能更好地理解多模态对话模式。这是从”理解图像”到”理解图文组合”的质变——few-shot 能力本身来源于对”多模态上下文”的理解，而非对”单图描述”的理解。

  4. Perceiver 是通用的模态压缩方案：将任意长度的模态特征压缩为固定数量”摘要 token”的思路不仅适用于视觉，也可延伸到音频、传感器数据、点云等任意模态。

  5. few-shot 能力是可训练的：Flamingo 证明多模态 few-shot 学习不是零样本方法的附加福利，而是可以通过专门的数据格式（图文交错）来显式训练的。这对设计下一个 VLM 的预训练目标有直接指导意义。

我的笔记

Flamingo 是我心中”写论文的黄金标准”——它的贡献不是”多做 0.1 个点”，而是定义了一整个领域的技术架构。当 2024 年的 LLaVA-NeXT、Qwen-VL、InternVL 仍然在使用”冻结视觉编码器 + 冻结 LLM + 可训练连接模块”时，你就知道 Flamingo 在 2022 年做的是多么超前的工作。

关于架构的”简洁之美”: Flamingo 的架构本质上只有三个组件：Perceiver Resampler、门控交叉注意力、数据混合策略。这三个组件各自解决一个问题：Perceiver 解决维度不匹配，门控解决模态融合，数据混合解决 few-shot 能力。每个组件都是”必要且充分”的——一个优雅的架构不需要更多的复杂度。

关于”为什么是 Flamingo 而不是其他人”: 在 2022 年初，绝大多数研究者认为”视觉+语言”应该像 CLIP 那样做对比学习，或者像 ViLT 那样做联合编码。Flamingo 独辟蹊径地看到了 LLM 的潜力——“如果把 70B 的 Chinchilla 拿来当多模态模型的大脑会怎样？”这是一个反共识的假设，但结果证明它的方向是对的。这让我反思：在 AI 研究中，最大的进步往往来自”连接两个看似无关的大型组件”，而不是”在现有组件上做微创新”。

关于门控初始化 = 0 的精妙性: 这是我职业生涯中见过的最简单但最有效的”工程技巧”之一。tanh(0) = 0 意味着训练开始时视觉信息不产生任何影响——这在数学上保证了 LLM 在第 0 步的行为与纯文本 LLM 完全一致。整个训练过程相当于从”纯文本模式”向”多模态模式”的平滑过渡。这种设计哲学——“不要让新信息一开始就干扰已有知识”——在几乎所有 adapter / fine-tuning 场景中都有用。LoRA 的初始化策略（B=0）其实也是同一哲学的不同实现。

关于闭源的遗憾: Flamingo 在研究中被广泛引用，在工程中却几乎无法使用——因为它不开源。这种”论文影响力巨大但实用价值受限”的矛盾在 DeepMind/Google 的论文中反复出现。这也解释了为什么 LLaVA 的”10M 参数的线性投影”虽然看起来”简陋”，却能获得社区的巨大关注——因为它是能跑得动的。

关于论文的”时机”: Flamingo 发表在 2022 年 4 月——正是 GPT-3 上下文学习能力被广泛讨论的时期。Flamingo 敏锐地将”few-shot 上下文学习”的概念从纯文本迁移到多模态，证明了多模态 ICL 不仅是可行的，而且效果惊人。这种”借势”——将一个领域的热门概念迁移到另一个领域——是高水平研究中的常见模式。

后续问题

  1. Perceiver Resampler 的压缩效率有没有理论上界？64 个 latent token 在什么任务上开始成为瓶颈？
  2. 如果使用更强的视觉编码器（如 ViT-G/14 + DFN），Flamingo 的表现提升是否线性？还是存在”视觉能力过强导致语言能力被抑制”的递减效应？
  3. 门控交叉注意力能否推广到三个以上模态——如同时注入视觉、音频、触觉信息，每个模态有独立的 tanh(alpha)？
  4. 交织数据的自动构建：能否利用 LLM 从大规模网页中自动筛选和标注多模态对话模式？
  5. Flamingo 架构中的 Perceiver 是否可以升级为 Q-Former（BLIP-2 的改进）或更现代的架构，在保持固定输出的同时提升信息保留率？
