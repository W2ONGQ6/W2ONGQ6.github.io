GPTQ: Accurate Post-Training Quantization for Generative Pre-trained Transformers

核心信息

  • 作者: Elias Frantar, Saleh Ashkboos, Torsten Hoefler, Dan Alistarh (IST Austria, ETH Zurich)
  • 发表: ICLR 2023 (oral)
  • arXiv: 2210.17323
  • 代码: IST-DASLab/gptq
  • 关键词: Post-Training Quantization, Optimal Brain Quantizer, Hessian-based, 4-bit, Layer-wise

GPTQ 是大语言模型后训练量化领域最具影响力的工作之一。它将经典的 Optimal Brain Surgeon（OBS）剪枝框架推广到量化场景，提出 Optimal Brain Quantizer（OBQ）算法，并通过一系列关键技术优化（任意顺序处理、延迟批量更新、Cholesky 预处理），将 OBQ 的计算效率提升了数个数量级，使得在数小时内完成 175B 参数模型的 4-bit 量化成为可能。GPTQ 首次证明了 LLM 可以在不需要任何重训练的情况下，以极低的精度损失压缩到 3-4 bit，成为后续几乎所有 LLM 量化工作的核心对比基线。

原文摘要翻译

基于大规模数据集预训练的生成式大语言模型（LLM）在各种任务上展现出令人印象深刻的表现。虽然 GPT-3 这类模型可以通过 API 公开访问，但需要大量 GPU 内存的推理成本仍然是一个主要障碍。本文将 GPTQ 作为一种新的一次性权重量化方法，该方法基于近似二阶信息，既高度准确又高效。具体来说，GPTQ 能在约 4 个 GPU 小时内将 GPT 模型（参数规模达 1750 亿）量化到 3 或 4 比特，相对于未压缩的基线模型，精度下降可以忽略不计。与之前提出的一次性量化方法相比，我们的方法在压缩收益方面将压缩-精度的帕累托边界向前推进了一大步，同时允许在单个 GPU 上执行 1750 亿参数模型的推理以进行生成式任务。我们通过实验证明，无论是在困惑度还是零样本任务性能上，GPTQ 都能提供与较高精度基线相当的精度。同时，我们的方法还比使用更少 GPU 的 FP16 推理带来速度提升，足够高性能，可以用于极大规模的语言模型。

创新点

  1. 首次将 OBS 框架推广到量化: 将经典的 Optimal Brain Surgeon 从剪枝扩展为 Optimal Brain Quantizer（OBQ），逐列补偿量化误差。

  2. 任意顺序处理 + Cholesky 分解: 突破了 OBS 必须按 Hessian 对角元顺序处理的限制，通过 Cholesky 预处理使得可以按任意顺序量化权重，大幅简化实现。

  3. 延迟批量更新（Lazy Batch Update）: 将多个列的权重量化后的 Hessian 更新合并为一次 GEMM 操作，充分利用 GPU 并行性，使算法在 GPU 上高效运行。

  4. 首次实现大模型极低比特量化: 在 3-4 bit 精度下，OPT-175B 等模型的困惑度上升不超过 1.0，且可在单个 GPU 上完成推理。

一句话总结

GPTQ 将 Optimal Brain Surgeon 推广到量化场景，通过 Cholesky 预处理和延迟批量更新实现 GPU 友好的高效二阶量化，首次在数小时内将 175B 模型压缩到 3-4 bit 且精度几乎无损。

研究问题

LLM 推理面临巨大的 GPU 内存瓶颈。FP16 格式下，175B 模型需要约 350GB 显存，远超单 GPU 容量。虽然知识蒸馏、剪枝等方法可以压缩模型，但往往需要大量额外的重训练，对于最大规模的模型来说成本极其高昂。一次性的后训练量化（PTQ）方法可以避免重训练，但现有的 PTQ 方法（如 ZeroQuant、LLM.int8()）在低于 8-bit 时精度急剧下降。核心问题在于：能否在不需要任何重训练的情况下，将 LLM 压缩到 3-4 bit 且保持几乎不变的精度？

Optimal Brain Surgeon（OBS）的核心思想是：当剪掉权重 w_q 时，通过更新所有剩余权重来补偿剪枝带来的误差，更新公式为：

3. GPTQ 的三个关键优化

优化1: 任意顺序处理（Arbitrary Ordering）

OBQ 要求按 H^{-1} 对角元贪心选择顺序，但 GPTQ 证明：在固定非贪心顺序下（如自然列顺序），量化质量几乎不受影响。关键技巧是始终使用同一行/列对应的完整 Hessian 信息，只是通过 Cholesky 分解预计算必要的信息。

具体做法：对 H^{-1} 进行 Cholesky 分解 H^{-1} = LL^T，其中 L 是下三角矩阵。此时 [H^{-1}]{qq} = ||L{q,:}||_2^2，且对第 q 行的更新简化为仅与 L 相关的高效操作。

优化2: 懒惰批量更新（Lazy Batch Updates）

GPTQ 的核心创新：不立即对每个量化后的权重更新 Hessian，而是累积 B 列（B=128）的更新，一次性批量应用。公式为：

这将以列为单位的更新转化为矩阵乘法 GEMM，充分利用 GPU 的并行计算能力。实践中 B 的选择在精度和速度之间权衡。

优化3: Cholesky 预处理

重新构造 Hessian：H = 2XX^T + λI，对 H 而非 H^{-1} 做 Cholesky 分解。原因是数值稳定性更好，且能避免矩阵求逆的不稳定性。加入阻尼项 λ（通常取 mean(diag(H)) 的 1%），防止奇异。

为什么 GPTQ 如此有效？

1. 二阶信息的核心价值

从 OBS 继承的核心洞察是：权重的重要性不是孤立的，而是通过 Hessian 矩阵相互关联的。H^{-1} 的非对角元捕捉了权重之间的”可补偿性”——当权重 A 被量化损失精度时，哪些权重 B 可以调整来补偿这个损失。一阶方法（如 RTN）忽略了这种相互关系，导致某些层（尤其是注意力投影层）的量化误差急剧放大。

2. Cholesky 分解的巧妙之处

对 Hessian 而非其逆做 Cholesky 分解，使得算法可以按任意顺序处理列。这解决了 OBS 框架最大的实际障碍——必须按某种复杂顺序处理（原本是贪心选择 Hessian 逆对角元最小的行）。Cholesky 提供了一种对 H^{-1} 的”结构化”访问方式，允许在任何时候低成本地计算所需的 H^{-1} 行。

具体来说，Cholesky 分解 H = LL^T 后：

  • H^{-1} 的第 q 行可通过前向/后向替代（forward/backward substitution）高效计算
  • [H^{-1}]_{qq} = ||e_q^T L^{-T}||_2^2

3. “懒惰更新”与 GPU 效率

这是使算法在实际 GPU 硬件上可行的关键工程创新。将逐个权重的精确补偿替换为批量近似的矩阵乘法，虽然理论上略微降低了补偿精度，但通过批量大小 B 的调节（通常 128），可以在效率和精度之间取得极好的平衡。这本质上是一种计算-精度权衡的经典设计模式。

4. 逐层量化的必要性

虽然逐层量化忽略了层间误差的累积，但 GPTQ 的实验表明，对于大规模 Transformer 模型，这种忽略是可接受的。可能的原因是：大规模 Transformer 的残差连接和 LayerNorm 提供了一定的误差容忍能力，单层的小误差不容易跨层放大。

量化敏感层的识别

GPTQ 的分析揭示了一个重要规律：Transformer 中不同层的量化敏感度差异极大。注意力层的 Q、K、V 投影矩阵和输出投影矩阵通常比 FFN 层更敏感。原因在于：

  • 注意力层的输出直接影响注意力分布（softmax 的输入），微小误差可能被放大
  • FFN 层的激活分布更均匀，有较大的冗余信息

分组量化的作用

Group-wise 量化（group size = 128）相比 per-channel 量化的关键在于：它在每个 group 内部独立选择 scale 和 zero-point，使得量化网格更好地适配权重的局部分布。group 越小，量化精度越高但存储开销越大。group size = 128 是实践中被广泛接受的 sweet spot。

GPTQ 的独特优势在于：无需重训练的同时，凭借二阶信息实现极高的压缩质量。这使其成为从 HuggingFace 等平台下载模型后立即进行量化的理想选择。

与 AWQ 的关系

AWQ（Activation-aware Weight Quantization）是 GPTQ 之后另一个重要的 4-bit 量化方法。关键区别：

  • GPTQ: 基于权重的 Hessian 信息（二阶统计量）
  • AWQ: 基于激活值幅度（一阶统计量），通过缩放重要通道来减少量化误差

两者在实践中精度相当，但 AWQ 速度更快且硬件实现更友好。许多推理框架（如 vLLM、TensorRT-LLM）同时支持两者。

局限

  1. 无法处理激活值异常值: GPTQ 仅量化权重，激活值仍保持在 FP16。当激活值中存在极端异常值（如某些层的异常大值通道），量化后的权重矩阵推理仍可能产生大误差。这个问题在 SmoothQuant 等 W8A8 方法中通过”平滑”技术得到解决。

  2. 二阶信息计算成本: 对每个线性层计算 Hessian 并进行 Cholesky 分解仍然有一定计算开销（虽然已大幅优化），对于非标准架构可能需要适配。

  3. 校验数据偏差: 量化质量依赖于校准数据的分布。如果校准数据不能很好地代表实际推理时的输入分布，可能出现精度下降。

  4. 分组量化元数据开销: Group size = 128 时，额外的 scale 和 zero-point 存储约增加 0.1 bit per weight，在极低比特（2-bit）时这个开销比例变大。

  5. 生成质量评估不足: 论文主要评估困惑度和零样本任务准确率，缺乏人工评估的生成质量对比。

可复用洞见

  1. 二阶信息是关键: OBS/OBQ 思想——通过 Hessian 捕捉权重间的补偿关系——是量化质量的核心。这个思想可以推广到其他压缩任务，如剪枝（SparseGPT 直接继承了这个框架）和低秩分解。

  2. 懒惰批量更新设计模式: 将逐元素的精确操作转换为批量矩阵运算，牺牲少量精度换取 GPU 并行效率，是深度学习系统优化的通用设计模式。类似的思想在 FlashAttention（分块计算）中也有体现。

  3. 逐层压缩 + 校准数据: 不需要端到端训练也可以实现高质量压缩。关键在于每层独立优化时使用代表性的校准数据来近似层输入分布。

  4. Cholesky 分解的数值技巧: 对 H 而非 H^{-1} 做 Cholesky，并使用阻尼项防止奇异，是处理实际数据中病态 Hessian 的有效方案。

  5. Group 量化的重要性: Per-channel 量化的粒度过粗，per-element 量化存储开销过大，group-wise 量化提供了一个优雅的中间地带。

我的笔记

GPTQ 是 LLM 量化领域的分水岭论文。在它之前，普遍认为 4-bit 量化需要 QAT（量化感知训练）才能维持精度；GPTQ 证明了使用二阶统计信息的 PTQ 可以达到相同甚至更好的效果。

最令我印象深刻的是从 OBS 到 OBQ 再到 GPTQ 这一系列思想的演化：

  • OBS（1993）: 纯理论框架，计算量 O(n^4)，在神经网络上只在极小的 LeNet 上验证过
  • OBQ（2022）: 将 OBS 推广到量化，但复杂度仍太高
  • GPTQ: 通过三个关键优化，使 OBS 框架在 175B 模型上可行

这完美体现了”好想法需要好的工程才能落地”的研究哲学。OBS 框架的理论洞察（Hessian 捕捉权重相关性）是正确的，但需要 30 年的时间跨度才能在工程上实现（LeNet -> GPT-3 的规模）。

此外，GPTQ 和后续工作（SparseGPT、Wanda）的关系值得注意：同一研究组几乎同时将相同的 Hessian 框架推广到量化（GPTQ）和剪枝（SparseGPT），展示了基础理论的通用性。

在实际使用中，GPTQ 模型在推理时需要特定的 kernel 支持（如 AutoGPTQ 中的量化矩阵乘法 kernel），这增加了部署的复杂性。但在 vLLM、TGI 等流行推理框架中原生支持后，这个障碍已经大大降低。
