InstructPix2Pix: Learning to Follow Image Editing Instructions

InstructPix2Pix: 学习遵循图像编辑指令

  • 机构: UC Berkeley

原文摘要翻译

我们提出 InstructPix2Pix，一种学习遵循人类指令进行图像编辑的方法。给定输入图像和一条文字指令告知模型该做什么，我们的模型将遵循这些指令编辑图像。为了训练模型，我们结合了两个大型预训练模型的知识——语言模型（GPT-3）和文生图模型（Stable Diffusion）——来生成一个大规模的成对训练数据集。具体来说，我们使用 GPT-3 从图像标题生成编辑指令和编辑后标题，然后使用 Prompt-to-Prompt 编辑生成对应的编辑前后图像对。尽管使用完全合成的数据进行训练，但模型可很好地泛化到真实的用户指令和真实的输入图像。我们的模型在单次前向传播中以惊人的速度执行编辑——推理约 4 秒（在单张 A100 上）。InstructPix2Pix 支持多种编辑类型，包括替换物体、改变风格、调整季节天气、修改材质纹理等。这一工作展示了将两个大型预训练生成模型的知识结合起来生成大量成对训练数据的可行性，从而将图像编辑重新定义为指令遵循问题。

创新点

1. 图像编辑 = 指令遵循任务

核心思想: 将图像编辑从传统的”工具操作”（画笔、套索、蒙版）和”像素操作”重新定义为”指令遵循”——给定图片和一句话，模型直接输出编辑结果。用户说”把天空变成极光”，模型直接执行。

为什么重要: 这是人机交互范式的根本改变。传统图像编辑需要专业技能（Photoshop 操作），指令式编辑将门槛降到了”会说话就会编辑”。这也是生成式 AI 从”创造”到”修改”的重要扩展——从”你看我画了什么”进化到”你看我把你的图变成了什么”。

更深层的范式意义: InstructPix2Pix 重新定义了”编辑”——不再是像素空间的变换（传统方法）、潜在空间的插值（GAN-based）、或注意力图的操控（Prompt-to-Prompt），而是”一个自然语言指令到像素变换的映射”。这种高层抽象的编辑范式使”编辑”的概念从”操作序列”变成了”意图传达”。

2. 全自动合成训练数据 Pipeline

核心思想: 无需人工标注，通过三大预训练模型的协作自动生成训练数据：(1) GPT-3 生成”原描述 + 编辑指令 + 编辑后描述”三元组；(2) Stable Diffusion + Prompt-to-Prompt 基于描述生成成对图像。总计约 45 万对”编辑前-编辑后”训练样本。

为什么重要: 这是论文最巧妙的地方——它不需要任何真实的图像编辑对。训练数据完全由 AI 生成，但模型在真实用户图片和真实指令上泛化得很好。这证明了”合成数据 + 大规模预训练”在视觉领域的威力——即使数据本身是”假”的，模型学到的编辑理解是”真”的。

数据工程的三级协作模型:

  • Level 1 (GPT-3): 语言层面的”编辑合理性”——知道什么样的编辑指令是自然的
  • Level 2 (Stable Diffusion + P2P): 视觉层面的”编辑一致性”——生成的前后图像在编辑区域外保持一致
  • Level 3 (指令条件扩散模型): 从合成的”伪 oracle”中学习”编辑行为”

3. 指令条件扩散模型的单次前向编辑

核心思想: 基于 Stable Diffusion 架构，将输入图像和编辑指令同时作为条件。输入图像通过 VAE 编码器变为潜变量（与噪声潜变量拼接），编辑指令通过 CLIP 编码为文本嵌入（作为交叉注意力的条件）。在单次去噪过程中完成编辑，约 4 秒（A100）。

为什么重要: 与需要反演 + 编辑 + 重生成的 Prompt-to-Prompt 相比，InstructPix2Pix 的单次前向传播快得多。与需要逐样本微调的 DreamBooth 相比，它是一种零样本方法——训练一次即可处理任意图像和任意指令。与需要手动分割掩膜的传统方法相比，它对语义层面而非像素层面进行操作。

速度对比（定性）:

  • Prompt-to-Prompt: 数十步 DDIM 反演 + 数十步注入去噪 = 约 15-20 秒
  • DreamBooth: 微调 10-20 分钟 + 生成数秒
  • InstructPix2Pix: 单次前向 = 约 4 秒
  • 传统 Photoshop 编辑: 数分钟到数小时（人工）

一句话总结

InstructPix2Pix 通过 GPT-3 自动生成编辑指令三元组 + Prompt-to-Prompt 生成成对图像，构建了约 45 万合成训练数据，训练出一个能遵循自由形式自然语言指令进行图像编辑的扩散模型，将图像编辑从工具操作时代带入了自然语言指令时代。

研究问题

核心挑战

图像编辑历来是专业工具密集型任务。能否让用户直接用自然语言指令完成编辑，而无需学习任何工具？

关键的数据难题

真实图像编辑对的数据收集极其困难——需要同一个人先创作原图再编辑，或者需要专业注释者配对。这导致了经典的数据匮乏问题：如果我们需要配对数据来训练编辑模型，但我们又没有配对数据——怎么办？

子问题分解

  1. 指令生成: 如何自动生成多样化、有意义的编辑指令？GPT-3 能生成什么样的编辑指令？
  2. 成对图像生成: 如何确保生成的前后图像在编辑区域外保持一致？Prompt-to-Prompt 的注意力注入在此是必要条件还是充分条件？
  3. 模型架构: 如何在扩散模型中同时条件化输入图像和编辑指令？两者的信息如何融合？
  4. 泛化验证: 合成数据训练的模型能否泛化到真实用户照片和真实编辑需求？

关键洞察

AI 生成 AI 的训练数据。GPT-3 能生成合理的编辑指令，Stable Diffusion 能生成对应的图像。两者的输出虽然不完全真实，但足以训练一个学会”编辑”概念的模型。

机制流程

步骤 1: 指令三元组生成 (GPT-3)

  • 输入: 来自 LAION-Aesthetics 数据集的图像标题。示例标题：”a cat sitting on a wooden table in a sunny room”
  • 操作:
    • 构造 prompt 模板，引导 GPT-3 根据标题生成：(1) 一条编辑指令 (2) 编辑后的标题
    • Prompt 模板示例：”Given a caption describing an image, generate an edit instruction and the resulting edited caption. Caption: {caption}. Edit instruction: … Edited caption: …”
    • GPT-3 在 prompt 引导下生成符合格式的三元组：(原始标题, 编辑指令, 编辑后标题)
    • 过滤步骤：移除编辑后标题与原标题完全相同的样本（没有实际变化）、移除编辑指令过于模糊的样本（如”make it better”）、移除编辑后标题明显不合理的样本
  • 输出: 有效三元组 (原始标题 C, 编辑指令 I, 编辑后标题 C’)，共约 45 万个


Figure 2: 来源—原论文。

步骤 2: 成对图像生成 (Stable Diffusion + Prompt-to-Prompt)

  • 输入: 三元组 (原始标题 C, 编辑指令 I, 编辑后标题 C’)
  • 操作:
    • 使用 Stable Diffusion 和 Prompt-to-Prompt 技术生成成对图像
    • 具体流程：
      • 使用原始标题 C 通过 SD 生成图像 I_orig（原始图片）
      • 同时记录生成 I_orig 时的交叉注意力图
      • 使用编辑后标题 C’ 通过 SD 生成图像 I_edited（编辑后图片）
      • 在生成 I_edited 的过程中，注入步骤 1 记录的注意力图（Prompt-to-Prompt 的核心操作）
      • 注入目的：确保 I_orig 和 I_edited 在非编辑区域（如背景、构图）保持一致
    • 过滤步骤：
      • CLIP 相似度过滤：C 与 I_orig 的 CLIP 余弦相似度 > 阈值（确保原始标题与生成的原始图相关）
      • CLIP 方向性过滤：(I_orig, I_edited) 的变化方向与 (C, C’) 的变化方向在 CLIP 空间中的夹角 < 阈值（确保”编辑方向”与”描述变化方向”一致）
      • 过滤掉约 30% 的不一致样本
  • 输出: 成对图像 (I_orig, I_edited)，约 31 万对（约 45 万 * 0.7 通过过滤）

步骤 3: 指令条件扩散模型训练

  • 输入: 三元组 ((I_orig, I_edited), edit_instruction)
  • 模型架构: 基于 Stable Diffusion v1.5 的改进
    • VAE 编码器：将输入图像 I_orig 编码为潜变量 z_orig
    • 噪声潜变量 z_t 与 z_orig 在通道维度拼接（concat, 而非 add），作为 U-Net 的输入
    • 编辑指令通过 CLIP 文本编码器编码为文本嵌入，作为 U-Net 交叉注意力的条件
    • 额外的输入通道：由于 z_orig 与 z_t 拼接，U-Net 的第一层卷积的输入通道从 4 扩展到 8（或通过零初始化新增通道来保持兼容性）
  • 训练目标:
    • 标准扩散损失：L = E[||epsilon - epsilon_theta(z_t, t, z_orig, c_instruct)||^2]
    • epsilon_theta 是 U-Net 预测的噪声
    • 条件包括：噪声潜变量 z_t、噪声时间步 t、原始图像条件 z_orig、编辑指令条件 c_instruct
  • 训练细节:
    • 约 31 万合成训练样本
    • 图像分辨率 256x256（训练），推理时支持 512x512（通过 SD 的多分辨率泛化）
    • 训练约 1-2 天（A100 x 8）
  • 输出: 训练好的指令条件扩散模型


Figure 3: 来源—原论文。

步骤 4: 推理（编辑执行）

  • 输入: 真实用户图像 I_user + 编辑指令 “make it winter with snow”
  • 操作:
    • VAE 编码 I_user 得到 z_user
    • CLIP 编码编辑指令得到 c_instruct
    • 从随机噪声 z_T 开始去噪
    • 在每个去噪步，U-Net 以 z_user 和 c_instruct 为条件进行噪声预测
    • 使用 DDIM 采样（通常 20-50 步），Classifier-Free Guidance（CFG scale 通常 1.5-7.5）
  • 输出: 编辑后的图像
  • CFG 策略: 训练时以一定概率 dropout 条件（10-15% 的图像条件、10-15% 的文本条件），推理时使用 CFG 加权平衡：

深度分析

合成数据为什么有效

InstructPix2Pix 的成功揭示了一个深层原理：对于”编辑”这种高层语义任务，训练数据的真实性不是必要的——需要的是”编辑概念”的一致性。具体来说：

  1. GPT-3 生成的编辑指令覆盖了足够多样化的编辑类型：从物体替换到风格化、从场景调整到颜色修改——GPT-3 的文本-文本生成能力天然覆盖了丰富的编辑概念空间。这确保了训练数据的”指令多样性”——模型不会只学会几种固定的编辑模式。

  2. Prompt-to-Prompt 保证了编辑前后的图像在非编辑区域保持一致：这是合成数据”可用”的关键。如果生成的成对图像在背景、构图等方面随机变化，模型就无法学到”编辑的局部性”——它会以为编辑意味着”改变一切”。P2P 的注意力注入确保了”编辑”的语义是局部的、有针对性的。

  3. 扩散模型强大的图像先验使得模型在真实图像上不容易产生明显 artifacts：Stable Diffusion 的预训练分布极其广泛，模型在真实图像上的生成质量很高。即使训练数据是合成的，模型的”图像先验”仍然是真实的（因为 U-Net 从预训练权重初始化），因此编辑结果在像素级别保持自然。

  4. CLIP 过滤起到了质量门控的作用：CLIP 相似度过滤和方向性过滤移除了约 30% 的”坏样本”——这些样本如果被用于训练，会引入噪声。但过滤后剩下的 “干净样本” 提供了足够强的编辑信号。

换句话说，模型学到的不是”如何把这张特定的图变成那张特定的图”，而是”如何执行编辑指令这种抽象操作”。

与 Prompt-to-Prompt 的关系

两者形成编辑任务的互补：

维度 Prompt-to-Prompt InstructPix2Pix
编辑方式 修改注意力图 直接预测编辑后图像
需要训练 否（推理时注入） 是（需要预训练）
速度 慢（需反演 15-20 秒） 快（单次前向 4 秒）
控制粒度 词级（精确到 prompt 中的每个词） 语义级（理解整句指令的含义）
指令理解 弱（需要显式指定”哪个词变什么”） 强（理解自然语言指令）
输入要求 需要原始 prompt + 编辑 prompt 只需图像 + 编辑指令
编辑范围 只能编辑 prompt 中已描述的元素 可以编辑图像中的任何内容
泛化性 依赖生成的注意力图质量 泛化性强（指令条件训练）

核心差异: Prompt-to-Prompt 是”推理时操控”——不需要训练，但每次编辑都需要访问原始生成过程。InstructPix2Pix 是”训练时学会”——需要训练，但推理时只需图像和指令。

协同关系: 实际上，InstructPix2Pix 的训练数据正是用 Prompt-to-Prompt 生成的——这是一个”上游方法为下游方法提供数据”的典型案例。这也说明 Prompt-to-Prompt 的价值不仅在于自身作为编辑工具，更在于它使”自动生成编辑数据”成为可能。

Classifier-Free Guidance 的两维度权衡

InstructPix2Pix 推理时使用双重的 CFG：

  1. 图像引导强度 (cfg_image): 控制编辑结果与原图的相似程度

    • cfg_image 太高（> 2.0）：编辑不充分——模型过度”尊重”原图
    • cfg_image 太低（< 1.2）：编辑过度——模型可能改变非编辑区域
    • 最佳范围：1.5-1.8

  2. 文本引导强度 (cfg_text): 控制编辑遵循指令的程度

    • cfg_text 太高（> 10）：过度编辑——偏离原图太远，可能出现 artifacts
    • cfg_text 太低（< 5）：编辑不充分——指令没有被充分执行
    • 最佳范围：6.5-9.0

两者的交互: cfg_image 和 cfg_text 之间存在微妙的平衡——增加 cfg_text 通常需要同时适度降低 cfg_image，以让模型有”编辑空间”。这可以看作是一个二维的”编辑自由度”超参数空间。

训练数据生成 vs 模型编辑能力：因果关系分析

一个重要但未充分讨论的问题是：GPT-3 生成的指令分布决定了 InstructPix2Pix 能做什么不能做什么。具体来说：

  • GPT-3 倾向于生成”简单、直接”的编辑指令——如 “make it winter” 而非 “adjust the atmospheric conditions to simulate a winter environment with snowflakes falling at a 45-degree angle”
  • 这导致 InstructPix2Pix 在”简单直接”的指令上表现好，在”复杂冗长”的指令上表现差
  • GPT-3 对”空间关系”的表达能力较弱——很少生成 “move the cup to the left of the book” 这样的指令
  • 这导致 InstructPix2Pix 在空间关系的编辑上表现弱——不是模型能力不行，而是训练数据中几乎没有这样的样本

因果链: GPT-3 的能力 -> 合成指令的分布 -> 训练数据覆盖 -> 模型编辑能力的上限。这一因果链暗示：如果想扩展 InstructPix2Pix 的编辑能力，与其改进模型架构，不如改进指令生成策略（如使用更强更强的 LLM、构建更丰富的指令模板）。

局限

1. 复杂指令的准确性问题: 涉及计数（”三个苹果”）、精确位置（”左上角”）、多步操作（”先做A再做B”）的指令仍容易失败。这是因为：

  • 计数理解需要模型同时感知物体数量 + 目标数量 + 两者的差异——这是高级视觉-语言推理
  • 精确位置需要模型对空间关系有类似坐标级的理解，而扩散模型的潜变量空间分辨率有限
  • 多步操作本质上是组合的——错误在每一步中累积

2. 背景一致性的不完全保证: 虽然在合成训练时通过 Prompt-to-Prompt 尽力保持背景一致，但在模型训练后：

  • 非编辑区域可能出现微弱的颜色偏移、细节变化或风格泄露
  • 这种现象在真实照片上比在合成训练数据上更明显——因为合成数据中的背景一致性是”硬约束”（P2P 注入），但模型学习到的是”软约束”（统计规律）

3. 人脸编辑的身份保持问题: 处理人脸编辑时（如 “add a smile”, “make the person older”）：

  • 模型可能在全球性变化中改变人物的整体面部特征
  • 缺乏对人脸身份的显式约束——DreamBooth/InstantID 有专门的嵌入，但 InstructPix2Pix 没有
  • 导致编辑后的脸可能与原脸不够”像”——这在用户研究中是主要的失败模式之一

4. 合成数据分布的偏差: 虽然合成数据覆盖了丰富的编辑类型，但其分布可能与真实用户需求存在结构性偏差：

  • GPT-3 生成的编辑指令可能偏向于某些高频编辑模式（如物体替换 > 精确裁切）
  • LAION-Aesthetics 的标题分布（偏向自然风光和日常场景）与用户编辑需求（可能更偏向人像和产品照片）不一致
  • 合成图像的美学质量高度影响训练效果——如果 Prompt-to-Prompt 生成的某些类别图像质量偏低，模型在该类别上的编辑也会偏弱

5. 编辑尺度的不可控性: 模型难以控制编辑的”程度”——例如 “make it a little bit darker” vs “make it very dark”：

  • 模型对程度副词的理解是粗糙的——“a little” 和 “very” 可能产生几乎相同的效果
  • 缺少连续的控制参数（如 0 到 1 的编辑强度滑块）
  • 这降低了在需要精细控制的应用场景中的实用性

6. 对未见编辑类型的有限泛化: 虽然模型在未见指令上表现出色，但存在不可见编辑类型——如果一种编辑类型在训练数据中从未出现（如”把这张照片变成火柴人画风”），模型可能完全失败或产生无意义的结果。

7. 推理速度与交互性的差距: 约 4 秒的单次推理（A100）对于批量编辑来说足够快，但对于交互式编辑（用户输入指令，看结果，再微调指令，再看结果）来说仍不够实时。在消费级 GPU 上（如 RTX 3060），推理时间可能增加到 10-20 秒——离”实时编辑”还有距离。

8. 版权与数据使用的灰色地带: 训练数据（LAION-Aesthetics 标题）来源于公开发布的网页图片，但生成编辑指令的 GPT-3 是闭源模型，其训练数据中可能包含有版权的编辑指导文本。这种多层级的数据溯源使得数据合规性分析极为复杂。

可复用洞见

  1. 合成数据管线的三要素: 一个成功的合成数据管线需要 (a) 一个能生成多样性指令的语言模型 (b) 一个能产生一致性输出的生成模型 (c) 一个过滤低质量样本的评估机制。缺少任何一个，合成数据的质量都会下降。

  2. 预训练模型之间的”协同效应”: GPT-3（语言知识）+ SD（图像知识）+ P2P（一致性知识）-> InstructPix2Pix（编辑知识）——这个知识蒸馏链证明了”将多个预训练模型组合可以生成单个模型无法获得的新能力”。

  3. 编辑的”局部性”是可学习的: 通过 Prompt-to-Prompt 生成的”编辑区域外一致”的成对图像能让模型学会”编辑是局部的”——这个学习信号不能仅通过描述获得，必须通过示例获得。

  4. 双 CFG 的精细调优: cfg_image 和 cfg_text 的双轴控制是一种实用的推理时质量调优范式——在图像保持和指令遵循之间动态平衡。这种范式可推广到任何”多条件生成模型”中。

我的笔记

InstructPix2Pix 是我认为最有”工程智慧”的论文之一——它不追求方法的复杂度，而是追求管线的巧妙性。”用 AI 训练 AI”这一核心思想极其优雅，它解决了一个经典的 cold start 问题：没有数据训练模型，但没有模型又无法生成数据。破局之道是：不需要最好的数据，只需要”刚好够好”的数据。

关于论文的”实用主义”: CVPR 2023 上有很多刷 SOTA 的论文，但 InstructPix2Pix 的不同在于——它创建了一个全新的使用范式。”告诉我你想怎么编辑这张图”这种交互模式在 2022 年之前不存在，现在它已经内嵌在 Photoshop（Generative Fill）、Midjourney（Vary Region）等产品中。一篇论文的终极影响力不是”我比前人多刷了几个点”，而是”我定义了一种新的人机交互方式”。

关于 Prompt-to-Prompt 与 InstructPix2Pix 的”生态位”: Prompt-to-Prompt（2022.08）和 InstructPix2Pix（2022.11）只间隔了 3 个月，但两者代表了画像编辑的两种哲学。P2P 是”控制论”——精确操控模型的内部状态；IP2P 是”行为主义”——通过输入-输出对训练编辑行为。两种哲学不是对立的——P2P 为 IP2P 提供了训练数据，两者形成了上下游的协作关系。这种”上游理论突破驱动下游工程应用”的模式在 AI 研究中极其常见。

关于合成数据的信任问题: InstructPix2Pix 的成功证明了一个重要观点：对于高层语义的学习任务（如编辑、分类、推理），合成数据的”真实性”不是关键——关键是”概念一致性”。如果合成的 red->blue 编辑对和真实的 red->blue 编辑对在 “编辑概念” 的层面上是等价的（都在教模型”改变颜色”），那合成数据就完全可用了。这其实意味着我们思考”数据质量”时应该从”像素保真度”转向”概念保真度”。

关于论文的 scaling 潜力: InstructPix2Pix 的 31 万训练样本在当时看来已经很大，但在 scaling law 时代，这个数量其实还很小。更大的 GPT-4 + SDXL 生成的更高质量的合成数据 + 更大的模型 = 更强的编辑能力？这个 scaling 假设虽然未被论文验证，但直觉上应该成立。如果我是作者，接下来的实验方向就是：10x 数据、10x 模型、然后观察编辑能力的涌现。

后续问题

  1. 如果能用更强大的 LLM（如 GPT-4 或 Gemini）替代 GPT-3 生成编辑指令，模型的上限是否显著提升？指令的复杂性和多样性是否线性增长？
  2. 能否结合 RLHF 或 DPO 来对齐模型输出与用户偏好？编辑质量本身是主观的——“好编辑”依赖于人的审美判断。
  3. 多轮编辑（用户看结果 -> 修改指令 -> 再编辑 -> 再修改）是否可以通过维护”编辑历史”的上下文来提升多步编辑的一致性？
  4. InstructPix2Pix 的架构是否可以扩展到视频编辑——给定一个视频 + 一条编辑指令（”把白天变成夜晚”），模型编辑整个视频？
  5. 如何在保持编辑能力的条件下同时注入身份保持约束——使 InstructPix2Pix 和 InstantID 可以协同工作？
