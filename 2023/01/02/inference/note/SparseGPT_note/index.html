SparseGPT: Massive Language Models Can Be Accurately Pruned in One-Shot

核心信息

  • 作者: Elias Frantar, Dan Alistarh (IST Austria)
  • 发表: ICML 2023
  • arXiv: 2301.00774
  • 代码: IST-DASLab/sparsegpt
  • 关键词: One-Shot Pruning, Unstructured Sparsity, Hessian-based, Optimal Brain Surgeon, LLM Compression

SparseGPT 是大语言模型一次性剪枝领域的开创性工作。它将经典的 Optimal Brain Surgeon（OBS）框架重新设计为一种可以在大规模 Transformer 模型上高效运行的剪枝算法。核心思想是：基于 Hessian 矩阵的二阶信息，在剪掉权重的”同时”更新剩余权重以补偿剪枝带来的误差。与 GPTQ 同源（来自同一研究组），SparseGPT 证明了 LLM 可以在不需要任何重训练的情况下，一次性达到 50-60% 的非结构化稀疏度（unstructured sparsity），且困惑度上升极低。对于最大的模型，甚至可以在约 4 个 GPU 小时内完成剪枝。

原文摘要翻译

我们提出了 SparseGPT，这是第一种在单次操作中精确剪枝大规模语言模型的方法，无需任何重训练。SparseGPT 将大规模 Transformer 模型的剪枝问题视为一种大规模的稀疏回归问题，并通过一种新的大规模近似稀疏回归求解器来解决，该求解器效率足以在数小时内处理像 OPT-175B 和 BLOOM-176B 这样的最大开源模型。我们的实验表明，SparseGPT 在规模巨大的模型上效果惊人：只需 4 个 GPU 小时，我们就可以诱导 50-60% 的非结构化稀疏度，使其在困惑度上的增加极小。在极端稀疏度（如 80%）下，SparseGPT 仍然能够保持模型的准确性。与之前所有已知的从头训练和一次性方法相比，SparseGPT 显著推进了大规模剪枝的帕累托前沿。

创新点

  1. 将 OBS 框架简化为大规模场景: 重新设计了 Optimal Brain Surgeon——从必须按 Hessian 对角元顺序贪心剪枝，简化为固定顺序的行更新，通过矩阵求逆的秩-1 更新公式（Sherman-Morrison）高效实现。

  2. 大规模稀疏回归求解器: 将剪枝问题构建为逐行的稀疏回归问题：在每行上，选择 sparsity% 的最大权重保留，将其余权重设为零，同时用保留的权重更新来补偿剪枝误差。

  3. 自适应掩码选择: 核心创新——不是在选择权重之前补偿误差（OBS 做法），而是迭代更新剩余权重的过程中动态调整哪些权重被保留。剪枝掩码 M 和权重更新交替进行。

  4. 一次性完成、量化级效率: 不需要任何重训练、不需要多轮迭代。对最大模型（175B）的剪枝仅需 4 GPU 小时，与 GPTQ 的量化速度相当。

一句话总结

SparseGPT 将 OBS 框架重新设计为固定顺序+自适应掩码的大规模稀疏回归，首次在无需重训练的情况下一次性将 175B 模型剪枝到 50-60% 稀疏度且精度几乎无损。

研究问题

剪枝是模型压缩的重要技术路线，但传统方法要么需要大量的重训练（迭代剪枝、基于梯度的剪枝），要么在 LLM 规模下精度崩溃（幅度剪枝等简单方法）。核心挑战在于：能否找到一种无需重训练的一次性剪枝方法，在 LLM 上实现高稀疏度（50%+）的同时保持模型精度？

这个问题本质上比量化更困难。量化是将权重映射到有限的离散集合，而剪枝是将权重设为零——丢失了信息。OBS 框架在理论上可以通过 Hessian 信息补偿剪枝误差，但经典的 OBS 算法复杂度为 O(n^4)，在 LLM 上完全不可行。

1. 问题重构：剪枝 = 稀疏回归

SparseGPT 将剪枝问题重新定义为逐行的稀疏回归。对于权重矩阵 W 的第 i 行 w_i：

4. 分块处理（Block-wise Processing）

类似于 GPTQ 的批量更新，SparseGPT 将权重矩阵的列分成块（block size B = 50-150），逐块进行剪枝和补偿。这有两个好处：

  • 利用 GPU 的矩阵运算批量处理，提高效率
  • 避免对整个矩阵进行 Hessian 更新，控制内存使用

除了非结构化稀疏，SparseGPT 还支持半结构化稀疏模式（如 NVIDIA 的 2:4 稀疏），这种模式对 GPU 硬件加速友好。在 2:4 稀疏中，每连续 4 个权重中恰好有 2 个为零。SparseGPT 通过修改掩码约束（每 4 个权重中选 2 个最大的）即可适配。

规模效应：越大越好剪

SparseGPT 最惊人的发现可能是规模效应：模型越大，剪枝后的精度损失越小。OPT-175B 在 50% 稀疏度下的困惑度增量仅为 +0.08，而 OPT-125M 为 +2.29。这个趋势强烈且一致：

这个发现具有深远的含义：更大的模型不仅能力更强，而且更具”可压缩性”。有几种可能的解释：

  1. 大模型有更多的冗余参数，剪掉一部分不影响整体功能
  2. 大模型的参数空间更平滑，Hessian 矩阵条件数更好
  3. 大模型的过参数化程度更高，有效维度远低于标称参数数量

二次信息 vs. 一次信息：Hessian 为什么重要

SparseGPT 论文通过消融实验清晰地展示了 Hessian 信息的价值。如果仅使用权重大小（幅度剪枝）来选择掩码，困惑度会从 10.13 爆炸到 769.80。而加入 Hessian 引导的误差补偿后，困惑度仅上升到 10.32。

这背后的数学原理是：权重的重要性不是由其绝对值单独决定的，而是由其被剪除后在 Hessian 度量下的误差贡献决定的。具体来说，剪掉权重 w_q 导致的损失函数增加为：

这意味着：一个数值很大的权重如果其对应的 Hessian 逆对角元也很大（意味着可以通过其他权重很好地补偿），实际上并不重要；反之，一个数值很小的权重如果其 Hessian 逆对角元很小（难以补偿），可能是致命的。

非结构化 vs. 半结构化剪枝

论文的一个重要对比是：

  • 非结构化 50% 稀疏（OPT-13B）：+0.19 PPL
  • 半结构化 2:4 稀疏（OPT-13B）：+0.67 PPL

虽然 2:4 也是 50%，但精度损失更大。这是因为 2:4 对掩码施加了硬约束（每 4 个连续权重中必须有 2 个为 0），限制了自适应掩码搜索的自由度。然而，2:4 稀疏在 NVIDIA Ampere GPU 上可以获得 2x 的矩阵乘法加速，而非结构化稀疏在通用 GPU 上几乎无法加速。

自适应掩码 vs. 固定掩码

SparseGPT 的自适应掩码是其相对于其他 OBS 变体的关键改进。与传统的 “先选掩码、再补偿” 策略不同，SparseGPT 在补偿过程中动态调整掩码。这种自适应性使得最终的掩码方案更接近全局最优。

一个关键的实现细节是：SparseGPT 使用 “Hard Thresholding” 机制——在每次迭代中保留 k 个绝对值最大的权重。这本质上是 Iterative Hard Thresholding（IHT）在 Hessian 度量下的推广。

局限

  1. 非结构化稀疏的硬件加速困难: 尽管理论上可以剪掉 60% 的参数，但通用 GPU 对非结构化稀疏的加速支持有限。实际部署中，要么接受无加速（仅节省内存），要么使用半结构化 2:4 稀疏（性能略差）。

  2. 无重训练的限制: 虽然一次性剪枝很方便，但缺乏微调意味着剪枝后的模型无法”适应”稀疏化带来的分布偏移。对于需要极高精度的场景，可能需要少量微调。

  3. 逐层独立剪枝: 每层独立剪枝忽略了层间的相互影响和误差传播。虽然实验表明对于 Transformer 架构这种忽略是可接受的，但在更深的网络上可能累积误差。

  4. 任务特定性不足: 校准数据来自 C4 通用语料，可能无法最优地适应特定下游任务。如果需要为特定任务优化稀疏模式，可能需要任务特定的校准数据。

  5. 对激活函数和结构的假设: SparseGPT 假设激活值是线性层的输入（可以收集 Hessian），对于非标准组件（如自定义 activation 后的层），可能需要额外适配。

可复用洞见

  1. 规模越大越可压缩: 这可能是 SparseGPT 最反直觉但最重要的发现。在考虑压缩策略时，不应假定大模型比小模型更”脆弱”——恰恰相反。

  2. 自适应掩码 + Hessian 补偿: 将掩码选择和误差补偿交替进行，而非串行执行，可以获得更好的整体优化。这对其他组合优化问题也有启发。

  3. Sherman-Morrison 用于高效行更新: 秩-1 更新的数学技巧使得 O(n^3) 的 Hessian 逆更新降低到 O(n^2)，这是使 OBS 框架在大规模场景中可行的关键数学工具。

  4. 一次性方法的规模边界: SparseGPT 证明了对足够大的模型，一次性方法可以达到与迭代方法相当的精度。但规模阈值在哪里，以及如何预测，仍需要更多研究。

  5. 半结构化稀疏的现实约束: 2:4 稀疏虽然精度略低，但因为有硬件加速，在实践中可能比 50% 非结构化稀疏更有价值。这是一个算法精度和硬件效率权衡的典型案例。

我的笔记

SparseGPT 和 GPTQ 是同一研究组围绕 Hessian 框架的双子星。两者共享核心思想（OBS → 大规模高效版本），但面向不同压缩范式（量化 vs. 剪枝）。阅读这两篇论文可以深刻理解二阶信息在模型压缩中的普适价值。

我认为 SparseGPT 最具启发性的发现是规模效应的”单调性”：模型越大，剪枝精度损失越小，且这个趋势在 OPT 系列上从 125M 到 175B 一直成立。这暗示了一个深层属性——大语言模型的”有效参数数量”可能远低于其标称参数数量，存在大量的”过度参数化”。

与 Wanda 的对比也很有意思。Wanda 用极其简单的一阶准则（|W|·||X||_2）就取得了与 SparseGPT 接近的效果，这说明 Hessian 虽然在理论上更优，但在足够大的模型上，简单启发式已经够用——或者反过来，Wanda 隐式地近似了 Hessian 的某些关键性质。

从实用角度看，SparseGPT 最直接的应用场景可能是：在内存受限的环境中运行大模型（内存节省），或与其他压缩技术（量化、蒸馏）叠加使用实现更高压缩率。

后续问题

  1. SparseGPT 剪枝后的模型结构是否存在可解释的模式？某些类型的层（注意力 vs. FFN）是否有不同的最优稀疏度？
  2. 能否将 SparseGPT 的思想推广到结构化剪枝（如剪除整个注意力头或 FFN 中间维度）？
  3. SparseGPT + 微调的组合是否能在极高稀疏度下恢复精度？
  4. MoE 架构如何应用 SparseGPT？不同专家的稀疏度是否应该不同？
  5. 稀疏化的权重矩阵是否对某些攻击（如对抗样本、数据投毒）更脆弱？
  6. 能否在训练过程中使用 SparseGPT 作为”稀疏化调度器”，实现渐进式稀疏训练？
