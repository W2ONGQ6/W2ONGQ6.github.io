Wanda: A Simple and Effective Pruning Approach for Large Language Models

核心信息

  • 作者: Mingjie Sun, Zhuang Liu, Anna Bair, J. Zico Kolter
  • 发表: ICML 2024 (Spotlight)
  • arXiv: 2306.11695
  • 代码: locuslab/wanda
  • 关键词: Pruning, Activation-Aware, Magnitude Pruning, Unstructured Sparsity, Wanda

Wanda（Pruning by Weights AND Activations）是 LLM 剪枝领域的一次”简化革命”。它的核心思想极其简单：评估每个权重的重要性时，同时考虑权重的绝对值和对应输入激活值的 L2 范数，即使用乘积 |W_ij| × ||X_j||_2 作为重要性分数（权重矩阵的第 i 行第 j 列 × 激活值第 j 个通道的 L2 范数）。令人惊讶的是，这个如此简单的一阶准则在剪枝质量上几乎与 SparseGPT（基于 Hessian 二阶信息）持平，而计算开销仅为幅度剪枝的水平。Wanda 证明了：在 LLM 剪枝这个看似需要复杂二阶方法的问题上，一个经过精心设计的简单准则已经足够。

原文摘要翻译

大语言模型（LLM）的规模带来了巨大的计算成本。最近，SparseGPT 表明，大规模 LLM 可以在不需要任何重训练的情况下被精确地剪枝到高稀疏度。SparseGPT 基于 Optimal Brain Surgeon 框架，这使其成为一个复杂的方法。在本文中，我们展示了这样一个复杂的框架对于精确剪枝并非必要——我们提出了 Wanda（Pruning by Weights AND Activations），一种新颖的、简单的一步式剪枝方法。Wanda 通过一级数据驱动准则评估权重重要性：权重大小与对应输入激活 L2 范数的乘积。我们观察到，这一简单的乘积度量与 SparseGPT 等更复杂的方法具有很高的相关性。Wanda 在各种大规模语言模型上均能匹配甚至超越 SparseGPT 的性能，包括 LLaMA、LLaMA-2 和 OPT。此外，Wanda 在内存消耗和延迟方面效率极高，可在数秒内剪枝 LLaMA-7B 模型。

创新点

  1. Wanda 重要性准则: |W| × ||X||_2: 提出了一种新的权重重要性度量，将权重大小与对应输入通道的激活值 L2 范数相乘。这个简单的乘积在效果上接近 Hessian 引导的 OBS 准则。

  2. 揭示了一阶准则与二阶方法的相关性: 通过实验证明 Wanda 分数与 SparseGPT 的剪枝决策高度相关（Spearman 相关系数 > 0.9），从实证角度解释了为什么简单方法可以匹敌复杂方法。

  3. 极简的实现与极高的效率: Wanda 只需要一次前向传播收集激活值统计信息，然后逐行应用阈值。剪枝 LLaMA-7B 仅需 ~5 秒，比 SparseGPT 快 ~40 倍。

  4. 统一了多种剪枝方法的视角: 论文论证了 Wanda 对幅度剪枝和 SparseGPT 的统一——幅度剪枝是 Wanda 在均匀激活假设下的特例，SparseGPT 隐式地近似了 Wanda 的准则。

  5. 结构化剪枝扩展（Sparse-Wanda）: 将 Wanda 扩展到 N:M 半结构化稀疏和 2:4 结构化剪枝场景。

一句话总结

Wanda 提出了一种极简的剪枝准则 |W| × ||X||_2，在效果上匹敌需要 Hessian 矩阵的 SparseGPT，但计算效率高数个数量级，证明了 LLM 剪枝不需要复杂的二阶方法。

研究问题

SparseGPT 证明了 LLM 可以被准确地一次性剪枝，但它的实现涉及 Hessian 矩阵计算和权重更新补偿，相对复杂。这引发了一个基本问题：剪枝 LLM 真的需要二阶信息吗？是否存在一种更简单的准则可以达到类似的效果？

Wanda 的研究假设是：如果同时考虑权重和激活值的统计信息，一种简单的一阶乘积准则就足以识别重要的权重。这个假设的出发点是观察到不同 token 对同一通道的激活值具有相似的模式（通道级一致性），因此可以用一个通道级的标量（L2 范数）来概括激活值的”重要性”。

1. Wanda 核心准则

其中 ||X_j||_2 = √(Σ_n X_jn^2) 是第 j 个输入通道在所有校准 token 上的 L2 范数。

然后对于 W 的每一行（即每个输出神经元），保留 S_ij 最大的 k 个权重，将其余的设为零。

与幅度剪枝的区别:

  • 幅度剪枝: S_ij = |W_ij|（仅看权重）
  • Wanda: S_ij = |W_ij| × ||X_j||_2（权重 × 激活）

这个简单的乘法带来了关键差别：一个数值很小的权重如果对应的输入通道激活值很大，其重要性会显著提升，反之亦然。

2. 为什么 ||X||_2 而非均方根或其他统计量？

Wanda 选择 L2 范数有几个原因：

  1. L2 范数自然地对异常值敏感（因为有平方项），这使得大激活值通道得到更强的权重
  2. L2 范数是欧几里得距离/范数的自然推广，与 MSE 误差最小化的目标一致
  3. 与 SparseGPT 的 Hessian 准则有数学联系：Hessian H = XX^T 的对角元就是 ||X_j||_2^2

3. 完整 Wanda 算法

算法复杂度：O(d_out × d_in × log(k)) per layer（主要是排序开销），实际上是 O(d_out × d_in)（可以用 top-k 选择算法）。

Wanda 可以自然地扩展到 N:M 结构化稀疏（如 2:4）：

  • 将权重按 M 个一组分组

为什么 Wanda 这么简单却这么有效？

这是论文最核心的问题。答案涉及几个层面：

1. 激活值的通道级一致性

LLM 的激活值表现出极强的通道级一致性：同一通道在不同 token 上的激活幅度具有很高的相关性。这意味着用一个标量（L2 范数）来概括整个通道的”重要程度”是合理的近似。这种通道级一致性在 SmoothQuant 和 AWQ 中也被观察到——它们都利用了异常值集中出现在特定通道上的特性。

2. 对角线 Hessian 近似

在 OBS 框架中，权重显著性 = |W| / [H^{-1}]{jj}。如果假设不同输入通道之间不相关（H 是对角矩阵），则 [H^{-1}]{jj} = 1/||X_j||^2，这样就得到 |W| × ||X_j||。虽然不同通道间实际上存在相关性（非对角元不为零），但在足够大的维度下，对角近似可能是对 Hessian 的一个合理近似。

3. 大规模模型的自然正则化

LLM 具有大量参数和高度冗余的结构，这使得”不完美”的剪枝决策也能被其他参数补偿。Wanda 不需要显式地补偿误差（不像 SparseGPT 的权重更新步骤），但模型的过度参数化提供了隐式的补偿能力。

Wanda 的设计哲学

Wanda 体现了一种重要的研究哲学：在尝试复杂解决方案之前，先尝试找出最简单的有效方法。SparseGPT 引入 Hessian 矩阵和权重更新来解决剪枝问题，但 Wanda 证明了一个简单的乘积准则就足以获得 90%+ 的收益。这种”够好的简单方案”在工程实践中有巨大的价值。

这与 AWQ 对 GPTQ 的关系类似——都用更简单的统计信息替换了复杂的二阶计算，且几乎不牺牲精度。

Wanda 的权重更新（或缺乏更新）

一个值得注意的细节是：Wanda 不更新保留的权重。这与 SparseGPT 形成对比，后者会更新保留权重以补偿剪枝误差。这意味着 Wanda 所有剪掉的权重信息都永久丢失了。然而实验结果却表明 Wanda 在大部分场景下匹敌 SparseGPT。

可能的解释：

  1. 对 50% 的稀疏度，剩余 50% 的参数已经足够补偿
  2. SparseGPT 的权重更新实际上可以通过调整来补偿”不太完美”的掩码选择，而 Wanda 的掩码选择本身已经足够好
  3. 在极高稀疏度（80%+）下，Wanda 会开始落后于 SparseGPT，说明权重更新在那时变得关键

局限

  1. 校准数据依赖: Wanda 需要代表性校准数据来计算激活值统计量。如果推理时输入分布与校准时显著不同，剪枝决策可能不再是次优的。

  2. 极高稀疏度下退化: 在 70-80% 的极高稀疏度下，Wanda 开始明显落后于 SparseGPT，说明 Hessian 补偿机制在极端情况下仍有不可替代的价值。

  3. 粗粒度的通道级近似: 使用单个标量 ||X_j||_2 来概括整个通道，可能丢失了 token 级别的偏差信息。对于激活值在不同 token 上变化很大的通道，这种近似不够精确。

  4. 缺乏权重更新: 不更新保留的权重意味着剪枝引入的偏置无法被补偿。对于需要极高精度的下游任务，这可能是一个限制。

  5. 非结构化稀疏的硬件挑战: 与 SparseGPT 一样，Wanda 的非结构化稀疏在通用 GPU 上难以获得实质性的推理加速。

可复用洞见

  1. 简单准则的威力: Wanda 是”简单方法打败复杂方法”的又一个例证。在投入大量精力实现复杂方案之前，总是值得先尝试简单的 baseline——有时简单方案已经足够好。

  2. 权重的价值由输入定义: 权重的重要性取决于它在做什么（与什么输入交互），而非它本身的大小。这个原则在 AWQ、SmoothQuant、Wanda 三个独立的工作中都被验证。

  3. 通道级聚合的有效性: 将 token 级别的激活值信息聚合成通道级统计量（L2 范数），在 LLM 上是一种有效且高效的做法。这不仅适用于剪枝，也可能适用于其他需要评估参数重要性的场景。

  4. 对角近似的普遍性: Wanda 通过对 Hessian 做对角近似（忽略通道间相关性），取得了与全 Hessian 方法接近的效果。这暗示在 LLM 的高维参数空间中，对角近似可能是一个普遍有效的工具。

  5. Jaccard 相似度作为分析工具: Wanda 使用 Jaccard 相似度来量化不同方法剪枝决策的一致性，这是一个简单而有效的分析工具，可以在其他方法对比中复用。

我的笔记

Wanda 是一篇”少即是多”（less is more）的典范论文。它没有提出新的理论框架，没有设计复杂的算法——只是观察到一个简单的事实：|W| × ||X||_2 在剪枝决策上与复杂的 Hessian 方法高度相关。但正是这种简单性使它具有持久的价值。

一个有趣的思考实验：如果 Wanda 在 SparseGPT 之前发表会怎样？可能 SparseGPT 的接受度会大不相同——因为一旦简单方法被证明有效，读者对复杂方法的额外收益期望会大大提高。这提醒我们，方法发表的顺序有时会影响我们对方法价值的判断。

Wanda 也提供了一种方法论启示：好的实证分析（相关性分析、消融实验）可以是研究贡献的核心，而不仅仅是辅助材料。论文中 Wanda 与 SparseGPT 的决策相似度分析就是一个典范。

从工程角度看，Wanda 的”秒级剪枝”能力使其在实际部署中非常有吸引力。它可以在模型加载时动态进行剪枝，根据目标设备的约束（内存、计算）实时调整稀疏度。这种灵活性是 SparseGPT 不具备的。

后续问题

  1. Wanda 准则 |W| × ||X||_2 是否可以直接用于训练过程中的动态剪枝（而非仅限于训练后剪枝）？
  2. 能否将 Wanda 的激活感知思想应用于量化？即用 |W| × ||X|| 来指导量化比特分配？
  3. 对于非 Transformer 架构（如 SSM、Mamba），Wanda 的准则是否仍然有效？
  4. 通道级聚合（L2 范数）是否是激活值统计的最优形式？是否存在理论上更优的聚合函数？
  5. Wanda + 微调（少量训练）的组合能否在极高稀疏度（80%+）下匹敌 SparseGPT + 微调？
  6. 能否利用 Wanda 的重要性分数来指导模型架构设计（如自动确定各层宽度）？
