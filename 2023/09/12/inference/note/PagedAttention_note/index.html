PagedAttention: Efficient Memory Management for LLM Serving

PagedAttention：LLM服务中KV缓存的高效内存管理

核心信息

  • 标题: Efficient Memory Management for Large Language Model Serving with PagedAttention
  • 标题翻译: PagedAttention：使用分页注意力实现大语言模型服务的高效内存管理
  • 作者: Woosuk Kwon, Zhuohan Li, Siyuan Zhuang, Ying Sheng, Lianmin Zheng, Cody Hao Yu, Joseph E. Gonzalez, Hao Zhang, Ion Stoica
  • 机构: UC Berkeley, Stanford University, UC San Diego
  • 发表时间: 2023年9月
  • 发表渠道: SOSP 2023 (ACM操作系统原理研讨会)
  • arXiv: 2309.06180
  • 论文链接: https://arxiv.org/abs/2309.06180

原文摘要翻译

大语言模型的高吞吐量服务需要同时批处理足够多的请求。然而现有系统难以应对此需求，因为每个请求的键值（KV）缓存占用大量内存且动态增减。当KV缓存管理不当、出现碎片化和冗余复制时，内存浪费严重——仅有20-40%的分配内存被实际使用。这一低效限制了批处理大小，成为服务吞吐量的主要瓶颈。为解决此问题，我们提出PagedAttention，一种受操作系统经典虚拟内存和分页技术启发的注意力算法。PagedAttention将KV缓存分割成固定大小的块，这些块无需在物理内存中连续存储。这消除了内部和外部内存碎片，实现了接近100%的内存利用率。此外，PagedAttention支持块级内存共享——当多个序列共享相同前缀时（如并行采样和beam search），物理块可被多个逻辑序列引用，无需复制。基于PagedAttention，我们构建了vLLM，一个高吞吐量的分布式LLM服务引擎，实现了KV缓存接近零浪费、灵活的块级共享、以及高效的内存调度。vLLM对流行的LLM实现了比最先进系统（如FasterTransformer和ORCA）高2-4倍的吞吐量提升，且无需对模型架构做任何改动。

创新点

1. KV缓存的分页抽象

核心思想: 将操作系统的虚拟内存分页技术应用于LLM推理的KV缓存管理。每个请求的KV缓存被分割成固定大小的”块”（如16个token/块），块在物理GPU内存中可不连续存储。逻辑上连续的KV序列通过”块表”映射到物理块地址。

为什么重要:

  • 消除内存浪费: 此前KV缓存内存中有60-80%因碎片和预分配而浪费。FasterTransformer和ORCA等系统需要预分配最大可能长度的连续内存空间。当实际生成短于最大长度时，大量预留内存被浪费（内部碎片）。不同请求的分配导致外部碎片。
  • 接近100%利用率: 分页抽象仅分配实际使用的内存。当新token生成时动态分配新块，当序列结束时立即回收。无需预留，无碎片。
  • 类比操作系统: 1960年代的分页虚拟内存解决了完全相同的碎片化问题。论文将60年前的OS智慧应用到LLM推理这一全新场景。

2. 块级内存共享（写时复制）

核心思想: 物理KV缓存块可在多个逻辑序列间共享。当多个序列共享相同前缀时（如并行采样生成多个候选、beam search中的共享路径、或系统提示前缀），所有序列引用相同的物理块。仅在某个序列需要修改时（实际生成不同时），才创建新块（写时复制语义）。

为什么重要:

  • 并行采样: 生成n个候选答案时，传统方案需复制整个KV缓存n次。PagedAttention只复制块表引用，物理块共享，内存节省55%。
  • Beam Search: beam=6时，传统方案需维护6份KV缓存。PagedAttention通过块表引用节省40%内存。
  • 共享前缀: 多请求共享系统提示（如”你是一个有帮助的AI助手”）时，每个请求的提示KV缓存指向相同物理块，节省28%内存。
  • COW语义: 使用引用计数实现，当块的引用计数降为0时自动回收到空闲池。

3. 动态内存调度和抢占

核心思想: 当GPU内存不足时，vLLM可以”抢占”（swap out）部分请求的KV缓存块到CPU内存，腾出空间给其他请求。当GPU内存可用时再”换回”（swap in）。这类似于OS的虚拟内存交换（swapping）。

为什么重要: LLM服务面临高度可变的请求到达率和序列长度。动态调度使vLLM可以优雅处理内存压力峰值，避免OOM（内存溢出）或拒绝请求。这是首次在LLM推理中实现类似OS交换的精细内存管理。

一句话总结

PagedAttention将操作系统60年的分页虚拟内存智慧应用于LLM推理，通过块级KV缓存管理将内存利用率从20-40%提升至接近100%，块级共享在并行采样中节省55%内存，动态调度支持内存抢占，使vLLM实现2-4倍的LLM服务吞吐量提升。

研究问题

核心挑战：LLM推理的内存管理危机

LLM推理服务（如ChatGPT、Claude）面临严重的内存管理问题。以典型LLaMA-13B模型为例：

KV缓存为什么这么大？ 自回归解码中，每个生成的token需要访问所有之前token的K和V。为避免重复计算，推理框架缓存已计算的K和V。对于长序列或大模型，每个请求的KV缓存可达数GB。

传统系统的内存浪费来源:

量化浪费: 实验测量显示，在生产工作负载上，传统系统仅有20-40%的KV缓存内存被实际使用。对于一个80GB的A100 GPU，这意味着48-64GB的”幽灵内存”——已分配但未使用的浪费空间。

为什么不能用简单的动态分配？

简单的malloc/free风格动态分配在GPU上不可行：

  1. GPU malloc开销高: GPU上的动态内存分配慢且不可预测
  2. 碎片化: 不同大小请求的分配/释放导致外部碎片，最终无法分配连续大块
  3. 无法共享: 动态分配不提供跨请求共享机制

现有方法的局限

  1. FasterTransformer (NVIDIA): 预分配最大序列长度。简单但极浪费。对于变长序列，高达80%的分配内存闲置。

  2. ORCA (UC Berkeley, OSDI 2022): 使用迭代级调度（iteration-level scheduling）提升批处理效率，但KV缓存管理仍是预分配。内存浪费是其主要扩展瓶颈。

  3. HuggingFace TGI: 使用动态批处理和简单的内存池，但无法处理碎片化和共享。

关键洞察：为什么分页？

这是虚拟内存问题！ LLM推理的KV缓存管理面临的问题——碎片化、预分配浪费、共享困难——与1960年代操作系统面临的物理内存管理问题完全相同。当时的解决方案是分页虚拟内存（paged virtual memory），它通过固定大小的页框、页表映射、写时复制共享，彻底解决了这些问题。PagedAttention将相同的智慧应用于KV缓存。

分页开销的量化分析

PagedAttention虽然引入了块表间接寻址的开销，但实验表明该开销可忽略：

开销来源 大小 相对占比 影响
块表内存 8 bytes/块（物理地址） <0.1% KV缓存 可忽略
块表查找 O(1) GPU寄存器操作 <0.01% 计算时间 可忽略
块内填充（最后一块） 平均block_size/2 tokens ~3% KV缓存 微小

关键结论: PagedAttention的内存节省（60-80%的碎片消除）远超其引入的间接寻址开销（<0.1%）。

为什么发表在SOSP而非ML会议？

PagedAttention/vLLM选择发表在SOSP（操作系统领域顶会）而非NeurIPS/ICML，这本身就是一个重要的声明：

  1. 核心问题是系统设计: 内存碎片化、分配策略、共享机制——这些都是经典OS问题
  2. 解决方案来自OS: 分页、写时复制、交换——都是OS教科书概念
  3. 评估方法不同: 关注吞吐量、延迟、内存利用率等系统指标，而非模型精度或困惑度
  4. 影响力更广: SOSP论文影响了整个LLM服务生态系统的设计

这一选择证明：随着LLM部署的规模化，系统设计变得与模型架构同等重要。

局限

1. 块大小敏感性

块大小是关键的调优参数。16 tokens/块在大多数场景下是最优的，但不同模型和序列长度可能需要不同块大小。目前需要手动调优，缺乏自动选择机制。

2. 块表内存开销

每个请求维护一个块表。对于超大batch（如1000+请求），块表本身的内存开销变得不可忽略。但对于典型LLM服务场景（数十到数百并发请求），开销可忽略。

3. 非注意力内存

PagedAttention仅优化KV缓存内存（通常占运行时内存的30-50%）。模型权重（固定）和其他激活内存（如中间层的hidden states）仍需要常规管理。对于小型模型或短序列，PagedAttention的相对收益较小。

4. GPU内存分配器碎片

虽然PagedAttention消除了逻辑碎片，但底层GPU内存分配器（cudaMalloc）可能有物理碎片。vLLM使用自己的GPU内存池来缓解此问题，但无法完全避免。

5. CPU-GPU交换延迟

当GPU内存不足需要swap时，CPU-GPU数据传输引入延迟（每次~ms级）。对于延迟敏感的应用，频繁的swap可能是不可接受的。论文通过优先swap不活跃请求来最小化影响。

可复用洞见

1. 跨领域类比的力量

PagedAttention展示了将一个领域的成熟技术（OS虚拟内存）应用到新问题（LLM KV缓存）的巨大价值。这启示我们：许多ML系统的瓶颈可能已被其他领域解决。

2. 内存管理是LLM推理的核心瓶颈

在LLM推理中，内存（而非计算）通常是瓶颈。KV缓存的动态性质使其管理尤为困难。高效的LLM推理系统必须以内存管理为核心设计。

3. 写时复制在ML推理中的威力

COW（写时复制）是系统编程中的经典模式。在LLM推理中，由于并行采样、beam search和共享前缀的普遍性，COW的收益远超预期。28-55%的内存节省证明了这一点。

4. 分块是通用抽象

分块（固定大小、不可变）是管理动态资源的通用模式。FlashAttention使用分块加速计算，PagedAttention使用分块管理内存——相同的抽象服务于不同目的。

5. 系统设计与ML算法的融合

vLLM展示了系统设计（分页、COW、swap）和ML算法（注意力计算）可以深度融合。这种融合（而非各层独立优化）是实现最优性能的关键。

我的笔记

为什么PagedAttention如此重要？

PagedAttention解决的是一个”痛苦但被忽视”的问题。在它之前，KV缓存的内存浪费是LLM服务中的”房间里的大象”——大家都知道它存在，但没有人系统性地解决。PagedAttention通过将60年前的OS智慧应用到新场景，优雅地解决了这一瓶颈。

其影响力体现在两个方面：(1) vLLM成为事实上的LLM服务标准，被全行业采用；(2) 分页抽象启发了后续工作（如SGLang的RadixAttention、LightLLM的token级内存管理）。

与FlashAttention的分工

FlashAttention解决”如何计算得更快”（计算效率），PagedAttention解决”如何管理得更好”（内存效率）。两者是LLM推理系统的左右手——任何一个的缺失都会严重限制整体性能。现代LLM推理框架（如vLLM、SGLang）同时使用两者。

未来演进

随着模型上下文窗口向百万级token扩展（Gemini 1.5、GPT-4 128K），KV缓存的内存压力将进一步增大。PagedAttention的分页抽象为此提供了基础——更大的上下文意味着更需要块级管理和共享。未来的演进方向包括：稀疏KV缓存（仅缓存重要token）、量化KV缓存（FP8/INT8存储）、分层存储（GPU-CPU-SSD三级缓存管理）。

后续问题

  1. 自适应块大小: 如何在运行时自动选择最优块大小？能否根据请求的统计特性动态调整？
  2. KV缓存的量化: 将FP8 KV缓存与分页管理结合，内存使用可再减半。块量化是否与块管理无缝集成？
  3. 分层存储: 对于百万级上下文，GPU内存不够。如何设计GPU-CPU-SSD的三层KV缓存系统，利用分页抽象进行透明管理？
  4. 训练场景: 训练期间的激活内存管理类似KV缓存管理。分页抽象能否推广到训练场景的激活检查点？
  5. 多节点: 在分布式服务中，多个GPU节点如何共享KV缓存块？块表是否可跨节点扩展？
