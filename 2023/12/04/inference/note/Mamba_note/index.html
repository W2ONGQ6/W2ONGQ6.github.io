核心信息

Mamba 引入了选择性状态空间模型（Selective SSM / S6）——将 SSM 参数从固定的线性时不变（LTI）变为输入依赖函数——配合硬件感知并行扫描算法，以线性时间推理和 5 倍生成吞吐量实现了 Transformer 级别的建模质量。Mamba 证明了非 Transformer 架构能在质量上真正具有竞争力，催生了整个替代架构研究生态（Mamba-2、Jamba、Griffin 等）。这是自 “Attention Is All You Need” 以来最具影响力的替代架构论文。

原文摘要翻译

我们提出了 Mamba，一种基于选择性状态空间模型的新型序列建模架构。与传统的线性时不变 SSM 不同，Mamba 的 SSM 参数是输入依赖的，使模型能够根据当前 token 选择性地传播或遗忘信息——这解决了 SSM 在内容感知推理上的根本缺陷。由于选择性使高效卷积计算模式不可用，我们设计了硬件感知的并行扫描算法，灵感来源于 FlashAttention 的 I/O 感知设计。Mamba-2.8B 在语言建模上超过同等规模 Transformer 并匹敌两倍规模 Transformer，生成吞吐量提升 5 倍。

创新点

  1. 选择性状态空间模型（Selective SSM / S6）：

    • 传统 SSM（S4、H3）的参数 (Delta, A, B, C) 是固定的 LTI 参数——所有 token 共享同一个参数化，无法根据内容选择性处理信息
    • Mamba 将 Delta, B, C 变为输入 x_t 的函数（A 保持固定但 Delta 的输入依赖性间接使 A 具有选择性）
    • 这使得模型能够根据 token 内容选择性地遗忘或保留信息——解决了 SSM 在 “选择性复制” 和 “归纳头” 等关键语言任务上的能力缺陷

  2. 硬件感知并行扫描算法：

    • 选择性破坏了 LTI 性质，使卷积模式不可用——必须使用递归形式
    • 递归形式的朴素实现是串行的（逐时间步），在 GPU 上极慢
    • Mamba 设计了 GPU 优化的并行扫描算法：分块（tile）扫描，利用 SRAM 减少 HBM 读写
    • 将 SSM 状态从 HBM 加载到 SRAM 后，在 SRAM 中完成整个扫描块的局部计算，再写回

  3. 极简架构设计：

    • 完全移除 attention 层甚至 MLP 块
    • 核心组件：Selective SSM 层 + 门控 + 残差连接 + LayerNorm
    • 架构深度可比 Transformer，但每层结构更简单
    • 无 KV cache —— SSM 状态大小恒定，不随序列长度增长

  4. 线性时间 + 高效推理：

    • 每 token 计算时间恒定（不需要对所有之前 token 做 attention）
    • 推理状态仅为一个固定大小的 hidden state 向量，无增长的 KV cache
    • 生成吞吐量比等规模 Transformer 快 5 倍

一句话总结

Mamba 以选择性状态空间机制赋予 SSM 内容感知能力，以硬件感知并行扫描解决训练效率问题，证明了线性时间架构可以匹敌 Transformer——这是替代架构的 “GPT 时刻”。

研究问题

  • 表达能力问题：传统的线性时不变 SSM（如 S4）在处理需要内容感知的任务（如选择性复制、上下文检索）时严重落后于 Transformer。能否通过引入选择性（输入依赖）来弥补这个能力缺口？
  • 效率问题：选择性破坏了 SSM 的卷积计算模式，使训练无法高效并行。如何在 GPU 上实现高效的选择性 SSM 训练？
  • 架构简化问题：能否完全移除 attention 和 MLP，用一个纯净的 SSM 架构达到 Transformer 级别的性能？
  • 长序列问题：线性时间架构能否在长序列任务上展现出超出 Transformer 的优势？

数据与任务定义

  • 语言建模：The Pile（300B token）、C4、WikiText-103
  • 评估任务：语言建模 PPL、Zero-shot 下游任务（LAMBADA、HellaSwag、PIQA、ARC、WinoGrande）
  • 合成任务：Selective Copying、Induction Heads（用于测试内容感知能力）
  • 长序列评估：长度泛化测试（2K 训练 → 更长序列评估）
  • 对比基线：Pythia（Transformer）、H3（SSM）、Hyena、RWKV

步骤 2: 从 LTI 到 Selective（LTV）——引入输入依赖性

传统 SSM（S4）——LTI（线性时不变）：

  • A, B, C, Delta 对所有 token 都是相同的、固定的
  • 优点：可以使用卷积形式并行训练（利用FFT加速）
  • 缺点：没有内容感知——模型对所有 token 做同样的状态更新，无法选择性记忆或遗忘

Mamba（S6）——Selective（选择性/LTV，线性时变）：

  • B(x_t) = Linear_B(x_t)：B 变成输入 x_t 的线性投影函数
  • C(x_t) = Linear_C(x_t)：C 变成输入 x_t 的线性投影函数
  • Delta(x_t) = softplus(Linear_Delta(x_t))：Delta 变成输入的函数（经 softplus 确保为正）
  • A 保持固定，但通过 Delta 的输入依赖性间接具有选择性（A_bar = exp(Delta * A)）

选择性的效果：

  • 模型可以学会”只关注重要的 token，忽略不重要的”
  • Delta 的输入依赖性类似 LSTM 的遗忘门——大Delta=快速更新（新信息重要），小Delta=保持记忆（旧信息重要）
  • B 和 C 的输入依赖性类似 attention 的 query/key——决定”从状态中读取什么”和”向状态中写入什么”
  • 打破了LTI的卷积等价性，使得训练必须使用递归形式

步骤 3: 硬件感知并行扫描——解决选择性带来的训练效率问题

选择性破坏了LTI性质，使卷积/FFT模式不可用——必须使用递归形式。但递归形式的朴素实现是串行的（逐时间步），在GPU上极慢。

递归形式的串行依赖：

并行扫描解决方案（Parallel Scan / Parallel Prefix Sum）：

  • 将序列划分为块（tiles），每块约256-1024个token
  • 每个块内使用work-efficient parallel scan在SRAM中并行计算所有h_t
  • 跨块传递全局扫描状态（仅块边界的状态在HBM中读写，开销极小）
  • 利用GPU的并行性同时处理多个token

I/O感知的内存优化：

  • 将SSM状态保持在SRAM中直到tile扫描完成
  • 消除中间结果的HBM读写——类似FlashAttention的核心理念
  • 计算公式：state_size × d_model = O(常数) — 每个token只需读写固定大小的状态

步骤 4: 推理时的结构效率优势

  • 推理只需维护一个恒定大小的状态向量 h（维度 = d_state × d_model，如16×2560 = 40K元素）
  • 每个新 token 的计算量：O(1) 状态更新（矩阵-向量乘） + O(1) 输出投影（vs. Transformer 的 O(n) attention）
  • 无 KV cache 意味着任意长序列生成的内存成本是固定的
  • 在batch=1场景下推理吞吐量是同等规模 Transformer 的约5倍

深度分析

1. 选择性 = SSM 的 Attention

Mamba 的核心洞察可以这样理解：选择性之于 SSM，如同 self-attention 之于 Transformer。在普通 RNN 中，所有 token 共享相同的转移矩阵。Attention 的创新在于，每个 token 的”注意力分布”是根据其与所有其他 token 的关系动态计算的。Mamba 的选择性本质上是对 SSM 状态更新做了类似的事情——每个 token 的动态特性（Delta、B、C）是根据其内容决定的。

更具体地说：

  • Transformer 的 attention：q_i^T k_j 决定了 token i 对 token j 的”关注程度”
  • Mamba 的 Delta(x_t)：决定了 token t 的”记忆窗口”（遗忘速率）
  • Mamba 的 B(x_t)：决定了 token t 的”写入强度”
  • Mamba 的 C(x_t)：决定了 token t 的”读取模式”

三者组合，Mamba 实现了类似 attention 的”选择性关注”，但以 O(1) 而非 O(n) 的复杂度。

2. 硬件感知设计与模型设计的统一

Mamba 的另一个重要贡献是证明了硬件感知不应该是一个”后优化”步骤，而应该与模型设计同步进行。论文中详细描述了在 GPU SRAM/HBM 层级下选择性 SSM 的效率分析，并将”在 SRAM 上能否高效执行”作为算法设计的约束条件之一。

这与典型的 ML 研究流程（先设计算法，再优化实现）形成对比。Mamba 的设计哲学是：如果一个算法在目标硬件上不能高效运行，那它就不是一个好的算法——即使它在理论上很优美。

这种哲学的直接后果是：Mamba 的并行扫描算法不是最优的数学算法（在理论上可以使用更复杂的分治策略），但它是在 GPU 上最高效的算法。这种”在给定硬件约束下的最优”vs”理论上的最优”的思维方式，是工业级 ML 系统设计的核心素养。

3. Mamba 与 RWKV 的对比

两者都是线性时间架构，但核心机制不同：

Mamba RWKV
核心机制 选择性 SSM WKV (Receptance Weighted Key Value)
状态大小 固定（每层） 固定（每层）
训练方式 并行扫描（自定义 kernel） 并行计算（类似 Transformer）
选择性 内生的（参数是输入依赖） 后加的（RWKV-6 引入动态衰减）
GPU 优化 硬件感知扫描 标准矩阵运算
生态 学术界为主 开源社区驱动

Mamba 的学术性更强（来自 CMU/Together AI），RWKV 的社区性更强（来自 EleutherAI）。Mamba 的理论基础更深厚（SSM 数学框架），RWKV 的工程实现更友好（标准矩阵运算，不需要自定义 kernel）。

4. 对长上下文场景的深远意义

Mamba 的恒定大小状态在长上下文场景中有根本性优势：

  • 这个特性对于流式处理（streaming）、实时对话、无限长度文档分析等场景至关重要

Mamba 处于替代架构历史上最关键的转折点：它是第一个在质量上真正超越同等规模 Transformer 的非 Transformer 架构，同时保持了线性时间和无 KV cache 的效率优势。

局限

  1. 训练吞吐量劣势：Mamba 的自定义并行扫描 kernel 在训练时不如标准 Transformer（使用 FlashAttention 的成熟实现）快——Mamba 的效率优势主要体现在推理阶段。
  2. 选择性机制的”黑盒”：Delta、B、C 的选择性函数如何工作缺少直观解释。什么输入导致大 Delta（快速更新）vs 小 Delta（保持记忆）？缺乏可视化或分析。
  3. 对大规模验证的缺乏：Mamba-2.8B 是主要实验规模，与当时存在的 70B+ 模型有数量级差距。选择性在大规模下是否保持优势缺乏证据。
  4. 硬件耦合性强：并行扫描 algorithm 针对 NVIDIA GPU 优化，在 TPU、专用芯片、边缘设备上的移植可能困难。
  5. attention 仍有关键价值：后续工作（Griffin、Jamba）证明纯 SSM 在需要精确局部匹配的任务（如代码复制、精确文本检索）上不如 attention。

可复用洞见

  1. 选择性/输入依赖 = 模型能力的关键杠杆：从 LTI 到 LTV 的转变是 Mamba 成功的核心。任何”固定模式”的模型（不限于 SSM）都可能通过增加输入依赖性获得能力跃升。
  2. 算法和硬件应该协同设计：不要先设计最优的数学算法再做硬件优化。从设计阶段就考虑硬件的内存层级、并行能力、通信带宽。
  3. 合成任务是能力缺口的最小测试集：Selective Copying 和 Induction Heads 这些简单的合成任务完美地暴露了 LTI SSM 的能力缺陷。在评估新架构时，设计能够针对性暴露弱点的合成任务至关重要。
  4. 推理效率和训练效率可能需要不同平衡：Mamba 的训练不如 Transformer 快，但推理快得多。对于推理密集型部署，牺牲一点训练效率换取推理效率是有利可图的。
  5. 无 KV cache = 长上下文部署的游戏规则改变者：对于需要长时间运行、处理无限长度对话或流式输入的应用，无 KV cache 架构有天然的结构性优势。

我的笔记

Mamba 是一篇让我重新思考”架构创新”定义的论文。在它出现之前，我已经接受了”Transformer + 各种优化就是 LLM 的标准配置”这一叙事。Mamba 挑战了这个假设——不是通过”让 Transformer 更高效”，而是通过提出一个完全不同家族的方法。

但这也是 Mamba 面临的困境：Transformer 的生态系统太强大了。即使 Mamba 在理论上更高效，所有的优化工具（FlashAttention、vLLM、TensorRT-LLM）、训练框架（Megatron、DeepSpeed）、和硬件加速（Transformer Engine）都是围绕 Transformer 设计的。切换架构意味着放弃这些投入了数年优化的基础设施。

这解释了为什么后续的混合架构（Jamba、Griffin）比纯 Mamba 更受工业界欢迎：它们可以在保留 Transformer 生态兼容性的同时获得 SSM 的效率。纯 Mamba 可能是”理论上最优”的，但混合架构是”工程上可行”的。

Tri Dao（FlashAttention 和 Mamba 的共同作者）的角色值得特别关注：他同时拥有”让 Transformer 更快”（FlashAttention）和”替代 Transformer”（Mamba）的双重视角。这种双重身份使他在架构选择上可能拥有最全面的技术判断——他在 Mamba-2 中给出的建议是：混合架构可能是最优解。

最后，Mamba 的硬件感知设计哲学对我个人的工程实践产生了深远影响。现在每当设计一个算法时，我会首先问：”这个算法在目标 GPU 的内存层级中该如何运行？SRAM 能装下吗？HBM 的读写频率是多少？”这已成为我的设计思维的一部分。

后续问题

  1. Mamba 的 hidden state 维度与模型总参数的最优比例是多少？是否能推导出类似 Transformer 中 “d_model 和 d_ff 的比例”的经验规则？
  2. 选择性的”强度”随模型规模如何变化？更大的 Mamba 是否变得更”选择性”？（Delta 的方差随层数/规模增加？）
  3. 能否用 Mamba 作为 Transformer 的 KV cache 替代品——用 Mamba 的状态总结历史上下文，query 仍然使用 attention？
  4. Mamba 在 encoder-only 场景下（如文本嵌入、分类）的表现如何？选择性 SSM 在双向上下文中如何工作？
  5. Mamba 的 hidden state 能否被解释（如可视化哪些 token 被保留在状态中）？这对理解模型行为和安全审计至关重要。
